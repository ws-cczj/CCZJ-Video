# 类型化请求流程与有界数据处理

2026-10-20 补充：所有前端绑定现有显式的请求策略和通道标识，读取合并、写入代次隔离与视图订阅取消由 API 层统一拥有。视频远端搜索、豆瓣搜索/详情、更新检查、源探测及 DLNA 发现传递请求取消；新增采集状态批次接口，保留旧入口。当前约定见 [请求通道与取消](../request-pipelines.md)，验证见 `reports/request-pipelines-2026-10-20.md`。下文描述的是 2026-10-19 的接入范围。

2026-10-19。沿用 Go/Wails/Vue 类型化绑定与现有成功返回格式，在实际交互处复用公共流程。

## 请求与资源归属

`app/service/requests.go` 的 runRequest 将已有 operation.Run 与模式生命周期组合。进入时在短暂模式锁内取得模式名和请求所有者，执行期间不持有模式切换锁；完成时释放所有权。公共流程负责取消前检查、panic 恢复、错误关联、日志和有限聚合统计，不重写领域错误、业务事务或重试。

接入范围包括已有 context 的阅读、阅读状态、视频详情/线路测速、弹幕，以及新增 context 的评论与两个源导入入口。模式切换、退出、日志等宿主控制继续采用各自生命周期，避免切换操作等待自身完成。已提交写入不会因统一的“返回前取消检查”被改报为未提交。

前端 response 组合 applicationRequest 与业务解码器，保留 CancellablePromise 和真实绑定取消。读取、解码失败与取消各记一次；视图继续以 generation 防止迟到结果写入。阅读 DTO、视频详情（网络和缓存）、评论及弹幕已使用公共流程。保留原有 IPC 名称、数据字段与返回结构；Wails 注入的 context 不增加 JS 调用参数。

## 有界载荷

`app/payload` 管理 Base64 预分配预算、读取预算、Brotli/gzip 识别、解压后容量和单个完整 JSON 文档校验。JSON 未知字段是否拒绝由调用方决定。源导入保留 64 MiB 输入/输出预算；详情缓存解压上限 16 MiB；备份保留原有 64 MiB 预算。

`UnpackBytes` 复用调用方已有输入，未压缩数据不额外复制。输入与输出都受到限制，业务解码、合并和事务由调用方负责。文件读取的 context 检查是合作式的，不承诺中断任意不支持取消的底层阻塞 Reader。

## 设置与事件

createSettingsQueue 串行保存，合并尚未确认的同键修改，只有对应版本成功后才移除待保存内容。失败保留最新值供明确重试，不增加无限自动重试。主题保存已接入错误展示与重试，编辑器保存失败保持打开；后端 SetSetting 用专用锁保证持久化与运行时生效顺序一致。模式切换在此锁外保持原有独立流程。

api/events 对已知事件校验已声明字段，保留额外业务字段。进度按任务/来源身份在一帧内合并；终态即时交付，collect:done/error 到达时先刷新待交付进度，解除订阅时取消排程。调用方可以提供额外身份过滤和扩展事件解码器。未知扩展事件不被伪称已通过完整业务校验。

## 诊断与兼容

后端 operations 只聚合已接入的固定操作名，按当前模式/共享宿主过滤，保留成功、失败、取消、累计和最长毫秒数。它不是全项目所有函数的覆盖率。

前端 transport、业务资源与事件计数分别观察。activity 的固定操作集合取代任意名字占满 16 个槽后静默丢弃的模式。事件诊断记录收到、格式错误、合并及身份过滤计数，不存载荷内容。高频成功调用不逐条写日志。

保留阅读的来源自然键、缺失书架条目的 null 槽、旧详情集表兼容和合法空集合。生成绑定及类型声明不替代运行时检查。具体 source/provider 规则、缓存、事务、分页续传和请求频率仍由原有模块拥有。
