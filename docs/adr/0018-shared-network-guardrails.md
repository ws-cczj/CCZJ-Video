# 共享出站约束与原有请求节奏

2026-10-23 更新：按用户当前要求，所有查询出口已统一采用档位随机冷却；下文保留 2026-10-19 的历史决策。当前实现、连续传输豁免及缓存边界见 [请求通道与取消](../request-pipelines.md)。

2026-10-19。采用前提：已有模块的请求频率正常；引入弹幕后统一约束异常请求，不整体放慢原有业务。

## 职责

`app/netpolicy` 在各 Go HTTP 客户端的流量计数器外层执行请求准入。每个客户端原有 Cookie、SSRF 校验、重定向、超时、并发预算和业务重试仍由原模块负责。统一层不增加自动重试任务、不轮询、不替换来源。

App 在 SQLite 打开后安装唯一 Manager，退出时先取消并关闭持有的响应体、等待完成，再关库。已有包级客户端在请求时查询已安装实例；关闭中的实例继续拒绝迟到请求，避免退出时绕过约束。

## 原有业务

搜索、详情、目录、评论、采集和更新检查只合并同时在途且身份相同的安全读取。完成后删除复用项，下次正常查询照常出站。响应未完整读取、超过 1 MiB 或声明 no-store 时不复用，等待者正常获取自己的响应。

普通失败继续使用原有重试。HTTP 429、带 Retry-After 的 503 或统一层明确拒绝时，返回剩余等待时间，采集页工作器不继续按 5/10 秒循环冲击。源站等待按主机协调并落库；除源站明确限流或全局安全上限外，不对连续传输设置查询冷却。

播放、图片（含漫画图片）、下载、测速和设备控制不捕获响应用于共享，也不套用长冷却。安装包下载显式标记连续传输，避免依赖 URL 是否以 exe/apk 等结尾判断。

## 档位

统一设置 `network_request_policy_v1` 保存于 SQLite，视频高级设置、小说设置和漫画设置展示同一个面板。通过正常设置接口保存后立即生效；备份恢复后按现有流程重启重新装配。

| 档位 | 新增弹幕相同请求的随机间隔 | 单主机查询突发容量 / 持续上限 |
| --- | --- | --- |
| 标准（默认） | 5–6 分钟 | 30 / 每秒 10 个 |
| 稳健 | 10–12 分钟 | 20 / 每秒 6 个 |
| 低频 | 30–35 分钟 | 10 / 每秒 3 个 |

应用聚合突发预算为单主机的四倍。这些上限用于异常突发保护，不是改写原有查询间隔的调度器；已有更低的模块预算照常生效。新弹幕仅首次实际准入计算一次随机截止时间，手动重试或切换档位不重置已有截止时间。失败、已准入后取消也占用间隔；进入中间件前已取消则不发请求。各页面、视频、分段仍按各自身份读取，不能用一个全平台锁阻断整段播放。

## 身份与边界

请求身份包含业务分类、方法、规范化 URL、来源身份、声明的全部请求头和可重放请求体。仅忽略 B站搜索和爱奇艺已知接口的动态签名字段，不删除任意接口的 timestamp/sign。Cookie、鉴权和自定义表示请求头参与身份，SQLite 只保存 SHA256 和截止时间。

冷却记录通过 v16 有序迁移增加，不改动 v15 弹幕表；重启不重置已保留的弹幕及源站冷却。弹幕分段与索引仍优先使用原有至少一天的新鲜缓存和 30 天淘汰策略；短期 HTTP 响应复用不是另一份持久内容库。

内存上限：4096 个查询身份、512 个主机/突发槽、128 个在途响应、128 个等待复用者；单条可捕获响应 1 MiB，正在捕获和已保留的响应各最多 8 MiB，保留响应最多 128 条。淘汰响应字节不删除冷却截止时间，连续流不占响应复用缓存。

诊断只展示当前模式和共享更新服务的准入次数、复用次数、拦截次数；实际流量仍由内层 netstats 记录。复用和拦截不重复计算网络字节。任意可信脚本自行发起的浏览器 fetch、WebView 原生媒体请求和系统网络不因此自动经过 Go 中间件，不能据此宣称覆盖所有网络。
