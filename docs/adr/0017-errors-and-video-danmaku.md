# 错误出口与视频弹幕

2026-10-19。当前开发规范见根目录 AGENTS.md；本文记录此次实现与边界。

## 错误出口

保留 Wails 的现有成功返回方式。失败使用语义字符串 `code` 与用户消息 `message`，可以附带 `operation`、`requestId`、`retryAfterSeconds`、`logged`。HTTP 状态、日志等级和默认展示消息由错误目录分别提供；不要求领域内部统一成一种错误类型。

`app/operation.Run` 拥有请求恢复、耗时观察和关联编号；`operation.Log` 写私有原因后标记已记录。取消不作为故障日志。新弹幕出口使用这套中间件，其他绑定由 `apperror.Marshal` 提供兼容编码与日志兜底，逐步迁移耗时和恢复机制。

SP-TJob 的参考价值是错误目录、传输出口、日志中间件和界面策略各自有明确职责。CCZJ 使用 Wails，无需套用 Gin 的统一数字成功/失败响应。

Wails beta.30 的服务注册没有使用全局编码器作为实际回退，因此服务显式配置 `ServiceOptions.MarshalError`。Android JNI 又把 CallError 压成字符串：原生构建生成 SDK 的本地副本并只修补此分支，前端 `api/androidTransport.ts` 保留结构化 cause。共享模块缓存、根 go.mod 和桌面运行时不被修改。Go 1.26 禁止覆盖 GOMODCACHE 下的源码，所以 Android 使用生成的 modfile 与本地副本；上游分支变化时脚本中止构建，要求重新审阅。

前端 API 层一次解码为 `ApiFailure`，数字 `code/msg` 与旧文本前缀仅用于兼容。错误 store 合并短时间重复提示，取消保持安静，后端已记录的错误不再次写前端日志。诊断关联号保留在提示详情中。旧绑定的原始 Wails diagnostic message 仍可能包含内部原因；界面消费公开 cause，不能直接展示原始 Error.message。

## 视频弹幕

`app/danmaku` 负责平台协议、单集绑定、窗口读取和 SQLite 缓存；不控制视频播放。B站绑定 cid/aid，腾讯绑定 vid，爱奇艺绑定 TVid，平台标识与远端 ID 均为字符串。播放器通过 `DanmakuMatch` 自动匹配，不提供手动选源、搜索或选集入口。按用户反馈采用 `episode-priority-v1`：名称归一后移除有限的版本后缀，字符编辑相似度至少 80% 才成为候选；三个字及以下的短名称仍要求相同，双方明确声明不同季时不混用。作品按名称相似度排序，已知年份和类型相同加分，冲突不再直接否决。年份和类型来自已有交接协议：腾讯 `videoInfo.year/typeName`、爱奇艺 `year.value/channel`、B站 `fix_pubtime_str/pubtime/season_type_name`。

单集以明确声明的集号对应为通过条件；重制版允许采用，时长仅用于同集号候选排序。相同排序分数按远端身份稳定选择，避免目录换序导致选择变化。不使用数组下标推断集号。预告、花絮、解说和剪辑等仍过滤；B站显式内容角标保留到目录标题中参与过滤，会员角标不作为内容类型。B站目录缓存单独升级到 discovery-v3，避免复用遗漏预告角标的旧目录。匹配策略版本加入失败指纹：旧规则产生的作品/单集拒绝可以重新评估，旧网络异常、限流和空弹幕池冷却维持原期限；共享出站频率策略不变。成功日志及匹配记录保留相似度、集号和双方时长。该策略提高自动匹配覆盖，并不证明重制版与本地视频时间轴完全一致；匹配只保存可替换的弹幕绑定和缓存，不改变影视资料、收藏和播放进度。

本地绑定身份由视频来源、视频 ID 和集标识组成。偏移量只在本地时间轴上应用，不改写缓存中的源时间。三平台都只读取当前时间前 10 秒至后 75 秒的所需分段；合并窗口最多 12000 条。高级脚本弹幕不执行。

分段、索引、作品搜索和剧集目录保存于 SQLite。v15 建立原有弹幕表，搜索/目录缓存复用现有表；v17 增加独立的逐视频来源失败冷却表，不改写 v15 迁移。默认新鲜期一天，可选择 1–30 天；超过 30 天不回退使用，并在活跃读取/写入时清理。缓存逻辑载荷上限 128 MiB，容量淘汰保留最近 24 小时的新条目。若新条目无法在预算内保存，明确报告缓存失败，仍允许当前窗口播放。

网络复用共享 SSRF 拨号规则、独立弹幕并发通道和网络计数。请求归视频模式所有，切换模式时取消；没有后台轮询或预加载整集。重复读取合并在途工作，错误按来源语义分类。

前端懒加载弹幕功能，Canvas 由当前视频时间驱动；暂停、缓冲、隐藏与销毁时停止持续绘制。滚动和上下固定弹幕使用受限轨道，不创建每条弹幕的 DOM。更新预读窗口保留仍在屏幕上的弹幕；跳转时丢弃旧轨道。移动竖屏使用底部面板，桌面使用控制栏上方的紧凑设置面板；提供滚动、固定、彩色筛选以及显示参数，不展示来源选择流程。

桌面弹幕面板以弹幕按钮为锚点，在播放器范围内保留至少 16px 左右边距；展开及宿主尺寸变化时更新位置，观察器随关闭/销毁释放。控制栏三组按正常内容尺寸分配空间，中间组与左右组保留间距，窄屏优先避免重叠。面板只调整显示，不重复提供弹幕总开关；显示开关始终由控制栏拥有。匹配记录默认折叠且内容区独立滚动。缓存有效期配置位于弹幕源管理，合并最新显示偏好后只修改 freshDays，保留既有存储格式。

失败冷却不创建定时任务，也不在 24 小时到期时自动请求。重新进入播放页、重新开启或手动重试才重新判断；已绑定的正常播放仍按当前时间按需读取分段。作品搜索和整部目录跨集复用，正文按提供方、远端单集身份与分段隔离；同一远端弹幕池允许跨本地播放源复用缓存，不把第一集的正文套到其他集，也不一次预取整部剧。行为验证见 `reports/danmaku-panel-cache-2026-10-19.md`。

视频元数据事件启动配件初始化，随后挂载弹幕模块。首段读取完成、无匹配、停用或失败都可结束准备；配件等待最多 1.5 秒，弹幕等待最多 2.5 秒，超时继续播放并允许原请求在其自身超时内完成。仅当准备结束且 canplay 时触发自动播放。换源、换集、退出通过媒体会话取消等待及计时器。左下角提示与诊断事件由上述真实阶段驱动。

诊断只在视频模式返回弹幕缓存命中、缓存未命中读取、过期回退、缓存异常，以及自动匹配、来源回退、失败冷却命中计数；缓存未命中读取可能由共享请求层复用响应，不等于真实 HTTP 次数。搜索及目录请求也记入视频弹幕网络分类。播放器设置只读展示本次各来源结果及冷却期限。

匹配属于可正常返回“不可用”的查询，不能依赖错误中间件只在抛错时写日志。现在每次匹配生成 match_id，普通 INFO 日志记录请求元数据、有限候选、选定作品/单集、逐源阶段/失败码/耗时、冷却期限及最终结果，不要求先开启录制。用户界面展示细分原因和关联号，原始网络原因保留在私有日志。旧综合失败码可用现有缓存重新解释，不发请求、不解除或延长冷却。

控制栏只保留一个弹幕按钮：点击开关，鼠标悬停 150ms 展开设置；按钮与面板之间留 220ms 离开延迟，移入面板取消关闭，悬停打开不抢焦点。触屏长按 450ms 或键盘上下方向键打开，长按后不再执行同次点击开关。关闭、媒体切换、销毁清理计时器。显示参数可在弹幕关闭时调整，不因此发起匹配。侧栏显隐按钮在鼠标接近视频右侧中部时出现，最后一次靠近/操作 5 秒后隐藏；键盘聚焦可见。侧栏以 360ms 宽度与内容位移过渡，收起后 inert，保留同一个视频元素；窄屏沿用原来不显示侧栏的行为，尊重减少动画设置。验证见 `reports/player-hover-interactions-2026-10-19.md`。

准备阶段保持加载状态，暂停提示仅在准备完成、无自动起播请求等待时显示；canplay 只表示媒体可用，不再提前结算首播帧指标。路由、详情、恢复进度、媒体附着、配件、弹幕与起播阶段另写 player.startup 普通日志。复现和边界见 `reports/player-startup-feedback-2026-10-19.md`。

## 内置弹幕源管理

视频管理区新增与采集源并列的 `/danmaku-sources`；移动端入口在设置工具中。当前只管理写死的 B站、腾讯和爱奇艺，不引入外部接口导入或多库合并。

`danmaku_sources_v1` 使用现有 SQLite settings 保存启停和默认选择。每次进入当前单集，最多并行探测三个已启用来源，整个服务最多运行三条来源匹配管线。按默认源、其余内置源顺序决策，不能让更快完成的回退源抢占默认源；确定赢家后取消并等待不再需要的探测。仅持久化赢家绑定，旧绑定不能抢先覆盖当前默认源优先级；同一远端单集保留既有偏移量。Go 在搜索、选集、绑定校验及窗口读取之前校验来源启停，停用不删除绑定或缓存。没有来源启用时停止请求。

每个来源内部按作品搜索、目录、单集校验和当前窗口读取顺序执行。未匹配、空弹幕池、缺段及上游错误按本地视频单集身份与提供方写入 SQLite，冷却 24 小时并跨重启生效；元数据指纹变化后重新评估。取消、停用和本地存储错误不伪装成来源失败。有效索引中的空时间窗不代表整集没有弹幕。全部不可用时不绑定、不绘制。后续窗口读取失败或缺段会重新评估来源，仍只展示一家。

播放读取只针对一个已验证绑定，首次直接使用匹配返回的窗口；覆盖窗口内不重复发起前端读取，作品、目录、索引和分段复用缓存及在途工作。单来源探测超时 12 秒，资源归属匹配会话。原有绑定方法保留兼容。取消是合作式的，不能把发出取消指令描述成网络已在同一瞬间完全停止。原有共享请求中间件的随机频率限制继续生效；一天失败冷却是独立的结果策略，不改变其他业务节奏。

播放器分别展示未检查、加载、未找到候选、停用、读取失败、当前时间段为空、缺段和实际读取条数。计数仅覆盖当前窗口，不代表整集总量；搜索到作品不等于已验证该集存在弹幕。至少读取到普通条目才能确认该集有可用内容，不额外扫描全片来证明没有。

## 当前边界

- 支持公开读取的普通弹幕；源站鉴权、限流与接口变化显式反馈，不影响视频播放。
- 爱奇艺已适配交接样本中的内联剧集目录；其他目录分支明确提示不支持，不提供手动地址/ID入口。
- 绑定与偏好可在本机重启恢复；现有跨库内容备份尚未包含新弹幕绑定表，分段缓存也不作为长期备份内容。
- 当前并行匹配的交接依据、验证结果与环境限制见 `reports/danmaku-parallel-match-2026-10-19.md`；较早验证见 `reports/danmaku-errors-2026-10-19.md`。
