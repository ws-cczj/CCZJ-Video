# 请求通道与取消

`frontend/src/api/app.ts` 是绑定的唯一入口，由 `scripts/gen-request-adapter.mjs` 生成。`requestPolicies.json` 为每个绑定声明策略；新增或移除绑定后，生成器和 `scripts/verify.ps1` 会检查策略与导出是否一致。其他 API 文件也不能直接绕过此入口导入生成绑定。

每次调用拥有独立的 `request.requestId`、固定的 `request.pipeline`（`rpc.绑定方法名`）与实际工作的 `request.flightId`。合并读取的订阅者共享 flightId，各自保留 requestId。身份不包含源地址、正文、文件路径或完整参数。

| 策略 | 行为 | 例子 |
| --- | --- | --- |
| read | 仅合并同时在途、参数相同的读取；完成后立即移除 | 设置、章节、目录、采集状态 |
| refresh | 合并同一轮显式刷新，并隔开刷新前后的读取 | 探测、刷新目录、线路测速 |
| write | 每次独立提交，派发和确认均隔开读取代次 | 设置保存、导入、进度、窗口尺寸 |
| isolated | 每次独立执行，保留流式事件或宿主控制的归属 | 带身份的搜索、日志订阅、退出、压缩 |

参数键依据 IPC 的 JSON 语义规范化对象键顺序，保留数组顺序和值类型。大型导入、压缩正文不参与参数键计算。写入没有自动重试、合并或回滚。隔开读取代次意味着后续读取不会加入写入前的旧请求；视图仍须用代次或请求身份拦截旧结果。

同一个读取可以有多个订阅者。取消一个订阅者仅释放它；最后一个订阅者离开时才取消底层绑定。已取消的工作从可加入表移除，直到底层 Promise 结束才释放读取名额，最多允许 128 个不同的在途读取。超出时返回 `UNAVAILABLE`，现有请求仍可加入。该上限约束前端 Promise；原生取消后的 I/O 收尾与实际并发限制由后端生命周期、工作池和网络预算负责。共享 DTO 在多个订阅者之间复制，并保留生成模型原型，避免一处编辑污染另一处。

视图通过 `createRequestScope` 管理订阅；隐藏或销毁时取消，同时保留代次校验。视频列表、源探测和源站搜索已接入。源站搜索使用新增的 `SearchSourceRequest` 携带进度身份，旧 `SearchSource` 仍可调用。进度必须匹配当前 requestId，重复相同关键词也不能接受上一轮事件。

视频源保存后的强制刷新同时推进 store 的读取代次，早于保存开始的响应不得覆盖新列表。列表与附加统计分别处理；统计不阻塞源列表或保存确认，空库返回的 `null` 作为空列表处理。`CreateSource` 在同一次写入中保存初始策略并返回分配的源身份；旧 `AddSource` 保留兼容。表单持有已提交身份，后续读取失败后重试仍操作同一个源，不再次新增。新增、修改、删除与策略修改均记录操作结果和源身份，不把接口地址中的凭据写入管理日志。

视频源巡检使用 `collect.CreateStrategyFromSource` 构建列表首页地址，并通过 `FetchWithStrategy` 使用实际出站路由、解压、响应封装与字段归一化。请求 `limit=1`，忽略条数参数的源仍受采集器 32 MiB 响应限制。巡检验证列表能力，不承诺关键词搜索；关键词接口明确拒绝搜索时，不能据此判断整个列表源失效。HTTP 应答后发生解析错误仍保留实际状态码，不能把 HTTP 200 的格式错误记成网络未应答。保存时去除地址首尾空白，策略构建地址时也兼容已有空白值；CMS 成功码接受数字及数字字符串，成功响应必须包含 `list`。gzip、zlib 包装及旧式原始 deflate 分别解压；无效元数据、全部不可解析的记录不能伪装成成功空页。部分记录无法解析时保留其他可用对象并记录告警。

[MAC CMS 采集实现](https://github.com/magicblack/maccms10/blob/master/application/api/controller/Provide.php)与[网页联想实现](https://github.com/magicblack/maccms10/blob/master/application/index/controller/Ajax.php)属于不同入口。普通 MAC CMS 采集搜索明确拒绝关键词（观测到的 `code=1002` 或协议正文 `暂不支持搜索`）时，首屏搜索可使用同域同安装路径的 `index.php/ajax/suggest`；网络、鉴权和任意 HTML 错误不触发该路径。API 码保留为带错误链的 `collect.APIError`，只在搜索操作处解释，不把列表或详情的同码错误一律归为不支持搜索。旧式前缀匹配的通配符补搜只用于未声明其他响应封装的 MAC CMS 策略，不改写任意声明式接口的关键词。

网页候选仍使用原源身份；候选不含分类，因此最多 20 个候选 ID 通过原采集接口进行一次批量详情读取，再应用既有分类禁用规则，不为每条结果另开请求。批量详情未返回全部候选身份时明确报错；不换源猜测身份。相对图片地址按同域入口解析。候选接口只提供有限首屏结果，`SearchSourceResult.limited` 标识这一限制，界面提示输入更完整片名，不能把候选数量当作全部匹配数。

未声明自定义响应封装的 CMS 接口同时接收 JSON 与旧式 RSS XML。XML 接收 UTF-8、GBK／GB2312 编码，分页、影片身份、CDATA 文本及多条播放线路先转换为已有 CMS 字段，再走同一映射和校验；有效空列表仍是成功空页，HTML 验证页或夹带第二份 XML 文档不作为成功响应处理。JSON 的 list 支持对象数组、单个详情对象及 null；字段映射与默认别名共用同一身份校验，部分坏记录跳过，全部缺少影片标识或名称时报解析错误。声明式 JSON 通过 response.list_path 等路径适配嵌套封装；任意 HTML、脚本、加密正文或自定义 XML 封装不承诺自动识别。

巡检返回增量字段 failure_kind：request 表示连接、读取或超时失败，http 表示上游非成功 HTTP 状态，source 表示业务码拒绝，decode 表示解压或数据结构无法解析，configuration 表示配置错误，cancelled 表示取消。错误链保留底层原因，HTTP 200 解析失败仍显示 200；源管理可以展开查看失败原因。明确业务拒绝先于列表解码处理，采集不会反复下载同一份已确定无法解析的响应。验证入口为 app/collect/adapter_matrix_test.go、app/collect/engine_context_test.go 和 app/service/source_probe_response_test.go。

源搜索同时返回 `filtered_count` 与 `unclassified_count`，分别说明分类规则排除与缺失分类造成的隐藏。被过滤为空的页面保留源站分页，仍可前往后续页面，不显示成“源站无结果”。请求失败展示结构化错误与真实重试入口；只有成功空响应才显示空状态。

持久化设置的界面确认以成功写入为准：默认源仅在 `SetSetting` 成功后更新当前选择和成功提示，保存中禁用重复操作。下载目录的 `Directory.Set` 串行执行写入，数据库保存成功后才发布新的进程内目录；失败或重置失败保留原目录。`SetDownloadDir` 绑定向前端返回错误，前端不吞掉失败，也不把未被后端接受的目录当作当前生效值。

下载由 `app/download/engine.Engine` 管理准入、HTTP／HLS 执行、任务状态、输出文件和 SQLite 断点；`service` 负责绑定适配、模式准入及 `download:progress` 事件发送。父包 `app/download` 保留执行器、目录及存储契约，SQLite 适配器依赖这些契约，避免实现反向依赖形成循环。

启动／恢复请求只负责提交一次下载。接受后，执行上下文归下载所有者管理，并生成独立的 `download.transfer` 身份，保留 `parent_request_id`、任务身份及模式；原始请求结束不取消已接受任务。暂停、取消和应用退出停止对应执行；退出等待网络、文件及最终断点落盘后才关数据库。最终断点使用保留执行身份的有界独立上下文，避免取消导致收尾状态无法保存。恢复持久任务时不自动启动网络传输，需要显式恢复。

模式切换与下载准入共用应用层模式锁：切换先阻止新提交，再等待当前下载暂停，避免暂停快照漏掉刚被接受的任务。进度快照复制分片状态，事件消费者不能反向修改任务内部数据。任务 DTO、公开绑定名与进度事件格式保持兼容。

Go 的 `runRequest` 保留原有 operation 名称，同时记录相同的 `rpc.*` 通道名。`operation.IdentityFromContext` 可以读取该后端操作的 request ID 与通道名。前端订阅 ID、Wails 原生 call-id、Go operation request ID 各有用途，不能把它们当作同一个跨进程追踪 ID。原生 call-id 继续负责实际绑定取消，结构化错误保留后端 request ID。没有增加逐请求的额外 IPC。

图片、HLS 与 Android 媒体 HTTP 入口返回 `X-CCZJ-Pipeline` 和 `X-CCZJ-Request-ID`。Range、分片和流式响应保留自身语义，不通过 RPC 合并器拼接。

## 视频查询、详情与用户记录

`app/media.Service` 拥有列表、远程搜索、推荐、详情、播放线路探测、显式入库、回收站、身份维护、收藏及观看历史。绑定层负责 JSON 兼容与 `runRequest`，这些操作不再绕过请求跟踪直接操作存储。`db.MediaStore` 显式接收数据库解析函数，用户记录和目录管理使用带上下文的 SQLite 操作；目录分页、分类、推荐与详情身份读取也接收请求上下文。目录搜索落库的事务关联请求上下文，取消后不能提交新结果。部分身份解析和分类策略的兼容辅助查询仍经包级数据库入口，尚未改为全量可替换存储接口。

收藏按全局视频身份共享，历史仍保留来源、视频、集数坐标。查询收藏遇到存储错误会返回错误，不能当成“未收藏”；没有历史记录仍返回位置 0。最近历史通过同一次 JOIN 取齐卡片字段，避免逐条补查及隐藏补查错误。

应用显式创建一个 `detail.Service`，供普通详情和线路探测共同使用，并在关库前关闭。兼容的包级缓存失效入口通过 `cache.SetDetailService` 接入这个实例，释放后恢复原入口；`detail.Default` 保留给旧内部调用和测试。详情缓存仍采用容量／字节预算和过期先返回旧值、后台刷新的规则。

共享详情取数复用 `workflight`（最多 64 个不同在途工作），一个等待者取消不影响其他等待者；最后一个等待者离开会取消上游。后台刷新由详情所有者持有、每键合并，并保留两分钟上限；应用退出取消并等待所有共享取数与刷新。工作使用独立 `video.detail.fetch` 身份并关联原请求；调用者拿到独立的视频／线路／集表快照。失效会推进缓存代次，新请求不会加入失效前的旧工作，旧响应也不能重新填回当前缓存。

显式入库只接受视频源，按来源／视频坐标去重，复制调用者数据后保存目录投影，不把详情、播放地址写进目录。成功提交后失效受影响源的缓存；恢复已退役目录与解除退役标记在同一事务进行。

删除、恢复、彻底删除、清空和合并返回已提交的 `CatalogChange`；单条身份和批量受影响来源都在写事务内读取。`cache.PublishCatalogChange` 只处理提交结果，不再“先查来源、再另开事务改库”；取消或失败不广播成功，提交后即使请求随后取消，也完成失效发布。旧内部 `cache` 变更入口复用相同存储实现，实际绑定从 `media` 进入。

数据库迁移 v20 新建 `catalog_retirements`，只保留彻底删除条目的源坐标和时间。目录行可以物理删除，收藏与历史不删，投影通过退役标记继续隐藏；再次入库时原子解除。迁移前沿用现有备份流程，不猜测旧版本已物理删除而无法区分的坐标，未入过目录的旧收藏／历史保持原可见性。便携内容备份沿用原格式，只携带用户记录和元数据，不携带完整目录或退役展示状态；SQLite 完整备份保留这些状态。

人工合并只接受所有记录带相同非空豆瓣 ID，或在无冲突豆瓣 ID 时片名归一化一致且已知年份不冲突的组；一条已知 ID 不能为无关的缺失 ID 记录提供身份依据。历史冲突仍取较大进度，进度相同取较晚记录，同时保留获选记录的视频坐标和观看时间，不伪造一次新观看。引用更新失败整体回滚。合并与目录批次写入共用可取消的身份写入准入；提交后推进代次，下一页重载批次索引，避免使用被合并掉的 ID。此准入只协调内存身份索引，SQLite 仍负责事务和数据库锁。

验收入口：`go test ./app/media ./app/detail ./app/source ./app/collection ./app/cache ./app/service ./app/db`；Windows 原生绑定与退出用 `python scripts/test-windows-lifecycle.py`，Android 验收包用 `python scripts/test-android-lifecycle.py --device <serial> --check-video`。共享探针只添加和清理自己的禁用视频源及记录，恢复默认源设置；覆盖 SQLite 入库、身份查询、收藏、历史、删除／恢复／清空／再入库。人工合并和失败注入由 Go＋真实 SQLite 验证，未将其写成原生界面验收。源级变更已通过 `source.Service` 协调 `collection.Service.Quiesce`：先禁止同源新采集，取消并等待旧运行收尾，再提交变更。

## 阅读共享获取与持久状态

`library` 保留获取协调职责，小说章节、漫画话次和质量策略继续由已有内部模块承担；本轮未按文件体量另建一套工具层。正文、漫画页和趋势通过 `workflight` 合并读取，各等待者独立取消，最后等待者离开才取消上游。`library.Close` 先取消全部读取种类，再等待，正文卡住不会延迟漫画请求的取消。目录、章节、所属作品和来源查库接收请求上下文。

`operation.OwnedContext` 为共享或后台工作分配独立执行 ID，只继承发起请求的关联号及明确字段。详情、采集、下载与阅读实际 I/O 共用它；工作寿命由各自所有者决定，不复制短 RPC 的截止时间或任意请求参数。共享工作关联发起者不代表后续等待者也归该发起者所有。

| 状态 | 权威存储与恢复承诺 |
| --- | --- |
| 视频收藏与观看位置 | SQLite `favorites/watch_history`，现有内容备份携带用户记录；播放器定期和退出时同步，未提交的最后数秒不能承诺恢复 |
| 近期视频时长与百分比 | `episodeProgress` 的 30 天浏览器缓存，校验根对象与每条值；丢失后用 SQLite 位置兜底，时长/百分比可能不完整；名称键只兼容旧显示数据 |
| 小说/漫画书架、进度与偏好 | SQLite `reading_state`，按模式与来源身份保存；既有旧浏览器值原子导入流程保留 |
| 详情、章节正文、漫画页与图片 | 各领域有容量/过期/失效规则的可丢缓存，不以缓存持久性代替业务提交 |
| 模式路由、视图分组与滚动 | `modeSessions` 的限时会话快照；漫画设置旧路由规范化，设置分组键与模式对应 |

应用仍以单进程单运行时装配，数据库和网络包级安装点属于兼容实现；媒体存储、下载执行器、阅读预算和工作所有者在真实替换点注入。本轮没有机械生成全套 Repository。若未来支持同进程多应用，应先迁移剩余安装点，而非并行发布两套全局状态。

SQLite WAL 的普通写事务使用 `BEGIN IMMEDIATE`，在读取待改状态前取得写入资格，避免读取后升级写入遇到 `SQLITE_BUSY_SNAPSHOT`。`ReadOnly` 事务仍使用 deferred，不阻塞并发写入；已有网络冷却记录和目录维护共用此数据库约定，不靠界面重试掩盖冲突。双连接竞争回归位于 `app/db/wal_test.go`。

## 来源配置与采集所有权

视频分类默认策略由 db 的归一化名称规则统一处理：福利、伦理片与倫理片（及片／类等后缀别名）新建时默认禁用，未知远程命中在入库前也按此默认过滤。迁移 21 原地修正旧库中这些分类的默认开关，保留影片和用户记录；之后手动启用会保留，不在每次启动重复覆盖。类型管理返回启用项在前、禁用项在后，同组按既有排序值、名称和身份稳定排序。


`source` 拥有来源校验、配置、健康、搜索和便携导入导出；`collection` 拥有按源登记的引擎、状态快照、手动与定时运行。应用装配注入事件发布与后台工作入口，两个模块不直接依赖 Wails。旧 `handler` 包的实现和测试已迁到对应领域，没有另留一套并行编排。

手动采集生成独立执行身份并关联准入请求；短 RPC 完成后任务继续，模式退出及应用退出仍能取消实际 HTTP。手动和定时运行共用收尾路径，状态完成意味着 HTTP、健康记录与缓存失效已经处理。源修改、策略切换、清空、删除和导入共享按源变更准入；取消等待不进行存储变更，变更期间拒绝同源新采集。下载与采集通过同一模式准入边界注册任务，避免切换时漏接。

来源创建及首次默认源设置原子提交；导入将配置、显式分类映射、媒体身份与目录置于同一 SQLite 事务。拒绝空目录条目、未知格式版本、跨模式覆盖以及阅读源中的视频数据。导出用上下文流式读取目录，唯一临时文件关闭后才发布，失败先关闭再移除，重复导出不覆盖既有文件。整源清空／重建先在同一事务保存退役坐标，再物理清空目录，防止保留的收藏历史重新冒出；再次入库解除退役标记并保留原位置。分类和策略设置只修改所属列，避免覆盖并发保存的其他配置。

回归入口：`go test ./app/source ./app/collection ./app/collect ./app/db ./app/service`。包含真实阻塞 HTTP 取消、源变更等待、注册拒绝、SQLite 失败回滚、流式导出取消及状态快照隔离；原生导入导出交互需单列验收。

## 宿主请求、更新与备份

更新元数据通过既有来源执行最多三路的有限并发，每个来源限时四秒；首个有效响应胜出，取消并等待其他请求收尾。手动检查与后台通知共享弹窗展示代次，迟到的失败不能覆盖已经发现或正在下载的版本；关闭后同版本通知不再反复弹出，用户手动检查可重新打开。

`runHostRequest` 将更新下载、备份导入导出和旧数据恢复登记到应用所有者；切换视频／小说／漫画模式不会取消这些操作，应用退出会取消并等待它们。普通页面查询仍归当前模式。前端组件销毁时取消自己持有的请求，仍用代次或对象身份阻止迟到结果回写。

更新下载由 `update.Service` 串行准入，避免同一进度通道混入多个安装包。`updater.Downloader` 显式接收应用网络预算，同一下载的校验和、HEAD、测速、正文与哈希验证共享请求上下文；固定批次使用 `parallel.Each`，主源成功后取消并等待多余请求。取消关闭响应、清理部分文件，不继续尝试下一镜像。模态框隐藏时保留下载，组件卸载时释放；“退出时安装”的状态读取也检查包路径与请求代次。桌面重启仅在替代进程成功启动后进入退出，两种拉起均失败时向界面返回错误；Android 拒绝桌面重启入口。

备份导出通过 `db.ReadBackupSnapshot` 在同一只读事务读取设置、来源、影片、收藏、历史与阅读数据，再过滤不应传递的本机信任与授权。导入、旧库合并和迁移归档恢复复用 `db.WriteBackup`：持有目录身份写入准入，把各类写入放进一个事务，任何存储错误或取消都回滚；无效或重复条目才计为跳过。缓存失效仅在成功提交后发布。归档临时副本每次恢复独立持有和清理，关闭一个恢复不能删除另一个仍在读取的副本。

`files.CopyContext` 统一复制与哈希读取的取消检查；`WriteUnique` 发布唯一导出文件，`WriteAtomic` 在同目录完成后替换指定文件，失败保留旧内容。来源和备份前端通过 `readFileDataURL` 接入请求 scope，读取前限制 64 MiB，取消时中止 FileReader 并解绑回调。备份文件列表按实际修改时间排序，唯一文件名的随机后缀不影响先后。导入和导出共用二十万条目的计数规则（包括阅读目录），JSON 也受 64 MiB 限制；超限导出在发布文件前失败，避免生成自身导入器拒绝的备份。

## 豆瓣补全的模式所有权

`collection.SchedulerService` 将视频模式上下文交给豆瓣调度器；补全批次具有独立 `douban.batch` 执行身份并关联父请求。停止同时取消限速等待、在途搜索和详情 HTTP，数据库查询、标记、回填与写入接收相同上下文。调度器只有循环真正结束才发布停止状态，仍在收尾的补全会计入运行状态，模式退出持续等待。手动补全和立即批次经过 `runRequest`，写入失败返回存储错误，不报告成功。

## 用日志追查操作

正常排查使用 INFO；WARN／ERROR 会省略步骤，日志面板会提示这一限制。启动记录包含应用、Go、Wails、平台和进程版本信息。每条新记录携带 `session_id` 和会话内 `seq`，历史文件解析与三种导出格式均保留身份；不同启动的相同序号不是同一条记录。旧文件仍按原格式读取。

`operation.Run` 记录开始，`operation.Log` 记录成功、取消或失败及耗时，内部步骤通过 context 继承 `request_id`、`pipeline`、模式和明确选择的业务输入。`operation.WithFields` 只接收适合诊断的字段，不传整个 DTO 或请求体。模式切换的设置操作使用独立操作边界，不能把切换本身注册到它要停止的旧模式工作组。

| 排查目标 | 日志证据 |
| --- | --- |
| 保存源后未显示 | `source operation complete` 的源身份、名称、启用状态、配置指纹；`sources_loaded` 的读取数量与身份；前端 `Sources.list` 的请求／合并身份、代次、`published`、`discarded_stale_response` 或 `failed` |
| 源搜索失败或结果减少 | 同一后端关联号下的源身份、关键词、页码、策略及配置指纹；请求地址、HTTP 状态、压缩编码、响应字节数及 SHA-256；原始／归一化／丢弃数量与少量作品 ID；分类禁用、未分类、可见数量与分页 |
| 搜索与网页表现不同 | `suggestion_fallback`、`suggestions_resolved`、`substring_retry` 与有限结果标记；只在实际发生时记录这些路径 |
| 请求没有实际出站 | `request_policy` 的缓存复用、在途合并、查询／站点／跨重启冷却、容量和频率限制及等待秒数；实际公共／本机代理尝试记录路由类型、节点指纹、状态与耗时 |
| 探测没有执行或失败 | `probe_cooldown` 的剩余时间与历史样本时间；实际探测明确标记 `capability=list`，抓取和最终结果共享源身份、策略、配置指纹与关联号 |
| 设置或下载目录没有保存 | 操作起止、设置键或目录指纹、结果与底层错误；默认源与模式保留所选身份，其他任意设置值不直接打印 |

先从错误的 `request_id`、搜索的 `ui_request_id` 或源身份定位，再按会话和序号查看步骤。前端列表日志保留自己的请求身份，搜索同时记录 UI 进度身份；普通 RPC 没有把前端订阅 ID 冒充为后端关联号。日志中的输入可以重发原操作，配置和响应指纹可以判断现场是否已变化；未保存的远端响应、凭据和旧配置无法从指纹还原，日志不代替配置备份。

不再在 INFO 逐条打印影片简介、演员、导演和图片地址。结构化值最多 2 KiB，整行最多 16 KiB，超长部分以原长度与指纹标明；请求 URL 去掉用户信息和片段，未列入公共 CMS 参数白名单的查询值脱敏，明确的凭据字段不输出。解码错误保留阶段、错误链与响应指纹，不把原始响应正文拼入公开错误。

日志目录或文件写入失败不会再丢弃内存记录。`persisted=false` 标识文件写入失败，概览提供失败累计数、未落盘累计数、最后错误与成功写入时间；下一次写入重试打开文件。初始化失败可以重试，显式初始化会接管此前懒建的日志目录。未落盘记录仍受 5000 条内存容量限制，退出或被覆盖后无法恢复。界面会持续提示本次启动发生过未落盘，不因下一条写入恢复就清零失败证据。

事件流不能推进轮询的补齐游标；轮询与手动刷新按序号合并，迟到或乱序记录仍可插回。超过内存容量的缺口会明确提示查历史文件。实时转发由应用工作组拥有，退出时停止；订阅队列丢弃数只表示事件推送丢失，不等同于文件日志丢失。

实时时间线导出默认包含全部保留文件及仍在内存的未落盘记录，按会话和序号去重；指定历史文件时只导出该文件，`since_seq` 则仅筛选当前内存。级别和关键词筛选均生效。扫描、条数或导出字节超过上限时明确拒绝不完整导出，历史查询标示扫描不完整；收集记录另有 64 MiB 预算，序列化通过有界流式写入，不先拼接整份导出内容。临时文件写入、同步、关闭成功后才替换目标，失败不清空已有目标。诊断报告附带最近最多 5000 条、8 MiB 的宿主进程日志、容量与写入健康状态，明确标记截断及跨模式共享进程的有限窗口。

日志级别先保存再切换；保留天数先保存再清理旧文件，持久化失败不修改运行值或删除历史。清除日志出现部分失败时向界面返回错误。

## 播放线路清晰度

进入详情页和播放页后，`ProbePlayLines` 按当前集读取各线路的 m3u8 元数据，不下载媒体分片做测速。探测使用既有媒体网络客户端、地址校验和重定向规则，每个列表最多 512 KiB、单线路 8 秒、整轮 24 秒；每批两路，播放页复用原来的两路源发现工作，不为每个源另开后台工作池。离页和换影片取消订阅并丢弃迟到结果。远端匹配的详情只读预览，用户选择后才沿原导入入口写入目录。

按 [HLS 协议的 RESOLUTION 属性](https://www.rfc-editor.org/rfc/rfc8216.html#section-4.3.4.2) 读取主播放列表声明的最高分辨率。该属性可缺省，普通媒体列表也可能只有分片；这种情况显示“清晰度未知”，不根据 URL、名称或带宽猜像素大小。声明值代表线路可提供的最高档，并不代表弱网 ABR 当前正在播放的档位。元数据读取失败显示探测失败，仍允许用户实际尝试播放。

清晰度按钮显示最接近的常用档位（144P、240P、360P、480P、720P、1080P、1440P、2160P、4320P）；横竖屏取同一档位，宽幅裁切视频按长边的 16:9 等效尺寸归档。例如 1080×608／1280×608 显示 720P 档，1920×800 显示 1080P 档。档位是展示分类，原始源声明宽高仍完整保留在提示和无障碍名称中，不改后端元数据，不把分类当成解码后的实际尺寸。缺少完整宽高时继续显示未知。

桌面端每条线路占一行，源名与清晰度徽标分列，线路名另起一行；已知档位从高到低、未知项靠后。源探测返回多条线路时更新对应源的结果，不追加上一轮记录；源身份和原线路序号作为行键，排序不自动改选当前线路。线路列表最多占 30vh（144～252px），内部滚动，防止探测结果展开后挤走选集。手机线路项同样分列，使用抽屉原有滚动容器，不增加嵌套滚动；视频下方的简介区不再重复展示播放源／线路入口，桌面保留来源面板；普通播放和全屏播放的“线路”入口均位于右上角收藏、投屏按钮之后；弹幕入口均位于底部控制栏，不在左上角重复挂载。线路、倍速、选集、更多设置和投屏复用同一抽屉组件：竖屏从底部弹出，顶部把手可在视口高度的 30%～90% 间拖动，初始 60%，支持方向键／PageUp／PageDown／Home／End 调整；内容独立滚动。关闭、取消触摸或离页时释放拖动捕获。

生命周期阶段直接显示在 loading.gif 下方原有加载文案处，随准备阶段更新，移除独立的左下角提示；播放开始后不另加浮层。续播按钮继续使用原来的位置与控制栏避让。全屏控制栏的上一集／播放／下一集组成同一操作组，通过既有页面事件切集，边界按钮禁用；窄屏允许控制栏换行，不再隐藏下一集。

`playlist_quality` 日志保留源、影片、集数、线路序号、声明宽高、带宽和失败原因，并继承请求关联身份。已有验收入口是 `scripts/test-playback-routes-browser.py` 和 `scripts/test-playback-routes-android.py --device <adb设备号>`。2026-10-25 浏览器回归覆盖 1280／1024px 桌面、390／320px 窄屏组件、裁切尺寸归档、待探测到 36 条线路展开、重复结果替换、选集位置和末条线路键盘选择，证据在 `dist/audit/playback-routing/layout-after/`。Android 脚本通过原生 Go 绑定读取受控 CMS／HLS 并实际触摸切线，其提示边界与全屏按钮选择器仍对应此前左下角方案，须按当前布局更新后再运行；本次不宣称 Android 原生通过。合成主列表的声明用于验证元数据读取，不把它当成真实影片画质证明。

## 视频弱网与分片调度

桌面与 Android WebView 使用同一套 HLS 播放、分片缓存和网络策略。缓存 loader 包装当前 hls.js 的流式 FetchLoader，保留响应头／正文超时、真实首字节与下载进度。成功后销毁 loader 不得把统计标记为取消，码率控制器会在分片进入缓冲后读取这些统计。缓存命中按最近实际吞吐量折算统计，不把内存速度当作网络带宽。

多码率切换由 HLS ABR 控制器负责；单码率源只有一个清晰度，网络持续低于媒体码率时仍可能耗尽缓冲。网络诊断按分片下载耗时与可播放时长的比例判断，并计入播放倍速；不从一次慢请求推断是服务器还是用户网络。正常／带宽受限分别保留 30／60 秒前向缓冲，分片正文截止时间随目标时长和近期下载比例在 15～60 秒之间调整。

正在播放的分片优先：前台下载立即取消后台预取，缓冲不足、下载能力没有余量、网络受限或失败时停止后台请求。只有当前播放点之后的连续缓冲达到门槛且吞吐量有余量时，才允许一条后台连接；按相邻顺序预取，不重复发起同一分片的对冲请求。跳转后旧的离散缓冲不计入可播放时长，旧预取窗口和会话迟到结果失效。动态媒体列表不进入永久文本缓存，避免播放完首个窗口后无法发现新分片。

`player_network_policy` 记录同一播放器会话的网络状态、实测／估算带宽、码率档位、可播放缓冲、后台额度和正文截止时间；`player_network_issue` 记录分片序号、档位、已收字节、重试与错误类别。`player_buffering_started/finished` 记录位置、是否跳转、倍速、缓冲及等待耗时，并区分恢复、暂停和退出，便于重放网络条件并对照卡顿时间线。

可重复验收：`python scripts/test-playback-weak-network.py --tag adaptive --scenario adaptive`，另有 `offline`（短暂断流）、`single`（可持续的单码率）和 `single-high`（网络不足的单码率）场景。需要 Python Playwright、Edge、Go、Node 和 ffmpeg。脚本实际解码生成的 H264/AAC HLS，经过生产 Go HLS 代理，共享总带宽从 3 Mbps／80 ms 降到 650 Kbps／250 ms 再恢复；额外注入响应头返回后正文停传，核对进度和超时。结果、请求时间线与生产日志放 `dist/audit/weak-network/`。浏览器脚本只替代无关 RPC，不替代播放器或媒体代理；Android 原生验收见 [Android 文档](android.md)。

## 共享网络策略

`app/netpolicy` 对所有查询出口统一应用梯度冷却：标准 5～6 分钟、稳健 10～12 分钟、低频 30～35 分钟。相同身份的请求共享截止时间，成功的完整小响应可在冷却期复用；无可复用响应时返回剩余等待秒数，重试和切档不重置已有期限。失败及已准入后的取消同样占用间隔，SQLite 账本跨重启恢复。不同查询分别计身份；播放、图片、下载、测速、设备控制等连续传输由 `queryRequest` 豁免。各领域更长的缓存仍在中间件之前命中，不会被梯度缩短。

豆瓣热榜、评论、搜索、详情和 `subject_abstract` 兜底另外共享站点级随机间隔与反爬静默期，限制不同查询的总体频率；等待限速槽位后会再次检查静默状态。验证失败、直接 HTTP 403／429 都会触发静默。静默到期允许下一次探测，连续失败按 5／15／60 分钟退避，只有正常响应才清零命中数。豆瓣本地静默状态目前只在进程内保存，重启会重置，统一查询冷却仍从 SQLite 恢复。中间件返回的冷却不计为远端反爬，详情不因此绕行 JSON 兜底。后台补全在静默期跳过整轮，批次中触发熔断后停止处理后续记录；搜索也停止尝试其他关键词。

| 接口 | 成功缓存与持久化 | 请求间隔与失败处理 |
| --- | --- | --- |
| 豆瓣热榜 | 按成功抓取时间缓存 **7 天**，SQLite 快照跨重启保留原时间；第 7 天后按需后台更新，旧榜单最多展示到抓取后第 14 天 | 失败至少冷却 5 分钟，同时遵守共享静默期；只有成功刷新才更新抓取时间 |
| 豆瓣评论 | 按条目／页码／排序缓存 24 小时，旧页可展示 7 天；内存最多 200 页，SQLite 最多 80 页／8 MiB | 同一页在途合并，失败冷却 30 分钟；命中缓存不发请求 |
| 豆瓣搜索／详情／JSON 兜底 | 没有通用结果 TTL；补全结果写入业务数据库，同豆瓣 ID 可继承已有字段 | 交互请求共享 15～40 秒随机槽位；后台批次共享 60～150 秒随机槽位。搜索正常页累计 5 次无结果后，按本地记录冷却 24 小时；详情成功但仍无评分也冷却 24 小时 |
| 弹幕搜索／目录 | SQLite 成功缓存 1 天，最多保留 30 天；跨单集、会话复用 | 相同请求冷却：标准 5～6 分钟、稳健 10～12 分钟、低频 30～35 分钟；失败及已准入后取消占用冷却，重试或切档不重置截止时间，冷却跨重启保留 |
| 弹幕索引／分段 | SQLite 按偏好缓存 1～30 天，默认 1 天；刷新失败可回退 30 天内的有效旧缓存，总容量 128 MiB | 与弹幕搜索共用请求策略；不同平台／单集／片段分别计身份，不自动请求其他平台补位；匹配失败按本地单集／平台冷却 24 小时 |

首页浏览器榜单缓存只负责立即展示，每次加载同时向 Go 获取缓存结果；浏览器收到旧数据的时间不能代替上游抓取时间，从而把更新再推迟七天。补全轮询默认每 30 分钟启动一批，可在设置调整；轮内请求带上述随机延迟，轮询周期不等于热榜刷新周期。首次无榜单、用户主动清缓存以及读取损坏缓存时，需要重新抓取。

`app/parallel.Each` 为有限批次创建固定数量的协程，错误或取消时停止派发并等待已开始的工作。视频源探测与线路测速最多使用 4 个工作协程。阅读前台源搜索跨请求共享五个活动额度，搜索、正文、目录、页图代理和检测图片通过 `app/library/quality/NetworkGate` 再共用五路 HTTP 闸门，额度保持到响应体关闭。背景巡检不能额外创建一套额度。短暂的内存状态读取采用批次接口，不额外创建协程。

全项目固定绑定的请求、派发、合并、取消、失败和拒绝次数随前端诊断导出，范围是当前文档会话，覆盖所有模式，不记录请求参数。Go 操作统计继续按模式筛选。关闭请求不等于撤销已提交写入，也不承诺中断旧存储接口中不接收 context 的单次同步调用。

## 公网代理池

`app/outbound` 在已有 `netstats.WrapTransport` 入口装配，每次实际代理尝试都经过原分类计数；外层 `netpolicy` 保留查询合并与梯度冷却。公共代理池接收 `douban`、`danmaku`，以及实际目标域名属于 `douban.com`／`doubanio.com`（含子域名）的 `image`／`reading-image` 图片请求；逐跳按实际目标地址判断，不用 Referer 识别。视频搜索与采集、阅读、其他图片、更新以及未知信息类别直接使用配置的本机代理，不等待公共池初始化、不选择公共节点，也不因公共池停用而关闭本机代理。没有配置本机代理时使用宿主普通直连。局域网／回环目标直接访问，原有私网访问授权仍生效；混合公网／私网 DNS 结果被拒绝。纯地址判据由 `app/netaddress` 共享，`proxy.IsPublicAddr` 保留兼容入口。

视频播放（HLS 清单、密钥、分片及媒体中继）、线路清晰度／测速和视频下载分别以 `playback`、`lineprobe`、`download` 分类保留调用方原来的 HTTP transport，不进入公共代理池，也不采用池配置的本机代理回退或等待节点刷新。底层客户端原有的代理设置、Cookie、Range、取消、TLS／地址校验、流量计数和共享额度继续生效。Wails 同源 HLS 中继仍负责跨域和引用头，不等于出站公共代理。此边界修复 2.4.2 中主清单与子清单在不同出口间切换后 403、无法起播的问题。

路由回归入口：`go test ./app/outbound -run TestMediaRequestsKeepCallerTransport -count=1`，覆盖代理池刷新中、耗尽和健康状态下的主／子清单、Cookie、Referer、Range 与真实尝试计数。实际内容源可显式使用 `python scripts/test-playback-weak-network.py --scenario single --seconds 15 --tag live-routing --media-url <播放地址>` 验证生产 HLS 中继与浏览器解码；该模式使用真实外网，不将合成带宽变化视为真实内容源的弱网测试，也不代表 Windows WebView2 或 Android 原生通过。

池内的信息请求依次使用健康公共节点，节点都不可用后才用配置的本机代理。默认 `system` 跟随系统网络设置：系统未配置代理时允许直接连接，适配普通手机网络；显式禁用本机回退时，池不可用仍返回错误。空池没有底层错误时也必须构造非空错误，不能返回 `(nil, nil)`。按注册域名稳定选路，失败才换节点。无法连上代理本身时让节点全局冷却五分钟；已连接代理后的目标站断开、CONNECT 隧道拒绝，以及 403／407／412／429／502／503／504，只让该节点对当前站点冷却五分钟，避免一个站点的故障影响其他站点。`outbound_attempt` 记录 `proxy_connected` 和 `request_sent`，区分代理可连接与请求已经发送。健康检查只证明节点当时能访问 IP 查询服务，不保证内容站点准入、带宽、地区和稳定性。响应头返回之后发生的流中断不拼接不同节点的响应；调用方按各自语义恢复。已发出的非幂等写入不会自动重放；带可重放请求体的弹幕查询型 POST 可按查询语义重试。HTTPS 保留目标证书校验，不接受关闭校验的代理传输。

代理池内部只有格式适配器不同：`HTML / JSON / TXT → 协议与元数据解析 → 公网地址校验与去重 → 跨来源轮换取样 → HTTPS 健康检查 → 有界健康节点池`。调用方仍只使用已有 HTTP 客户端，不各自获取列表、管理节点或重试。

默认登记以下来源；更新时间是本应用的保守抓取周期，不是发布方可用性承诺。只取一页，不自动遍历分页。

| 来源 | 格式与协议 | 本应用周期／状态 |
| --- | --- | --- |
| ProxyScrape、Databay | JSON／TXT，HTTP CONNECT | 15 分钟，启用；兼容旧 `sources` |
| 快代理、齐云 | HTML，按表头解析 IP／端口／协议 | 30 分钟，启用；齐云实测存在 403，会单独退避 |
| France VPN | HTML，逐行 HTTP／SOCKS5；跳过 SOCKS4／鉴权行 | 30 分钟，启用 |
| Geonode | JSON `data`，字符串端口与 `protocols` 数组，严格保留行级 CN | 15 分钟，启用 |
| proxy.scdn.io | JSON `data.proxies`，HTTPS 与 SOCKS5 各一源 | 15 分钟，启用；查询带 `country_code=CN`，接口没有行级国家，不能视为实测出口位置 |
| TheSpeedX、monosans | TXT，明确 SOCKS5 默认协议，不猜国家 | 60 分钟，启用 |
| Proxora | 优先官方 JSON `items` API，HTTP／SOCKS5 | 15 分钟，启用；无需同时抓 HTML 列表 |
| 站大爷、seofangfa、Rola | HTML | 已登记停用；本次分别为验证页、530、403，不能算成功来源 |

最多登记 16 个来源（含停用项），单源 2 MiB／最多 20000 条；默认每轮最多验证 24 个唯一候选、三路健康检查、保留最多八个健康节点。每个来源独立保存截止时间、候选缓存和轮换位置，失败从自身周期开始指数退避，最长六小时（配置周期更长时不缩短），不会触发其他源重抓；成功更新后复位。候选内存缓存最多使用两小时，健康验证仍独立进行。每分钟仅检查是否到期，节点验证按 `refreshMinutes` 或到期源更新运行，不按业务请求逐次触发。源下载最多三路、单源 12 秒、批次 40 秒；整轮连同健康检查最多 90 秒。HTTP 200 的验证页、未知 JSON 包装、失配 HTML 表头均为失败；有效空数组单独标记 `empty`。

列表里的 `https` 能力标签按 HTTP CONNECT 候选处理，只有明确 `https://` URL 才表示 TLS 到代理；SOCKS5 文本的裸 `IP:端口` 保留来源声明的协议。凭据节点、私网、保留地址和无效端口不入池；HTML 只解析表格字段，不执行脚本或从整页正则收集地址。所有候选仍需通过独立 HTTPS 出口检查；返回公网 IP 才算健康，通过检查不等于任意内容站点可用。

节点快照放既有 SQLite settings 表，原验证时间跨重启保留，超过三十分钟不再使用；局部更新保留未过期且本轮未验证的旧节点，验证失败会隔离旧节点。Transport 缓存最多 128 份，淘汰、响应体关闭与退出均负责释放。更新和探测由应用 `lifecycle.Group` 拥有，通过既有 `parallel.Each` 与 `netbudget` 限制并发，关库前停止与等待。

代理源下载属于路由控制面，不能递归调用正在构建的池：先用已保存的有效公共节点，失败或首次空池时才用本机代理下载列表。无本机代理、无有效快照且未配置种子时无法自动引导，明确报错。Windows 的 `system` 回退优先读取代理环境变量，再读取启用的 Windows 手动代理；PAC 没有被执行。Android 等宿主优先读取环境变量，也可明确配置本机代理 URL，不调用 Windows 设置。WebView 原生 fetch、系统组件和原生播放器自身的 HTTP 请求不属于 Go HTTP 出口，不能据此声称设备全局流量已代理。

后端设置键为 `outbound_proxy_pool_v1`，启动时保存默认值，通过现有 `GetSetting`／`SetSetting` 读写，修改后重启装配。`localProxy` 可为 `system`、明确的 `http://127.0.0.1:7890`／HTTPS／SOCKS5 URL，或空字符串（不允许本机代理回退）。公共种子必须为无凭据的公网 IP 与端口；源只能是无凭据的 HTTPS URL。配置示例：

```json
{
  "enabled": true,
  "sources": [
    "https://raw.githubusercontent.com/proxyscrape/free-proxy-list/main/proxies/protocols/https/data.json",
    "https://raw.githubusercontent.com/databay-labs/free-proxy-list/master/http.txt"
  ],
  "feeds": [
    {
      "id": "monosans-socks5",
      "url": "https://raw.githubusercontent.com/monosans/proxy-list/main/proxies/socks5.txt",
      "format": "text",
      "protocol": "socks5",
      "enabled": true,
      "refreshMinutes": 60
    }
  ],
  "seeds": [],
  "localProxy": "system",
  "refreshMinutes": 15,
  "maxCandidates": 24,
  "maxHealthy": 8
}
```

示例是精简的显式来源集；完整默认目录在 `app/outbound/sources.go`。`feeds` 格式支持 `auto/text/json/html`；`protocol` 为裸地址的默认协议（`http` 或 `socks5`），`country` 为可选行级国家筛选。旧配置若显式包含 `sources` 且没有 `feeds`，保持旧来源选择，不自动追加目录；要采用新增来源，保存含 `feeds` 的配置或完整 `DefaultConfig()` 后重启。配置不会自动覆盖自定义来源。

诊断活动页和导出中的 `outbound_proxy` 展示健康节点、公共代理尝试、本机代理回退与每个来源的候选数、状态、下次尝试和安全错误码，不输出代理认证信息。`ready` 只表示已解析，不是该来源节点均可用。源码测试默认不访问第三方；显式来源下载验收为：

```powershell
$env:CCZJ_OUTBOUND_SOURCES_LIVE = '1'
go test ./app/outbound -run '^TestLiveSourceDownloadAndParse$' -count=1 -v
Remove-Item Env:CCZJ_OUTBOUND_SOURCES_LIVE
```

该检查对每个启用来源断言下载／解析成功，外部来源故障会如实失败，但不改变其他源的结果，也不连接候选代理。真实节点与榜单验收为：

```powershell
$env:CCZJ_OUTBOUND_POOL_LIVE = '1'
go test ./app/outbound -run '^TestLiveAutomaticPoolAndChart$' -count=1 -v -timeout 115s
Remove-Item Env:CCZJ_OUTBOUND_POOL_LIVE
```

该验收使用临时 SQLite、全部默认启用源、最多二十四个候选与三个健康节点，真实查询一次豆瓣榜单，再确认重复请求没有增加代理尝试。联网通过只代表当次站点可用；完整来源调研与实测边界见[网络报告](../reports/network-request-policy-2026-10-19.md)。

弹幕公共池联网验收复用上述隔离 SQLite 与有限候选池，逐个平台验证搜索、单集元数据、实际弹幕窗口解码及重复窗口缓存：

```powershell
$env:CCZJ_OUTBOUND_POOL_LIVE = '1'
go test ./app/outbound -run '^TestLiveAutomaticPoolAndDanmaku$' -count=1 -v -timeout 6m
Remove-Item Env:CCZJ_OUTBOUND_POOL_LIVE
```

每阶段分别核对公共节点尝试与本机回退计数；本机回退成功不能算作公共节点验证通过。B 站、腾讯与爱奇艺分别报告，豆瓣或出口 IP 健康不等于弹幕接口可用。外网失败如实保留，常规验证不联网。
