# 阅读源路由、章节对齐与覆盖保留方案

2026-10-22。分模式内置源目录、分层搜索、章节／话次元数据对齐和随模式运行的周期巡检已接入。小说与漫画分别拥有规则、检测样本、排序记录和前端视图，共享五路阅读网络额度。实现与验证范围见[实施记录](reading-source-routing-implementation.md)。本文保留设计取舍；正文片段相似匹配、漫画视觉近似匹配仍未实现。

## 先解决是否应按分数淘汰

不设单一总分永久删除线。低总分源可能独有某部作品、某个版本或某段章节；未测、权限受限和真正内容损坏也不能混为一类。即使当前样本没有独有命中，也不能推断未知作品没有。

用已有日志做了一次纯离线阈值回放，不重新发请求，不改源开关。47 个完整适配源专项回归中，14 部不同作品存在成功抽样内容；如果只保留至少 60 分且状态非 failed 的源，其中 6 部会失去本轮已观测的可读来源。分散书目那一轮的 4 部有成功抽样内容的作品，则全部失去本轮可读来源。这不是全网独占证明，也不代表这些书的整本都可读。两轮基准不同，分别计算，证据见 `reports/source-quality/threshold-coverage-review-20261022.json`。

尤其当前评分同时包含置信度折算：样本不足最多 59 分，证据有限最多 84 分。咚漫漫画在只有一本命中的轮次为 59 分，在两本命中的专项回归为 84 分；不能仅凭这个分数变化认定站点内容突然变差。路由数据应分别存质量指标、置信度、样本量、规则版本和时间；未知保留未知，不填 0 分。

## 内置目录与分层多源搜索

源管理界面可以只展示产品维护的内置目录，内部保留完整源身份、状态与检测证据。内置不等于把所有下载的配置直接开放搜索：规则尚不支持的源先进入适配队列，不能只凭站点地址加入可读来源。

建议以“本作品已知可读来源 → 相应语言／题材的优先池 → 补充池 → 冷备／未测池”分轮搜索。使用最多 5 个共享额度，结果到达即展示，保留停止和继续扩展的能力；前台搜索／阅读优先，后台巡检让出额度。不同小说、漫画查询也共享额度，不能各自再起 5 路。

在时限内即便有一个结果，也不能宣称覆盖完毕或放弃其余来源：书名同名异作者、可访问章节少、翻译／版本不同，都可能需要继续扩展。没有结果时自动扩到后续池；达到预算或用户停止时明确记录只检查了部分源。不对数千源同时发请求，也不承诺任何作品一定搜到。

当前算法建议试行以下调度档位，属于后续回放待校准参数，不是已证明的最优阈值：

| 条件 | 处理 |
| --- | --- |
| 同版本本地证据至少 limited、实际阅读成功且分数 >=75 | 优先池 |
| 有足够证据、60–74 分，或有补充题材／章节价值 | 补充池 |
| <60、未测、证据不足、过期或临时超时 | 冷备／探索；按原因单独分类，仍可被精确作品命中提升优先级 |
| 多个不同时段确认不可用或规则损坏 | 冷却并降低探测频率；修复／复测后恢复，不删除书架和来源身份 |

已确认某本书／某章可读时，该证据优先于全站平均分。登录／付费限制影响当前可读范围，不因限制就删除内容来源。内置发布集合可以精简，但有独有作品或独有章节证据的来源需要保留备用入口和检测记录；没有覆盖证据的来源也不能当作冗余自动删除。

## 章节匹配应作为独立结果

`AnalyzeCatalog` 继续承担独立参考目录的多锚点核对、重复、反序及编号跳跃检查。新的小说／漫画匹配规则承担两源之间的目录位置对齐，两者证据分别保留。

跨源对齐应先确认作品、作者／创作团队、语言、版本和原著／改编身份，再对目录建立“卷＋编号／话次＋规范标题”索引。优先接受明确唯一的编号与标题匹配；只有编号相同、标题冲突时不自动对齐。标题改名、分卷编号重置、同名章节都保留歧义。

小说与漫画分别处理拆合章、上中下、番外、预告、小数话、单行本卷章和重绘版。单章可以映射多个候选章节，也可能没有可确认的映射；不能靠“总章数差不多”或“第100章对第100章”直接迁移位置。

唯一锚点先建表，按目录顺序串联；只在相邻锚点限定的局部窗口做有预算的相似核对，避免全目录两两比较。小说可用实际可访问的正文片段／段落指纹补证；漫画的图片相同／近似只能辅助，因为不同翻译、裁切、拼接及公共扉页会影响判断。采样正文不会证明全目录完整，视觉广告未检查时也不能写“无广告”。

输出至少包括 `matched / ambiguous / unmatched`、对应章节、证据、置信度、已访问／受限范围。新功能应独立记录对齐证据，不以同名合并书架进度；只有用户实际切源时才利用可靠映射落到对应章节，无法确认时保留原进度并让用户选择。

## 周期更新与覆盖保留

建议后台每 24 小时启动一轮全源轻检，分批持续推进；前台忙碌时暂停或让出额度。深检错峰轮换样本，稳定源可从 7 天一次开始，重点书目及变化／异常源优先复测。弱网、移动流量及应用退出应尊重实际运行条件，不要求应用退出后继续扫描。次数和周期是初始产品参数，需按负载及源站反馈调整。

SQLite 存按源／作品／章节的观测、时间、规则指纹、失败类别及置信度。用作品到来源的倒排表记录已知覆盖，章节记录对齐锚点／区间；统计“去掉此源会失去哪些已观测作品或章节”。只有存在足够新鲜且可读的替代证据时才能把某源标为已观测冗余，仍不能保证全站内容冗余。

样本覆盖很稀疏：批处理各源的查询书目不同，不能将“没测试到某作品”视为“源没有它”，更不能据此求一个无损删除集合。题材冷门源保留探索机会；每轮增加遗漏作品、投诉章节和新发现源，逐步校准分数与调度档位。

周期巡检属于应用内部生命周期任务，须拥有退出取消和等待、SQLite 有序迁移、共享网络预算及前台优先级。
