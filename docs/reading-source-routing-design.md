# 小说书源产品与路由设计

状态：2026-10-30 持续整改。小说供给分层、独立操作证据、候选折叠和换源正文预验已接入代码；下文仍包含尚未交付的目标，逐项范围见[实施记录](reading-source-routing-implementation.md)。通用术语见[CONTEXT.md](../CONTEXT.md)。本文以小说为主，第 11 节记录漫画来源的对照设计；该节尚未实施，不随小说方案自动迁移。

## 1. 产品目标与明确取舍

2026-10-30 缓存研究与实现补充：正文的最近访问时间、内容验证时间与书源复核时间分开记录。BlobStore 命中更新 mtime，30 天是闲置淘汰期限；正文记录增加独立 checkedAt，超过 24 小时或旧记录没有时间时，先读缓存再尝试刷新。显式刷新、取消及失败保留入口已接入阅读设置，交接与段落定位规则见[开发指南](development.md)。相邻章页数结果绑定正文与版式签名，字体／视口变化使排版结果失效。用户主动离线保存仍是未实现的独立目标，应具有容量及任务状态，不能用目录总章数冒充已保存正文，也不将本轮自动缓存优化描述为离线下载完成。

依据包括起点 7.9.480 本地正文读取校验、七猫 8.10 章末附加页的局部清理、官方番茄 7.4.1.32 阅读引擎的绘制缓存版本校验，以及 [fqapp 固定源码的正文缓存](https://github.com/ch6vip/fqapp/blob/724d43cc1958e315af8a2081909f908eb92a6873/lib/services/chapter_cache_store.dart)与[缓存目录不更新的用户报告](https://github.com/ch6vip/fqapp/issues/181)。后者是问题报告，不是本项目已复现的问题。REA 原始证据及 DEX 切片与父包的摘要对应保存在本地 `.cache/novel-research/`，不将单个局部方法扩大为竞品全部缓存策略。

番茄书源按访问路径记录可用性：网页负责发现与目录，正文优先使用客户端协议，可读范围以逐章结果为准。

默认路径是“打开书城 → 找到想读的书 → 开始阅读 → 持续读下去”。书源的格式、协议、规则和评分由应用承担；用户只在需要时选择版本或替代来源。书源模块对书城、搜索、书架和阅读器提供统一能力与证据，视图不各自制定可用性判断。

| 目标 | 产品含义 | 不成立的替代指标 |
| --- | --- | --- |
| 完整 | 某本书的目录、可读章节范围和已知限制说得清；当前章受阻时有可验证的恢复路径 | 目录章数多、首页能打开、第一章成功 |
| 多样 | 原创网文、出版／经典、外文和冷门作品有独立供给，版本可以选择 | 几千条重复规则、多个域名指向同一上游 |
| 快速 | 首批结果尽早显示，选书后尽快进入正文，后台任务给阅读让路 | 所有源同时请求、无限预取、只显示最快站点 |
| 美观 | 作品信息层级统一，来源与错误信息在需要时出现 | 每个站点照搬一套页面、把检测报告放首屏 |
| 简易 | 默认无需导入或编辑规则，换源一次明确选择，问题可恢复 | 用户自行试几十个开关、出现错误只能重启 |

确定的取舍：不追求源数量；不以总分永久淘汰冷门内容；不将不同来源正文静默拼成一本书；不把所有协议强塞进声明式规则。默认跨来源切换需要用户选择，阅读器只自动完成同一来源的正常翻页、预取和有依据的重试。

## 2. 当前事实与核心缺口

| 已有实现 | 需要改变的地方 |
| --- | --- |
| `registryFor` 合并维护目录与社区规则；`ensureBuiltinSources` 将可执行规则加入来源表并启用 | 适配完成、允许参与搜索、当前可读应分开；新规则不能只凭解析成功进入默认供给，手动停用始终优先 |
| 最近实例中有 42 条启用小说源；七条候选重测五条样本链通过、两条超时 | 这是来源样本，不是全本完整率，也不是所有 42 条今天均已复测；默认供给必须说明自己的证据范围 |
| 快检保存于旧 quality 设置；深检、搜索健康、作品阅读各有 SQLite 记录 | 保留不同测量语义，但统一供给源页及路由的证据查询，避免一个入口显示健康、另一个入口显示未测 |
| `searchManaged` 分轮检索，精确书名命中可停止一轮扩展 | 标题命中只形成候选，不代表作者、版本及可读范围确认；继续查找入口和未查完状态必须保留 |
| 书城有真实远端数据，但小说浏览主要依赖番茄适配 | 发现渠道与正文供给分开，某发现源失败不应让整个小说模式失去选书入口 |
| 来源身份、章节对齐、正文缓存、前后章预取及换源入口已经存在 | 补足“发现候选 → 验证目标正文 → 确认切换 → 保存新位置”的完整恢复状态，复用已有模块 |

上述表格保留整改前的基线，用于解释设计取舍；当前改动以实施记录为准。先修供给、证据和恢复；段评、仿真翻页和新的装饰性设计不进入本阶段主线。

## 3. 用户实际看到的流程

### 书城

移动端移除重复品牌栏，搜索框作为首个操作入口，下面是继续阅读和分类书单。每个书单保留“来自哪里、何时取得”的轻量说明；不把多站数据伪装成一个官方排行榜。

发现渠道可以提供书目而不提供全文。点击作品后必须解析为带来源的候选，不能把发现源的详情与另一个源的正文直接拼在一起。当前渠道失败时保留缓存和重试，并提供已有书架、搜索及其他支持发现能力的渠道；没有其他渠道时明确说明，不填假推荐。

### 搜索

先显示本地书架／书库匹配，再按有效证据检索维护池；结果到达即展示。相同规范书名、相符作者、语言和版本的结果可折叠为作品候选组，显示“可选来源 N 个”；信息缺失或冲突时分开展示，不自动归组。分组仅用于显示，旧条目 ID、收藏和进度不合并。

点击候选组，优先恢复用户的当前阅读来源；首次阅读展示推荐候选及理由，如“最近读到正文”“本章可读”“另一版本”。只验证候选身份、目录和起读位置所需正文，不在搜索结果页深检每一本书。

初始找到高相关候选后可结束首轮，界面表述为“已找到候选”；作者未确认、目录未取或正文未验时不得显示“已找到完整版本”。无可靠候选时自动进入补充池，在既有前台时间预算内推进；到预算后显示已检查／尚未检查数量，并提供继续扩展和停止。

### 详情与开始阅读

作品信息是主内容，来源区只突出当前选择、可读范围、最后验证时间和“其他来源”。首次打开可以立即读取目标正文，但只有实际拿到可读正文才记录“已验证”。“未检测后续章节”与“有受限章节”分别显示。

本书使用哪个来源由用户此前选择和有效证据共同决定。来源响应最快不等于版本最好，章数最多不等于目录最全；用户可以明确选定，应用不因后台排序更新而改选。

### 阅读受阻与换源

同源瞬时失败按错误类别提供重试；权限受限、章节不存在与规则失效不循环重试。保留当前正文、阅读位置与返回路径，同时显示准确原因和“查找其他来源”。

用户点击查找后，依次核对作品身份、对齐当前章节、取得候选目标正文。候选面板展示作者、来源、对应章节及验证结果；点击“切到此来源”即是最终选择，不再重复确认。存在拆合章或歧义时展示可选落点；无法确认时只能打开目标目录，不能跳到猜测章号。

切换提交以目标正文成功为前提；失败或取消不修改当前来源与原进度。成功时从对应章开头继续，说明“已切换到 X · 对应章节 Y”，保留原来源进度。第一阶段不在每章失败时静默切到其他来源；已验证替代也必须由用户选择。

### 来源管理

主视图是“默认使用／备用／需要处理”三个业务分区，支持名称、语言、题材和能力筛选。默认供给来自维护集合和用户主动启用的来源，不由“已收录几千条规则”决定。暂停状态独立保存，目录更新和重新发现都不能复活用户暂停的源。

详情显示站点与协议、配置原始出处、规则版本、支持能力、实际检测步骤与时间、限制和修复入口。检测必须区分“刷新已有记录”和“发起重新检测”，进度、取消、失败重试各有实际行为。暂不可用的源可保留备用和独有覆盖，不自动删除它的书籍。

对已有自定义来源保留管理入口，不以精简界面为由隐藏用户已保存的源。新源／订阅入口先预览识别、兼容性、规则来源和变更，再导入；这是后续能力，不在本阶段恢复一个裸 JSON 输入框。

## 4. 内容供给策略

供给分为维护集合、补充集合和待适配目录。维护集合按有代表性的作品、首中末章节和长期失败记录持续验证；补充集合保留题材、语言、版本和章节覆盖价值；待适配目录仅为工程候选，不能出现在用户的“可读 N 源”计数中。

当前首批中文候选为酷我、阅友、宅酷、番茄；这是样本链路通过的适配对象，不是已保证完整的默认发布清单。外文源独立分类，同站多规则按来源家族呈现，避免把同一听力室站点算作两份内容供给。平凡文学等此次超时的来源先标待恢复，后续成功可重新提升；不删除配置和已有作品。

每个进入维护集合的提供方至少具备：明确出处与维护者、可运行的适配、代表作品检索、可解释的目录／正文证据、失败分类及修复方式。发布时记录哪些语言／题材／版本仍缺供给；找不到书时积累匿名的缺口统计应另行设计，当前不得记录或上传用户搜索词作为默认行为。

正文获取沿用共享网络预算、持久缓存及失败恢复机制。接口变化时同步维护请求与响应兼容，逐章实测证据决定当前可读范围。

## 5. 统一能力、身份与证据

### 能力与身份

来源至少分别声明发现、搜索、详情、目录、正文、图文、段落身份、段评及是否需要访问会话。能力声明表示适配支持，最近观测表示当前运行结果，两者不互相覆盖。无段评不影响正文来源被选用。

保留稳定 `sourceKey`；规则变更使用 revision 使旧证据过期，不把改名当新源，也不把同站不同访问方式视为同一规则。同一上游的来源家族用于说明覆盖和协调限流，不承担进度身份。

收藏与进度沿用来源身份，作品候选组只是显示关系。新增当前阅读来源选择需要独立保存，并与原有按来源进度兼容；迁移旧书架不做同名去重，也不重写历史章节 ID。

### 证据的查询与展示

每项观测明确模式、来源身份、规则版本、操作、作品／章节范围、时间、结果、耗时及原因。沿用当前 SQLite 模块原地演进，不建立第二套永久 Map 或浏览器存储；旧 quality 记录作为有时间和范围的历史导入，不能导入当天就变成新鲜证据。

| 观测 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 搜索有结果 | 这次查询返回了候选 | 候选同书、章节完整 |
| 目录成功 | 目录可取得并解析 | 目录每章都有正文 |
| 某章正文成功 | 此版本此章曾可读 | 其他章或未来仍可读 |
| 权限受限 | 此访问方式缺少当前内容权限 | 站点已失效、其他协议也不能读 |
| 超时／限流 | 此操作此时未完成 | 内容永远不存在 |
| 规则不兼容 | 当前适配尚不支持 | 上游没有这本书 |
| 本地存储失败／用户取消 | 本机操作没有完成 | 来源质量下降 |

同一章同一 revision 的更新观测覆盖其当前状态，历史保留；不同章节和不同操作并列，不能用较新的搜索成功覆盖正文失败。新规则使旧证据标“待复核”。总分仅可用于内部排序辅助，用户主界面使用“本章已验证／后续未测／部分受限／暂时失败／待验证”等明确语义。

## 6. 请求顺序与缓存

优先顺序：当前正文与用户操作的目录 → 即将需要的相邻章 → 前台检索与缺章候选 → 后台检测。沿用阅读模式共享最大五路出站额度；同一上游的限流统一冷却，不因有多个规则绕过。后台检测可取消、让位、继续，应用退出须停止并等待。

候选数量、详情验证与正文预取均有上限，不同时验证所有结果；只有即将选用的来源进入正文验证。已命中的快照先展示，过期后后台刷新，但必须显示时间；失败保留旧内容，不能默认为最新。

当前 4 秒单源检索、16 秒单次后端批次、前端最多三轮／约 32 秒后停止启动新轮属于现有政策，不声称适合所有站点。本阶段先测首结果、可读正文和恢复耗时，再决定预算；不为了提高成功率无限加超时。正文与章节窗口沿用既有有界缓存；已完成的相邻章请求由阅读器交接，禁止切章又重复等待同一上下文。

## 7. 章节对齐与正文结构

复用 `app/library/novel` 与 `matching`，先确认作品、作者、语言、版本，再对目录建立卷、编号、规范标题与上中下等位置对应。匹配结果分 matched／ambiguous／unmatched，保留依据；只有编号相同而标题冲突时不自动确定。

正文片段相似只能作为有预算的补充证据，不证明全本等同；作者缺失、改编、同名书、番外、拆章和卷内编号重置都可能要求用户选落点。不能按章号或百分比复制位置。

正文后续演进为结构化块，保留真实远端段落 ID、章节版本、图文与必要获取上下文，同时迁移旧 DTO、正文缓存和调用方。段评按提供方能力接入，先正文、再数量、点击后评论分页、展开后回复；没有段落 ID 时不伪造。跨源不迁移外站段评，本地笔记独立保存。这是第二阶段，当前不为此增加空按钮。

## 8. 实现职责与迁移

| 现有模块 | 继续拥有的职责 | 目标接口的调整 |
| --- | --- | --- |
| `app/provider` | 各站搜索、目录、正文的协议和解析 | 声明自身能力；会话或签名属于相应 Adapter，返回明确权限／格式错误，不接管作品分组与用户进度 |
| `app/library` | 提供方装配、候选选择、缓存、证据解释和恢复协调 | `SourceDirectory` 返回按操作分类的证据摘要；搜索返回候选组及未检索范围，原始来源结果保留；路由理由由此产生 |
| `app/library/novel`、`matching` | 小说身份核对及章节对齐 | 保持独立匹配结果；恢复候选增加目标正文的验证结果，不能用 SearchOutcome 本身表示可恢复 |
| `app/db`、`app/readingstate` | 来源、观测、用户选择、收藏与进度 | 对旧记录原地迁移，必要时有序备份；新增选择关系不改旧来源进度，规则指纹变化只影响证据新鲜度 |
| `frontend/src/api`、阅读领域视图 | 传输解码、取消、用户展示和显式选择 | 消费统一证据与选择结果；移除视图独立推导的总健康／排名判断，继续使用既有请求及迟到响应保护 |

复用现有 `NovelBrowsePage`、`LibrarySearchPage/Stream`、`NovelSourceAlternatives`、`NovelChapterMatch` 与正文获取链，不另造第二个聚合引擎。已使用绑定签名和数据格式保持兼容；新增字段或操作应同步生成绑定、运行时解码及所有调用方，不能仅改 Go 结构体。

目标层面，找书只需要查询及续查身份；选书只需要来源作品身份；查找恢复候选只需要当前作品和章节；最终切换只需要已验证目标身份。网络预算、来源排序、证据过期、匹配步骤和取消资源由书源模块拥有，不能要求每个页面拼接一串底层请求。

旧 quick quality、深检和真实阅读观测不简单按“最新一条胜出”合并。先保留原始结果与时间，再提供一致的查询解释；来源管理和路由切到新查询后才停止旧写入口。候选组使用派生关系，不对旧 items 批量改 ID。版本迁移后发现坏数据应可回退到原来源条目，不以清库重建完成迁移。

## 9. 实施顺序和评审依据

| 阶段 | 可交付结果 | 完成依据 |
| --- | --- | --- |
| 一：供给与证据 | 维护／备用选择明确，源页、搜索与阅读使用同一证据查询，出处和限制可见 | 五条样本通过的来源不会被包装成五条全本源；手动暂停、规则变更、过期和冲突证据均解释一致 |
| 二：找书与选源 | 增量搜索、可靠作品候选组、详情可读范围和选源理由 | 同名异作者分开，已有书架按原身份续读；未查完可继续，找到标题不会误报完整 |
| 三：阅读恢复 | 失败分类、目标正文预验、显式切换与原进度保护 | 权限、超时、缺章和坏规则各有处置；目标失败／取消不改当前来源；歧义能选目录 |
| 四：能力扩展 | 新协议、结构化图文及只读段评 | 各能力有真实接口、缓存版本、失败恢复和移动端调用链，缺失能力不出现假入口 |

本阶段设计先评审阶段一至三，第四阶段不阻塞基础供给。实现仍遵守本项目不新增／扩写自动化测试、夹具和验收脚本的约定；编译、类型及静态检查后，由用户明确安排 MuMu／真机行为验收。

以下情境逐项检查：番茄目录完整但当前章受限；最快站点命中同名异作者；慢源有独有章节；所有发现渠道失败但本地书架可用；换源目标匹配却正文失败；用户暂停后更新维护集合；同站多规则共用限流；源规则升级使旧可读证据过期；评论请求失败但正文正常。不能用首次空页面或一个成功样章替代这些情境。

## 10. 既有研究与保留价值

旧阈值回放曾发现：47 个适配源专项回归中 14 部作品有可读抽样，按单一分数及 failed 状态淘汰后 6 部失去本轮已观测来源；另一轮分散书目的 4 部均会丢失。样本稀疏、查询书目不同，这不是全网独占或全本完整的证明，但足以说明不能用单一分数批量删除来源。历史证据位于本地 `reports/source-quality/threshold-coverage-review-20261022.json`。

社区设计、fqapp 协议及段评研究、2026-10-29 的七源重测分别保存在本地 `reports/source-experience-research.md`、`reports/01_fqapp_多媒体分发与请求链.md` 和 `dist/audit/novel-continuity/`。它们提供依据，当前源码及本文件的明确状态决定哪些已经实现。

## 11. 漫画来源改版：共享编排，保留图片与版本语义

状态：设计建议，尚未实施。本节依据当前工作区源码对照小说与漫画，不将小说已有能力算作漫画已完成，也不据此声明任何漫画源当前可用。

### 已有共性与实际缺口

| 领域 | 已有共性 | 漫画目前的缺口 |
| --- | --- | --- |
| 来源目录 | `SourceDirectory`、`useBuiltinSources` 已按模式读取，保留出处、规则版本和操作证据 | `ComicSources` 仍主要展示总分和开关，没有接入小说源页已有的分区、能力筛选、分页及单源检测展示 |
| 供给 | 注册、适配、搜索排序及维护任务共用现有 `library` 模块 | `ensureBuiltinSources` 对新增漫画的可读适配默认启用；小说已有维护集合约束。能解析规则不应等同于进入默认漫画供给 |
| 证据 | 搜索健康、`reading_work_sources` 和 `reading_chapter_evidence` 已区分模式；漫画已有 page_list 与实际 image 记录 | `sourceEvidence` 的作品阅读汇总目前只读小说观测，漫画源页没有接上完整的图片阅读反馈解释 |
| 候选 | `SourceAlternatives`、分轮搜索、作品身份核对、续查和取消已有共享实现 | 作品候选缓存、五分钟复核和真实阅读反馈目前由 `NovelBookSources` 及小说专用表持有，漫画没有对应的持久化候选流程 |
| 换源 | `MatchChapter` 复用匹配内核，小说与漫画各自解析章／话语义 | 小说先运行 `PrepareNovelSwitch` 验证正文再确认；漫画的 `choose` 当前在话次匹配后直接导航，没有页图预验 |

另一个两模式都应整改的点：当前目录能力在规则解析成功后直接填入 search/detail/toc 和 content 或 pages。这是能力宣称，不是逐项核对后的事实。后续应由实际协议适配和已配置操作决定声明，运行证据再描述各能力最近是否成功；例如官方作品目录未必支持任意关键词搜索。

### 用户流程

漫画源页建议采用“已启用／备用／需处理”的紧凑列表，搜索和能力筛选置顶。每行首先说明用途及最近结果，如“可发现作品”“目录已取得”“抽样图片成功”“图片访问受限”，出处、协议、规则版本、诊断码和历史检查放入可展开详情。刷新记录与重新检测继续分成两个真实操作。保留用户已有自定义来源和明确的启停入口。

发现频道可以只负责推荐作品。用户点开作品后展示明确的来源，不能把推荐站的元数据与另一站图片悄悄拼接。搜索结果可在可靠的作品身份与版本依据下折叠为“可选来源”，保留所有原始来源条目；作者、语言、汉化或版次缺失时不强行归组。

作品详情增加逐作品的来源区：优先读本地候选和旧证据，再按到期时间复核。当前来源优先展示，候选明确区分同作已核对、待核对、页表已取、图片抽样通过、受限、暂时失败、过期和停用。源页的整体评分不能替代本作、本话的状态，也不固定要求每部漫画凑齐三家来源；补充目标应由漫画自身的供给策略决定。

阅读受阻后的路径为：保留当前画面与进度 → 展示已有候选 → 核对作品及版本 → 对齐目标话 → 取得目标页表并验证实际图片 → 用户查看结果并确认 → 进入目标话。失败和取消留在原来源。若图片在检测后过期或失效，进入目标阅读器仍需正常处理错误，不能把短期准备结果当成永久可读承诺。

### 漫画必须独立解释的内容

- 搜索命中、目录取得、页表取得、图片抽样成功分别记录。抽样明确展示成功数量与范围，不表述为整话、全作可读。HTML 验证页、签名失效、缺少 Referer／会话、限流、权限及实际图片损坏分开反馈。
- 话次匹配保留小数话、分卷、上下篇、番外和重制标识。日文版、汉化版、单行本和重制版可能是同作的不同版本，应让用户选择；仅凭同名同作者或相同话号不足以证明可直接续读。
- 切换到对应话默认从该话开头开始，并说明页码未迁移。长图切片、裁切及拆页差异会改变页码和图内比例；没有可靠视觉定位证据时，不能把原来源第 15 页直接写到新来源。
- 图片核验复用现有 `quality.ImageProbe`、`ProbeReadingImageWithTransport` 及图片代理的实际内容校验能力。准备接口应统一取消、请求上下文和缓存复用，不让每个前端面板自行下载一批图片做成功判断，也不在共享五路预算之外另开检测并发。

### 共享能力的位置

共享范围放在 `library` 已拥有的候选编排、证据查询和持久化职责中：接收显式 mode、作品身份和可选的章／话身份，内部负责查缓存、到期补充、来源状态和取消。正文验证及漫画图片验证分别由对应领域提供。保留已有绑定作为适配入口，新增漫画操作时同步 Wails 绑定、前端解码和实际调用方。

小说的候选缓存表目前有 novel 前缀及小说专用查询，不应复制一套改成 comic 前缀。实施时先把持久化能力演进为按模式和来源身份隔离的作品候选记录，再通过有序迁移保留原有小说候选、复核时间及失败状态。候选关系依然是派生关系，不改书架与追漫条目，不合并历史进度。

前端复用 `useBuiltinSources`、候选状态和“查询／匹配／准备／确认”这些流程。漫画预验应有明确的漫画入口，不再让共享 `useSourceSwitch` 暴露一个实际固定调用 `prepareNovelSwitch` 的 preview。两端保留各自的预览内容、主题及话／章文案，不因复用而引入大批模式条件到模板。

### 建议实施顺序与限制

1. 先补来源能力与图片证据查询，接入漫画源页的分区、筛选和检测。新增漫画来源采用明确的维护集合及默认参与策略；既有用户启用、停用和自定义源保持原意，缺少用户操作记录时不猜测后批量关闭。
2. 再将小说作品候选缓存的通用部分演进为共享能力，接入漫画详情与换源面板，复用同一 SQLite 事实和请求合并。
3. 增加漫画换源准备：验证目标身份、规则版本、话次、页表和有范围的真实图片，再允许确认。采用有限预验而非每次扫描整话、全作；预览与阅读尽量复用同一图片缓存身份，避免刚验证又重复下载。
4. 最后补漫画搜索的版本感知分组与来源解释。语种／版次信息不足时保留独立候选，不为结果整齐牺牲身份可靠性。

本轮只完成设计，没有修改运行代码、数据库、来源启停或订阅，也没有发起源站检测。实施后按仓库要求编译、类型和静态检查；来源暂时失败、用户暂停、规则变化、页表成功但图片失败、不同版本页码不一致、预验取消、切换失败及原进度恢复由用户安排 MuMu／真机验收。
