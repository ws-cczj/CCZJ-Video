# 小说与漫画来源路由实施记录

2026-10-22。此版本已经接入下列应用行为，并补充了 [MuMu 原生搜索与阅读验收](https://github.com/ws-cczj/CCZJ-Video/blob/v2.4.5/reports/reading-performance-2026-10-22/README.md)；Android 真机与原生桌面阅读运行仍待验证。

## 两种模式独立拥有的行为

| 事项 | 小说模式 | 漫画模式 |
| --- | --- | --- |
| 规则 | `app/library/novel` | `app/library/comic` |
| 管理页面 | `NovelSources.vue`，书目清单 | `ComicSources.vue`，漫画卡片 |
| 查找其他来源 | `NovelSourceAlternatives` | `ComicSourceAlternatives` |
| 对齐入口 | `NovelChapterMatch` | `ComicEpisodeMatch` |
| 对齐语义 | 中文章号、分卷、上中下与番外 | 话次、小数话、卷、特典／预告与拆话 |
| 可读证据 | 无截断／混淆警告的实际正文 | 页表与已验证图片分开记，只有图片证据提升已知可读来源 |
| 切换落点 | 确认后从对应章节开头继续 | 确认后从对应话第一页继续 |

两种模式使用各自内置目录和样本桶。公共代码仅承担有界索引、SQLite 适配、网络额度和资源生命周期；数据身份仍包含 `kind + sourceKey + remoteId`。换源不合并原有书架／追漫进度，不复制章内百分比或漫画页码。当前没有可靠原位置时只给新作品目录入口，不猜测跳到某一章／话。

内部目录沿用批量实测的 6,232 规则快照：当时小说 3,702、漫画 2,530。当前拒绝将没有关键词参数的固定书单转换为搜索源，并新增经过实际搜索、目录和正文抽样的 `zhaicool-web` 小说适配；当前小说完整适配 42 个、漫画 4 个。拒绝转换后保留的原始规则身份及新增适配使当前去重登记数为小说 3,705、漫画 2,530，数量增加不代表每个站点都已验证可读。快照经过确定性 gzip 压缩内置，解压设 32 MiB 上限并校验原始 SHA256。未适配配置不会作为可读源启用，也不执行其中脚本或 APK。

源页展示已具备完整读取适配的内置规则，支持查找和启用／暂停，移除了新增配置、远程导入和编辑脚本的前台入口。未适配的内置元数据保留在内部待适配目录；已有自定义源、内容与进度仍保留，兼容方法没有删除。适配表示规则可以执行，初次未测仍显示“尚无足够阅读证据”。

## 搜索及排名

源列表首次加载／首次搜索会装配当前模式已适配内置规则，保留已有配置的来源身份与手动停用状态。搜索实测反馈与正文／页图质量分开：近期失败先后置，其余按本作品可读证据、精确搜索命中、近期搜索成功、未知和失败记录安排顺序，再比较有效质量池与分数。没有读过章节的搜索命中也能提升查找顺序，但不能成为可读证明。75 与 60 仅为质量池分界，不按分数删除来源；缺少正文／页图尝试的报告显示待测，不用零分冒充阅读质量结论。

每轮最多并行五源，每源期限为各模式政策定义的 4 秒，单次后端批次预算约 16 秒；剩余预算不足以启动完整下一批时返回游标。有规范书名精确命中即可停止扩源；仅作者名吻合不会停止，因为笔名也可能叫“天龙八部”。这个初步标题命中不等于作者、版本或完整性确认。前端没有精确书名命中且有待搜索来源时，自动跟进最多三轮，累计运行超过 32 秒后不再启动新轮，单轮在途请求仍可能用完自己的预算。用户可停止或继续扩展，游标保留尚未搜索的来源。

小说与漫画分别展示自己的结果，共用进度／异常折叠控件和取消链路。书名／作者匹配项优先，只有简介相关或源站推荐的条目放入“其他作品”；异常列表默认收起，展开有高度上限。显示已搜索和剩余来源，全部未命中、部分失败和未查完分别提示。小说页监听同一路由关键词变化，停止后切换关键词仍能重新搜索。

同一作品详情缺少作者时，若规范标题仍相同，保留搜索阶段取得的作者；详情实际提供新作者时仍使用新值。质量探测与换源章节匹配复用 `quality.MatchAuthors`，处理明确的国籍／朝代标签、著者署名和独立译者署名，不把译者当作者，不猜测异体字、笔名或改编关系。40 部类型代表的真实检索、误报和阅读边界见[质量评审补充](https://github.com/ws-cczj/CCZJ-Video/blob/v2.4.5/reports/reading-source-quality-review-2026-10-21.md)。

SQLite v19 独立保存 `reading_search_health`：同模式、同规则身份下，失败暂缓为 1／5／30／120 分钟，恢复成功即清零；记录跨重启保留，用户取消、本地存储失败与失效游标不作为源站故障。暂缓仅改变顺序，扩展搜索仍能触达；搜索记录不推进巡检时间，也不覆盖原有深检分数。后台先巡检完整适配源，再处理元信息目录，避免数千条不可读配置延迟前台可用源的检测。

小说、漫画的前台源搜索共用五个活动额度。搜索、正文、目录、页图代理和检测图片还共享同一五路 HTTP 闸门，额度覆盖响应体生命期；背景巡检串行推进，不再另起五路绕过前台限制。

## 小说搜索与阅读交互（2026-10-22）

小说搜索在当前模式内保留一个页面实例，返回详情或阅读前的搜索页时恢复结果、已搜索数量、续查游标及滚动位置；离开时取消未完成请求并保留已取得的结果。返回时超过 15 分钟重新搜索，与后端续查游标的有效期一致。切换模式释放页面，模式快照只保存轻量输入字段，不把完整搜索结果另存入浏览器存储。手动提交仍表示主动重新搜索。

全拼检索先用本模式的内置作品语料建立一次索引，再以流式本地书名扫描补充已发现作品；例如 `xiyouji` 可解析为“西游记”。只有唯一书名才转换，未知或同音歧义保留原词；不声称能把任意拼音唯一还原为作品，也未实现拼音首字母检索。源站收到中文书名，返回的有效关键词用于结果排序和匹配。小说、漫画索引隔离，续查继续使用同一有效关键词。新增 `github.com/mozillazg/go-pinyin v0.21.0` 提供汉字读音数据：固定版本、纯 Go、无额外依赖，模块顶层源文件约 0.79 MiB，未增加前端字典或 UI 框架；许可证与维护入口见 [上游仓库](https://github.com/mozillazg/go-pinyin) 和 [MIT 许可](https://github.com/mozillazg/go-pinyin/blob/v0.21.0/LICENSE)。Windows 测试和 Android 构建分别验证，不用编译代替真机检索结论。

小说详情和阅读内目录复用 `NovelChapterTools`，由共享 Segment、Button、NumberField 组成筛选、正倒序、当前章节、最新章节和序号定位。源站标题原样显示，移除重复生成的“第 N 章”。刷新保留旧目录和滚动位置，只在操作按钮显示忙碌状态；失败保留内容并显示可重试的错误。详情及阅读目录复用 BackToTop；后者指定目录的滚动容器。

小说默认上下滚动，保留用户已明确保存的横向分页选择。桌面滚轮在正文内自然滚动，读到章末后继续滚动进入下一章，在章首反向滚动回到上一章末尾；同一次滚动的惯性不自动跳过末屏。触屏使用原生滚动，边界处再次上下滑动跨章；分页模式也支持上下滑动翻页。正文末尾提供可见的前后章按钮。

阅读入口改用 `LibraryNovelContext`：SQLite 只构造当前章、前后可用章、位置与总数，跳过卷标记和已下架的相邻章；完整目录仅在打开目录面板时取一次，同一阅读实例内保留。接近目录末尾时用 `LibraryRefreshNovelContext` 复用十分钟刷新冷却，返回值仍为小窗口；不再每切一章返回完整 `ItemDetail`。源站不提供分页目录时，首次同步和必要刷新仍需获取其完整目录，但不会把全书正文一并下载。章节批量写入和下架在同一事务内按每批 100 行处理，避免长目录超过 SQLite 参数上限。

正文复用已有 30 天／256 MiB 磁盘缓存与五路出站预算。阅读实例另保留最近访问的至多 24 章／8 MiB、十分钟有效的内存副本，减少回看时的正文 IPC；身份使用后端同一源规则指纹及作品／章节自然键，配置修改后失效。只预取前后相邻章，退出实例释放内存与在途任务，失败或取消不写入正文缓存。重启后由磁盘缓存命中；缓存不是永久离线下载，超龄或预算淘汰后会重新请求。

同一本小说切章复用阅读实例，不使用路由淡入淡出，正文分页也直接切换。桌面默认滚轮翻页、左右方向键、PageUp／PageDown、空格／Shift+空格；设置可关闭滚轮或键盘翻页，前后键可分别指定方向键、字母或数字。F 与 Esc 留给沉浸阅读；输入框、输入法组合、修饰键和打开的面板不触发翻页。沉浸全屏复用 `platform/fullscreen.ts`，播放器也使用同一能力；退出阅读恢复窗口状态。移动平台不显示桌面按键设置。

阅读写入曾在 WAL 事务内先查询导入标记，再升级为写事务，与后台目录写入冲突时会立即得到 SQLITE_BUSY，绕过已有 busy_timeout。现在在事务前读取只增不删的导入标记，事务的首条 SQL 直接写入，让 SQLite 等待写锁；保留校验、原子批次和前端失败重试，不隐藏真实存储故障。`TestReadingProgressWaitsForConcurrentCatalogWriter` 复现过旧故障并验证修复后不会丢进度。

重复验收：启动本地 Vite 的 19320 端口，运行 `python scripts/test-novel-interactions.py --port 19320`。该脚本用生产 Vue 视图及确定性 RPC 替身验证搜索返回、全拼结果匹配、目录、真实浏览器全屏、桌面操作和移动呈现；不是原生宿主或真实源可用性验收。原始截图和结果在 `dist/audit/novel-usability/`；滚动与按需目录补充验证在 `dist/audit/novel-scroll/`，源站关键词传输与 SQLite 写锁另由 Go 测试覆盖。

## 章节／话次匹配

先核对原作品和目标作品属于同一模式，再核对规范书名及作者。缺作者保留暂定；作者／标题冲突拒绝自动对齐。标题规范化保留续作数字和改编标识；隐藏在标题之外的翻译／版次信息仍需人工核对。

各模式解析后，按卷、编号、标题、拆分标记、正常／番外类别建立索引。两侧都唯一的明确键才记 `matched`；编号相同标题不同、拆合章、缺卷、作者待核对或重名目录都记 `ambiguous`；不存在候选则为 `unmatched`。同名桶最多保留八个可展示候选，超出时仍可打开完整目录手动选择。复杂度为通常哈希表假设下 `O(原目录 + 目标目录)`，没有全目录两两编辑距离比较。

当前对齐依据目录元数据，不声称已核对全部正文、漫画视觉内容或完整度。正文片段指纹、局部相似度、漫画裁切／翻译版本识别尚不属于此版本。确认操作由读者明确触发；即使显示已匹配，也保留原来源进度。

## 后台巡检与存储

模式进入 45 秒后开始检查本模式内置目录。每个来源以持久化时间控制：通常 24 小时一次轻检，7 天一次深入抽检；循环每 30 分钟检查是否有到期项。退出或切模式会取消并等待旧模式任务，后台不会跨模式继续采集。停用的已安装源跳过巡检，前台网络读取会取消当前巡检请求，被取消的探测不会写成失败。

巡检样本沿用已采集的 6,832 部在线元数据，并加入原有带目录锚点的校准记录，按模式过滤、去重后建立独立基准哈希。记录于 `app/library/quality/bulk.v1.json`，与采集时冻结文件逐字节一致。它与之前 CLI 批次的基准分母不同，不能直接把分数并成同轮排行。

SQLite v18 新增检测、作品覆盖、章节证据及两源对齐结果；通过现有备份／有序迁移流程增加，不删除原表。轻检不会擦除独立深检分数；未知为 -1，不填 0 分。连续三轮明确探测失败会减少巡检频率、冷却 48 小时，保留启用状态、书架、作品覆盖和以前证据。得分还结合置信度与时间；失败冷却不是永久淘汰。

作品命中只写搜索覆盖。小说正文警告不会成为可读提升证据；漫画页表不算图片证明。图片代理成功验证图片后，仅按本源已有章节的完整 Referer 绑定抽样图片证据；无法对应就不猜章节。更新页表不会抹掉同规则的已验证图片记录，规则变化则使旧证据失效。此类抽样不能证明一整话图片全部正常或无广告。
