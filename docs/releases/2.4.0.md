# 2.4.0 发布与更新

版本来源为仓库根目录 `version.json`。Windows 文件版本为 2.4.0.0，Go 与 Android 展示版本为 2.4.0，Android versionCode 为 20400。

## 打包

在 Windows 仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build/release.ps1 -NoOpen
```

也可使用 `task release` 或双击 `build/release.cmd`。需要项目 Go、Node、Wails v3 环境，以及 Android SDK、NDK 和 JDK 17+。脚本先执行完整仓库验证，再构建前端、Windows EXE 与便携 ZIP、Android ARM64 Release APK，最后生成并验证发布清单。

默认 `-AndroidSigning ExistingPreview` 明确使用本机已有预览版密钥；不存在时拒绝生成新身份。当前 APK 的包名仍为 `com.cczj.video.preview`，并沿用之前 Android Debug 证书以支持旧预览版覆盖安装。Release APK 不可调试；构建类型与签名证书是两件事。请保留原密钥，它仍是预览版签名，不应当作应用商店正式签名方案。

需要使用自己管理的密钥时，设置 `ANDROID_KEYSTORE_FILE`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`，再传 `-AndroidSigning Environment`。更换证书通常无法覆盖已有预览版，不能把不同签名的包当成兼容升级。相关系统规则见 [Android 应用签名文档](https://developer.android.com/studio/publish/app-signing)。

`-SkipBuild` 仅对目录中已有产物重新生成说明与校验，不能把修改后的源码编进旧文件；`-SkipVerify` 跳过构建前仓库验证，但仍检查产物身份与完整性。旧入口 `build/windows/release.ps1` 已转接统一流程。

## 上传 GitHub

目标仓库为 `ws-cczj/CCZJ-Video`，标签为 `v2.4.0`。先提交并推送本次实际发布的源码，再让标签指向相应提交。当前清单明确记录工作区含未提交改动，不能据其中旧 HEAD 认定完整源码已经发布。

在 GitHub 创建 Release，正文使用 `dist/releases/v2.4.0/release-notes.md`，上传该目录中的全部八个文件：

- `cczjVideo-windows-amd64-2.4.0.exe`
- `cczjVideo-windows-amd64-2.4.0-portable.zip`
- `cczjVideo-android-arm64-2.4.0.apk`
- `checksums.txt`
- `version.json`
- `artifact-manifest.json`
- `android-metadata.json`
- `release-notes.md`

保留文件名，设为普通公开 Release。只上传 EXE 或 APK 会缺少更新校验依据。上传前可再次执行：

```powershell
node scripts/check-release-artifacts.mjs dist/releases/v2.4.0
```

本地脚本准备文件，不创建标签、不上传，也不发布 GitHub Release。发布后，应用的在线更新才能发现 2.4.0。

## 自动更新行为

Windows 保留下载、SHA256 校验、立即安装／退出时安装和替换回执。2.4.0 选择附件时同时核对系统、架构和扩展名，不再把任意首个附件当作更新包。

Android 选择匹配架构的 APK，下载到应用私有更新目录，校验后交给系统安装器。原生宿主还会核对路径、校验凭据、包名、版本号和签名。未授权“安装未知应用”时打开系统设置，授权后返回并再次点击安装；系统安装界面需要用户确认，取消不算安装成功。此权限接口依据 [Android PackageManager 文档](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls())。

旧 Android 宿主不含新安装桥接能力，首次升级到 2.4.0 请从 GitHub 下载 APK 后由系统覆盖安装，保留应用数据。安装本版后，后续版本可使用应用内下载与系统安装入口。ARM64 手机包不能安装到仅支持 x86_64 的模拟器。
