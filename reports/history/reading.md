### 小说优先：真实书城与完整阅读路径

2026-10-21，依据用户对上一轮交付的反馈重新确定方向。本轮已实现真实书城，实施与验证见 [书城交付记录](../novel-bookcity-2026-10-21.md)。本轮范围仅小说；漫画保留现状，后续另行设计。

<a id="origin-novel-first-plan-2026-10-21--纠正上一轮方向"></a>

#### 纠正上一轮方向

用户没有目标书名时，应能像进图书馆一样先浏览、筛选、挑选。默认进入个人书架、只提供搜索或“已入库作品”不能满足此需求。上一轮真实源回归验证了指定关键词后的搜索与阅读，首页截图使用测试书目，未验收零历史、零收藏、零关键词的首次浏览。

整改前的根本缺口：`app/library/catalog.go` 的 CatalogPage 只查询本地 SQLite；既有操作集合不含远端浏览。本轮通过独立的真实源浏览接口补足，未用本地收藏或预设关键词搜索替代。

<a id="origin-novel-first-plan-2026-10-21--小说的产品结构"></a>

#### 小说的产品结构

主入口为“书城 / 书架 / 设置”。搜索位于书城顶部，可随时精准找书。

- 书城负责尚未决定读什么的用户：真实源提供的作品列表、分类、榜单、完结等浏览入口。首次进入已有书可看；各板块名称以源实际提供的含义为准。
- 书架负责已经决定读什么的用户：收藏、在读、阅读历史、更新和继续阅读。
- 作品详情帮助选书：书名、作者、分类、字数、连载状态、简介、目录、来源与试读动作。数据缺失时只显示已知字段。
- 阅读器围绕长文本：排版、章节衔接、目录、位置恢复与退出路径。试读后可加入书架；从浏览返回时恢复分类、列表页和滚动位置。

小说视觉围绕中文书籍信息设计：适度封面、易扫读的标题作者、短简介与分类信息。桌面呈现较完整的分类与列表，手机优先显示当前分类和可连续滚动的书籍条目。漫画的封面墙、话/页进度及图片工具不作为小说页面模板。

<a id="origin-novel-first-plan-2026-10-21--实施顺序"></a>

#### 实施顺序

1. **接入一个完整的真实浏览源。** 优先验证番茄分类分页、榜单的文本作品过滤、详情、目录与可公开读取章节；再验证备用源。来源有浏览、搜索或阅读哪种能力要准确区分。
2. **补齐后端浏览能力。** 提供可浏览频道/分类与作品分页，保留来源身份、上游排序及真实续页信息；统一使用已有请求取消、超时、网络保护与错误链路。已停用源不自动恢复，浏览响应不授予脚本信任。
3. **建立书目缓存。** 浏览书目与个人收藏分别管理；首次打开无需用户预先搜索。先展示有标记的上次浏览结果，再按需刷新；短页加载、有限并发，过期或失败不标成实时推荐。
4. **单独重做小说书城。** 先用真实封面、真实长度的书名、缺失字段和大量章节检验版式，完成“浏览→详情→试读→加书架→继续阅读→返回原列表”。
5. **按用户路径验收。** 新的隔离数据库中不输入搜索词、不预先导入作品也能进入浏览；切分类、翻页、打开详情、读章节、退出恢复、重启续读分别验证。对 Windows Wails 与 Android 原生端实际操作并报告结果；浏览器替身只用于辅助回归。

<a id="origin-novel-first-plan-2026-10-21--完成标准"></a>

#### 完成标准

没有明确目标书名的用户，能在小说模式内连续浏览不同真实作品，识别作品、试读并留下阅读进度；下一次能接着读。这个路径以真实源和真实内容跑通，才视为小说阶段完成。漫画阶段在此后启动。

<a id="origin-reading-redesign--目标与证据"></a>

#### 目标与证据

用户实际使用反馈优先于既有“完成”报告：小说与漫画缺乏各自特点，阅读返回不能恢复原位置，源管理拥挤且大量不兼容，说明性内容挤占实际功能。整改以完成阅读任务为目标，不以页面数量、源数量、截图数量或测试数量为完成标准。

本次静态检查确认：

- `frontend/src/novel/views/NovelReader.vue` 的顶部与沉浸态返回入口使用固定书籍详情链接。
- `frontend/src/comic/views/ComicReader.vue` 的对应入口使用固定漫画详情链接。它们没有直接表达本次阅读来自书架、搜索或详情的语义。
- `NovelHome.vue` 使用书架数据组织特色区和推荐区域；`ComicHome.vue` 使用本地书库组织发现区。页面命名与实际数据来源需要重新对齐，不能把本地收藏包装成外部发现。
- `LibrarySourcesPanel.vue` 默认打开源库；`LibrarySourceCatalog.vue` 同时承担导入、社区库、筛选、排序、多选、检测和详情等任务。功能存在不等于信息层级合理。
- 旧设计要求小说与漫画都有发现、分类、个人页和大卡片区域，容易继续复制外壳，而没有先解决“找到能读的内容并接着读”。

尚未确认：用户安装包与当前源码是否一致、返回循环的完整触发路径、每个源在用户网络环境的实时可用性。本轮没有启动应用、复现故障或验证真实源，不能写成已定位全部根因。

<a id="origin-reading-redesign--产品结构"></a>

#### 产品结构

共用账号无关的基础设置、主题语义、错误映射、源身份、网络保护和持久化能力。小说与漫画分别拥有内容页面、阅读布局、进度语义及主要操作。不得为了差异化重复底层服务，也不得为了复用把两个产品压成同一个带 `kind` 参数的完整页面模板。

| 任务 | 小说 | 漫画 |
| --- | --- | --- |
| 默认入口 | 书架：最近在读、书名、作者、章名与进度 | 书库：封面、未读话数、最近读到的话与页 |
| 找内容 | 搜索优先，结果以书名、作者、简介辨识版本 | 搜索及有真实数据支持的浏览，结果突出封面与作品版本 |
| 详情 | 简介、来源、开始/继续阅读、可搜索章节目录 | 封面与简介、来源、追漫、话列表、已读状态 |
| 阅读 | 连贯正文、排版、分页/滚动、章内定位 | 条漫/单页、LTR/RTL、缩放、逐页加载与失败重试 |
| 更新 | 仅在实际检测到新章节时提示 | 仅在实际检测到新话时标记未读；无数据不造更新流 |
| 设置 | 排版与阅读行为优先 | 阅读方向、适屏方式与加载行为优先 |

当前主导航：小说“书城 / 书架 / 设置”，漫画保留“书库 / 找漫画 / 设置”。小说搜索位于书城顶部。源管理位于设置，也可从搜索的源选择入口抵达。小说书城已接入真实分类、出版列表与阅读榜，个人书架独立于浏览书目。

小说默认首页可直接浏览，首次使用配置内置可信文本适配器；已有停用源不自动恢复。阅读桌展示真实出版作品，主题书架提供连续浏览。个人书架空状态引导找书；原有收藏应始终可进入，不因源列表加载失败而封锁整个书架。漫画首页暂不调整。

<a id="origin-reading-redesign--返回与恢复契约第一优先级"></a>

#### 返回与恢复契约：第一优先级

“返回”与“查看作品详情”是两个动作，不能用同一固定详情链接代替。

1. 进入阅读前记录本次入口：模式、路由及查询条件、列表状态、内容锚点和滚动容器位置。入口可以是书架、搜索、详情或继续阅读。
2. 阅读器内切章、翻页、调整排版不制造新的页面返回层级，也不丢失本次入口。章节路由可以替换，但不能覆盖入口信息。
3. 点击阅读器左上角返回，一次退出阅读并回到本次入口。搜索词、筛选、结果集、选中项与滚动位置恢复；按稳定内容锚点恢复，像素位置作为补充。
4. 返回后再次返回应继续向上，不能再次进入刚退出的阅读器。防止“详情 → 阅读 → 详情 → 阅读”循环。
5. 系统返回与 Escape 先关闭最上层模态面板；无面板时按页面返回。阅读工具栏是否隐藏不得让用户连续返回才能离开。各输入方式共用明确的返回规则。
6. 外部深链、刷新或入口失效时，安全退回同模式详情；详情也不可用时回到书架/书库。禁止任意外部 return URL，禁止跨模式错误恢复。
7. 返回前保存进度；保存失败要有明确反馈和重试机会，不得静默宣称成功。退出时取消请求、停止预取并阻止迟到结果回写。
8. 长期阅读进度仍由 SQLite 管理。临时导航快照与长期进度分开，不能为导航重构清除书架、旧进度或偏好。

实现前先为用户路径建立能失败的回归用例。检查路由、模式恢复、原生返回和阅读器事件的交互，不先凭猜测替换所有 `push/replace/back`。交付证据包括操作序列和逐步路由/页面状态。

<a id="origin-reading-redesign--小说设计"></a>

#### 小说设计

书架默认使用紧凑书籍行，展示小封面、书名、作者、最近章节和阅读状态；继续阅读是直接动作，管理操作收纳到菜单。字号和行距围绕长时间中文阅读设计，正文宽度可调，纸色和夜间主题遵守用户偏好。

详情把“继续阅读”和目录放在容易触达的位置。目录支持搜索、正倒序、定位当前章与加载反馈。缺失章节、分段未完成与网络失败分别说明，不用空正文冒充成功。

进度使用稳定章节身份和章内文本锚点；字体、窗口、横竖屏变化后尽量恢复同一段落，不仅按旧页码定位。分页和滚动各自验证。正文不夹源管理提示、装饰卡片或大段使用说明。

<a id="origin-reading-redesign--漫画设计"></a>

#### 漫画设计

书库以封面网格为主，标题和未读标记克制；列表与网格可按实际需要选择。详情按话组织，明确已读、未读和当前话，避免把小说“章号”简单改名为“话号”。

条漫保持图片自然比例与连续滚动；单页支持 LTR/RTL、适宽/适屏与缩放。缩放时区分平移和翻页，点击工具栏不得穿透为翻页。优先加载当前页与有限相邻页，远离视口的图片及时释放。

加载、解码失败和重试按单页呈现，保留占位几何，不让前页补载把当前页顶走。进度保存稳定话身份、页身份和页内位置；前后话切换、旋转屏幕和返回重进后都要恢复。图片 Referer、Cookie 和声明请求头应贯穿资源请求，缓存必须保留隔离语义。

<a id="origin-reading-redesign--源管理重做"></a>

#### 源管理重做

默认页展示“我的源”：名称、类型、启用状态、简短可用性结果，以及检测/更多操作。没有源时展示单一“添加源”入口。批量操作仅在进入管理状态后显示。

“添加源”单独成页，分为可用目录与手动导入。手动文件/链接导入作为明确入口；规则编辑、兼容诊断、原始元数据进入高级详情。普通用户不需要先理解 JSON、CSS 选择器、APK 或脚本引擎。

默认目录只展示当前引擎已适配且具有明确检测证据的候选；未检测源可在明确标记的独立区域查看。尚不兼容的候选从普通目录移出，只在高级兼容查询中保留，并禁止当作可读源推荐。不能靠“完整库几千个”制造可用错觉。

兼容性和健康状态分别存储、展示：

- 兼容性：支持、部分支持、不支持，附缺失能力。
- 健康状态：未检测、检测通过、部分失败、暂时失败、需登录/验证，附检测时间与环境。
- 检测证据：搜索 → 详情 → 目录 → 正文/实际图片解码。HTTP 200、规则能解析、导入成功均不能单独算可读。
- 小说检查正文非空、非错误页、章节内容完整性；漫画检查实际图片响应、解码及必要请求上下文。单本通过不能声称整个源都可用。
- 失败时提供适合该原因的动作：重试、修改配置、停用或查看详情。普通页面显示短原因，日志保留诊断细节。

源能力不足必须处理到适配层：为实际需求实现相应适配器，或如实列出缺口。不能通过隐藏错误、取消检测、修改徽标来交付“兼容”。不承诺运行任意 Legado JS 或 Mihon APK；脚本授权不得被导入或备份绕过。

<a id="origin-reading-redesign--文案与视觉验收"></a>

#### 文案与视觉验收

每个页面先明确一个主要任务。说明只用于解释必要选择和下一步；无操作意义的欢迎语、设计宣言、能力口号删除。没有真实数据的评分、榜单、更新数与推荐区删除。空状态一条原因、一个主动作，必要时一个次动作。

保持已有主题与图标体系。小说强调正文和书籍信息，漫画强调图像与页操作。差异必须体现在布局、数据与交互，不能仅换强调色。键盘可操作，图标按钮有名称，焦点可见；触摸目标至少 44px，减少动画设置生效。

#### 实施顺序与验收门槛

| 阶段 | 必须交付 | 验收门槛 |
| --- | --- | --- |
| P0：可靠阅读 | 返回/恢复修复、可读链路诊断、回归用例 | 下方完整路径通过；能连续阅读和退出 |
| P1：信息结构 | 两种模式独立页面方案、源管理分层、删无效页面与文案 | 首次添加源到阅读无死路；已有内容能直接续读 |
| P2：阅读品质 | 小说锚点恢复、漫画逐页状态与资源管理 | 排版/旋转/失败重试不丢阅读位置 |
| P3：交付 | 全量检查、原生验收、构建与证据 | 报告版本、环境、失败、未测项和产物对应关系 |

每阶段先记录现有失败基线，再修改行为。测试必须驱动真实调用链，不写只检查实现字符串的伪回归。建议覆盖：

1. 搜索后滚动 → 详情 → 阅读 → 连续切三章/话 → 左上角返回 → 详情 → 返回原搜索状态。
2. 书架/书库滚动 → 继续阅读 → 切章/话 → 一次返回原书架位置。
3. 打开目录/设置面板 → 系统返回关闭面板 → 再返回离开阅读；左上角退出行为单独验证。
4. 阅读中刷新、外部深链、入口作品删除、切换模式后恢复；均不能循环、白屏或进入其他模式。
5. 离线、超时、限流、登录要求、空目录、正文不完整、图片部分失败；已有缓存和进度保留。
6. 快速切章、返回时请求未完成、重复点击、重启后继续阅读；旧请求不能污染当前页面。
7. 同名不同来源作品分别保存；升级、旧数据导入及备份恢复不丢数据。
8. 320/360/412/768px 与桌面 1280/1440px，深浅主题、长标题、文本放大、键盘和触摸；检查真实页面而非只测几何。

执行仓库 `scripts/verify.ps1`，行为变化补充前端与 Go 相关测试。绑定签名变更时运行 `scripts/generate-bindings.ps1` 后再验证。复用并修正 `scripts/test-reading-browser.py`、`scripts/test-reading-usability.py` 及 Android 验证脚本，不能假设旧脚本已覆盖本次症状。

浏览器替身、Windows Wails 和 Android WebView 分别报告。公网检测记录时间、版本、样本及结果；不将一次成功推广为永久可用。最终至少展示两种模式的书架/书库、搜索、详情、阅读器与源管理实图，并附可重复的返回验证步骤。未运行的环境必须标注未验证。
