### 设置页反馈修正

本轮依据实际应用截图修正 2026-10-14 的设置布局，保留水墨背景和用户选定的字体。

- 小窗口压缩侧栏间距，内置入口和两项扩展入口在 960×600 附近能完整显示。隐藏侧栏及设置分组导航的滚动轨道，仍保留滚轮、方向键和分组导航按钮；主内容禁止产生横向滚动。
- 下拉框在显示前计算位置，挂载后用菜单实际内容高度校正方向。选中项只在菜单内部滚动，避免首次打开时改变页面位置；打开期间跟随窗口、滚动和字号变化，有限的入场动画期间跟随控件位置。关闭和卸载清理监听、ResizeObserver 和动画帧。
- 窗口宽高和首页轮播间隔使用 NumberField：圆角文本框、加减按钮、方向键、Enter 提交、整数验证及范围提示。窗口尺寸写入按顺序执行，丢弃过时的排队请求和回读，避免连续修改宽高后旧结果覆盖新值。
- 移除基本设置中的播放分区。倍速、连播、续播、画质与增强选项由播放器负责；既有播放器偏好不被清除。
- 数据与网络细分为详情缓存、后台补全和网络访问。缓存策略解释对应的 30 秒、90 秒和 10 分钟软过期时间；豆瓣补全间隔使用已有接口；内网访问开关从高级设置移到这一处，并保留已有默认值和后端行为。诊断入口只在对应面板可用时显示，读取失败可重试。
- 动画页提供轻柔、均衡、灵动三种风格，速度、位移缩放幅度，以及页面、弹层、反馈和错开入场的独立控制。预览分为页面、弹窗和卡片，可连续重播，使用有限的 CSS 动画，离开视图后移除预览。取消每秒读取时长的后台刷新。
- 动画配置存入 `ui_motion_options`，总开关仍沿用 `ui_motion`。校验所有读入字段，串行保存，失败回到最后成功保存的配置；只订阅一次插件可用状态和系统减少动态效果，作用域销毁时解除订阅。系统减少动态效果及关闭动画不会冻结加载提示。

修改前的浏览器回归复现了首次菜单没有贴住控件的问题，故障注入复现了旧窗口请求覆盖新尺寸，以及连续保存失败回退到未保存值的问题。新增断言验证实际位置、最终窗口尺寸和持久化配置。

验证：97 项前端回归通过；Vue 类型检查、生产构建、前端约定检查、Go vet 和 Go 全部测试通过；设置和播放器的真实组件浏览器回归通过。设置测试覆盖水墨主题、楷体、中英文、20px 字号、大小窗口、数字控件、迟到请求、偏好保存、连续预览、减少动效及开屏生命周期。浏览器绑定使用隔离模拟，不写用户的真实设置或数据库；原生 Windows 手感仍需打包体验。

预览截图位于 `dist/audit/settings-20261014/`：`ink-compact.png`、`motion-ink.png`、`data-ink.png`。

## docs/settings-layout-2026-10-14.md

<a id="origin-settings-layout-2026-10-14--设置布局窗口边缘与开屏优化"></a>

### 设置布局、窗口边缘与开屏优化

设置页改为页面式布局：宽窗口使用侧栏分组导航，窄窗口使用横向导航和左右滚动按钮。分组标签保持单行，支持方向键、Home、End，切换分组回到顶部，并保留已挂载面板的状态和主题编辑草稿。

基础设置拆成外观、窗口、首页、播放、数据与网络、维护六张卡片，提供快速定位入口。可用宽度足够时呈现两列；较窄时使用单列，控制项和自定义宽高允许换行。使用主题变量，保留语言、字号和字体偏好。

<a id="origin-settings-layout-2026-10-14--修复"></a>

#### 修复

- 原生窗口和后端尺寸设置统一使用 960×600 最小值，前端控件采用相同下限。旧版本保存的有效小尺寸在启动时修正并持久化；合法尺寸恢复时不额外写库。
- 窗口右侧和底部保留 6px 边缘，滚动条不再覆盖最外侧的调整尺寸区域。播放器全屏时移除这段边缘。
- 侧栏自身可以滚动，扩展包菜单增加后仍能找到底部入口。
- 基础设置并行读取初始值，初始化时不重写字体偏好。读取期间禁用表单，避免旧值覆盖刚修改的设置；组件卸载后的迟到结果不再修改全局字体。
- 默认字体有 CSS 兜底，清除自定义字体后继续使用系统字体。设置保存失败进入已有错误中心；窗口操作失败后重新读取实际状态。
- 分段控件使用等宽选项，修正标签长度不同导致选中背景错位的问题，并补充下拉框和输入项的可访问名称。
- 动画面板使用统一的视图活动状态，切走分组、隐藏窗口或 KeepAlive 停用时暂停刷新，并清理预览计时器。

<a id="origin-settings-layout-2026-10-14--动效与开屏"></a>

#### 动效与开屏

加入分组淡入、卡片依次出现、导航图标微移、按钮按压与分段选择滑动反馈。使用既有动效时长和开关；装饰动画遵守系统减少动态效果的偏好，没有新增装饰性无限动画或常驻动画循环。

开屏在主题恢复后选定一张图片，250ms 后仍未恢复则使用当前主题兜底，后续主题变化不会替换正在解码的图片。图片异步解码后淡入并轻微缩放，品牌文字使用主题文字色。成功显示后约 850ms 退出；加载或解码停滞时 2200ms 后开始退出。卸载和退出都会清理计时器、主题监听，迟到解码不会重新显示开屏。

<a id="origin-settings-layout-2026-10-14--验证"></a>

#### 验证

- 改动前复现了设置导航挤成多行、旧 800×500 尺寸恢复不符合新下限、隐藏动画面板继续每秒刷新的问题。
- `scripts/verify.ps1`：91 项前端测试、Vue 类型检查、Vite 构建、Go vet 和全部 Go 测试通过。后续导航按钮和窗口错误反馈调整完成后，再次通过前端约定检查、生产构建和窗口包测试。
- `scripts/test-settings-browser.py --channel chrome`：实际 Vue 设置页覆盖 960×600、1600×900、900×600 降级布局，20px 字体、中英文、深色主题、核心分组、设置保存与失败回读、分组保留状态、导航滚动、减少动效和隐藏面板刷新停止。覆盖开屏延迟解码、主题切换、解码中卸载，以及主题读取和解码停滞。
- 右侧边缘测试经过真实 Wails JavaScript 运行时，确认滚动区域外侧可发送 `wails:resize:e-resize`；全屏时内容重新贴合窗口。
- 播放器和诊断页面的浏览器回归通过，诊断页保持内部滚动，导出按钮没有被外层滚动挤出窗口。

浏览器检查采用隔离的绑定模拟，不操作用户正在运行的应用或数据库。原生 Windows 拖拽手感和实际冷启动流畅度仍需重新打包后观察；上述验证不能替代真实设备上的帧时间测量。

### 插件系统检查与修复（2026-10-13）

检查覆盖 Go 插件扫描/安装/启停/卸载、前端注册表、脚本注入、合作式权限与资源生命周期。工作没有修改用户实际插件目录、数据库或正在运行的软件；浏览器测试只替换 Wails API 边界，安装故障测试使用临时目录。

<a id="origin-plugin-audit-2026-10-13--已复现并修复"></a>

#### 已复现并修复

| 问题 | 复现结果 | 修复 |
| --- | --- | --- |
| 并发启停丢失状态 | 两个 SetEnabled 各自读同一本账，再分别覆盖保存；最终只留下一个禁用项 | 扫描、启停的读改写和目录发布/卸载共用操作锁；初次扫描使用锁内入口，避免重入死锁 |
| 状态读取失败仍覆盖保存 | 数据库读取失败被降级成空账本，下一次修改覆盖其他禁用记录 | 读取失败停止扫描/启停修改并返回明确错误，保留先前注册表。数据库未打开时的既有纯扫描行为仍由原有测试覆盖 |
| 更新失败删掉旧包备份 | 新目录发布和旧目录回滚都失败时，错误提示要求手动恢复 `previous`，但 defer 随后删除整个暂存目录 | 失败且仍有 previous 目录时保留暂存区，日志记录恢复路径；故障注入确认旧代码仍可读取 |
| 任意顺序停用留下方法包装 | A、B 包装同一方法后，先停 A 仍调用 A，最后停 B 会恢复已停用的 A | 单个分派器管理可移除的包装链；清理任意层，保持剩余层、this 和参数；不覆盖包外另行替换的方法 |
| Vue 监听和迟到资源残留 | dispose 后 watchEffect 仍运行，迟到 setup 能重新加入样式 | watch/watchEffect 登记到包生命周期；组件 scope 结束也解除登记，保留 pause/resume/stop；撤销函数幂等；已停用运行时拒绝新的样式、订阅、路由、包装和存储写入 |
| 初始化阻塞全局同步 | 一个 await 永远未完成的 setup 使停用操作一直等在全局队列后面 | 入队前取消已停用包的等待并回收其运行时；读包、import、setup 等待有 30 秒上限；取消不记为坏包，迟到 rejection 被原任务接住；迟到 setup 不能再登记资源 |
| 重扫和文件读取乱序 | 旧 ListPlugins 覆盖新 RescanPlugins；旧源码读回后重新污染已清空的缓存 | 注册表和文件缓存使用代次；只接纳当前响应，迟到文件结果不入缓存 |

| 权限重复确认/保存失败仍放行 | 并发同项能力出现两次确认；SetSetting 失败仍完成授权；JSON null 账本触发异常 | 队列内复查决定，合并同项确认；保存串行且成功后更新内存/放行；校验账本结构；停用运行时撤销权限身份，等待中的旧调用不再执行 |
| 卸载异常导致界面/运行时残留 | 文件已删除，信任清理失败时跳过注册表刷新，调用方也跳过脚本同步 | 文件删除后立即移除本地注册表并作废缓存，清掉该包的隔离记录；信任清理失败仍刷新并同步运行时，提示文件已删除及清理失败详情。撤销信任操作先停用和清理，再保存撤销结果 |

<a id="origin-plugin-audit-2026-10-13--信任和安全边界"></a>

#### 信任和安全边界

保持用户指定的规则：内置包由嵌入内容核验后免提示；新的外部脚本包只在显式启用时确认一次，正常更新和重启沿用包 ID 的信任；启动和重扫不弹信任窗口。没有将包 ID 或 builtin 标识直接当作内容可信证明。

现有路径、符号链接、体积上限、无效包隔离、安装及内置升级测试通过。本轮没有新增 shell 执行或扩大包文件读取范围。

脚本插件仍运行在应用的同一 JavaScript 环境。授权包装是合作式 API，不能限制用户已信任代码直接访问全局对象、导入远程代码或调用未包装的接口。30 秒超时终止的是等待，不会强行终止已经运行的 JavaScript；直接创建的定时器、外部连接、全局 DOM 修改仍应通过 `onDispose` 提供清理。持久化失败时的卸载警告也不意味着磁盘中的信任记录已成功删除。完整隔离需要不同的执行模型，不能由本次生命周期修复宣称实现。
