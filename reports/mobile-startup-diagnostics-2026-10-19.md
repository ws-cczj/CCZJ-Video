# 移动端开屏、播放反馈与诊断修复（2026-10-19）

本轮用户重新授权实际切换与查看 APP，范围为开屏图片过渡、加载 GIF、暂停图片及诊断修复。已更新常用预览包 `com.cczj.video.preview`，没有清除应用数据；模式切换观察后恢复为原来的 video 模式。保留共享工作区其他会话的改动。

## 开屏实际观察与修复

在 MuMu 当前 APP 进行文档重载录制，逐帧观察实际绘制，未用 Chrome 替身判断原生体验。

- 修改前：HTML 先显示一份 CCZJ 品牌占位，Vue 挂载后移除；Vue 开屏容器又从透明淡入。首次插入开屏图片时，容器 opacity 约 `1.8e-19`，底下的页面与开屏交错出现。图片本身存在渐变帧，但整个交接仍显得突然。
- 修改后：去掉 HTML 重复品牌，开屏容器从首帧保持不透明；图片解码后隔开两个 animation frame，再让图片与字幕单独淡入，最后整体淡出。保留原开屏素材及图片可见时长，遵守用户减少动画偏好。
- 主题在 Vue 挂载前恢复，避免先显示默认主题再换色。初始 HTML、WebView 和 Activity 使用可丢弃的启动底色缓存，主题的权威设置仍在 SQLite；未将用户数据迁回 localStorage。
- Android 系统启动图标继续透明，启动页退出不再叠加默认退出动画。浅启动背景对应深色状态栏图标，避免 Android 15 透明系统栏上的白字看不清。

最终录制第一次插入图片时容器 opacity 为 **1**、图片 opacity 为 **0**；之后捕获到 14 个图片中间透明度样本。这证明图片以渐变方式出现，不把中间帧数量当作性能提升比例。观察属于文档重载及模式切换；系统进程尚未启动前的 Android 启动窗口不由 Vue 控制，不宣称消灭所有设备上的系统启动阶段。

证据：[修改前](mobile-startup-diagnostics-2026-10-19/before-startup/observation.json)、[最终录制](mobile-startup-diagnostics-2026-10-19/delivery-startup/observation.json)。可重复观察入口：`scripts/observe-android-startup.py`，会重载已运行 APP，不清设置或数据库。

## 播放反馈

原因是此前移动适配明确将 `loading.gif` 换成圆环，并在模板和 CSS 两处隐藏了暂停图片。

- 移动端恢复既有 `loading.gif`，保留移动加载文字，使用适合小屏的尺寸。
- 暂停图片恢复为可操作的 56×56 按钮；暂停且没有加载时出现，锁屏时隐藏，点击继续播放。
- 在实际播放页观察到初始加载 GIF，媒体随后达到 readyState 4；双击实际视频后暂停图片可见，图片自然宽度 1024、按钮布局 56×56。

证据：[实际加载状态](mobile-startup-diagnostics-2026-10-19/actual-player-observation.json)、[实际暂停状态](mobile-startup-diagnostics-2026-10-19/actual-player-pause.json)、[暂停截图](mobile-startup-diagnostics-2026-10-19/actual-player-paused.png)。这些播放检查使用首个预览构建；最终构建中的播放器/GIF/暂停相关源码未再改变。

## 诊断新增了实际采集链路

| 内容 | 实现与口径 |
| --- | --- |
| 启动时间线 | 文档模块、运行环境/端样式、语言、动画偏好、内容模式、主题、Vue 挂载、首轮渲染机会、图片解码/显现/离开。无需提前开始录制，当前文档内有界保留 |
| Android 启动 | Activity、Go 初始化返回、WebView 导航、内容提交、加载完成。Go 阶段相对 Activity，页面耗时相对本次导航，重载不会被算成冷启动用了几分钟 |
| 浏览器资源 | 活跃播放器、资源观察器、附着 video/canvas、近似 JS 堆。明确 DOM 不包含离屏保留树，数值不相加，也不冒充 GPU 内存 |
| 阅读 | 分页、搜索、阅读数据加载，以及 SQLite 状态恢复/保存的次数、在途、成功、失败、取消、平均/最长耗时；保存失败时保留待保存数量。仅计当前文档实际发生的操作 |
| 取消与迟到 | 阅读组件作用域释放时取消其在途资源；观测只结算一次，迟到结果不会把取消计成成功或重新写回页面 |
| 下载 | 原生执行器执行量、接纳量、并发上限、接纳上限；暂停或完成历史不算占用中的执行名额 |
| 网络 | 用 Go `errors.Is/As` 区分主动取消与失败，单列超时（仍属于失败子集）；取消不覆盖最后真实失败原因 |
| 可用性与范围 | 展示已观测/尚无观测及各项范围；旧宿主缺失值显示未知，不填零；Android PSS/RSS 仍仅限宿主进程 |
| 入口与移动布局 | 小说和漫画设置均能打开共享诊断；移动标签单行滚动，新增表格独立拥有局部样式并可横向滚动 |

启动与业务数据也写入导出。为避免把新字段塞入接近上限的播放快照，增加独立的 `startup_snapshot` / `activity_snapshot` 事件，只在变化时写入。保留原来的 **8 KiB/事件** 限制，没有靠放大阈值处理问题。业务观测限制为 16 类，不持有 URL、作品内容、书籍身份或原始错误正文。状态读取失败也会标记录制观测不完整，继续录制而不打断播放。

- 最终 `scripts/verify.ps1`：退出 0，36 个前端测试文件 / **174 项测试**，32 个 Go app 包测试、go vet、类型检查和前端构建通过。新增测试覆盖取消后迟到结果、作用域关闭、网络取消分类、下载名额释放、启动数据校验、未开启录制时的启动保留，以及大播放快照不被新诊断字段撑破。
