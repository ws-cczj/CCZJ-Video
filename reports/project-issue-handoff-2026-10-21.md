## 尚未解决的问题

### R01 / P1 / B：漫画继续阅读以可变目录序号定位，未使用已保存章节身份

位置：`frontend/src/comic/state.ts:153–157`、`views/ComicSeries.vue:37–42`、`data/repository.ts:150–155`、`views/ComicReader.vue:81`；目录更新见 `app/db/library.go:375–377`。

进度保存了 episodeId、episodeRemoteId，但继续阅读链接使用 episodeOrd；加载时只找 ord 相等的章节，页码恢复也只比较 ord。数据库刷新允许同一 remote_id 更新 ord。源目录插入番外、重新排序后，旧序号可能对应另一话，旧页码还会套在另一话上。这是代码路径确认的风险，未改写设备目录制造用户数据事故。

建议：按来源身份和稳定章节身份解析进度，ord 仅作显式兼容兜底；章节消失显示恢复选择，不能静默跳到别话。

验收：在隔离测试库保存第二话中间页，再在第一话之前插入新话、刷新目录，继续阅读仍打开原第二话原位置；删除原话时有明确恢复提示。桌面/Android 使用同一判定。

### R02 / P1 / B：阅读结束、章节不可用和错误页仍有返回循环入口

位置：`frontend/src/novel/views/NovelReader.vue:208,217,219,220`；`frontend/src/comic/views/ComicReader.vue` 的 `comic-episode-end` 与最后的 `#actions`；`NovelShell.vue:13–15`、`ComicShell.vue:10`。

上一轮仅修复了阅读器顶部和沉浸态返回按钮。上述“返回书籍/作品”仍是普通 router-link，会把详情压到阅读器之后；详情返回直接 router.back，又进入阅读器。触发序列是详情 → 阅读结束或错误 → 返回详情 → 详情返回。代码仍能形成该循环，尚未在本轮加载最终章或制造断网复现。

验收：顶部、读完、空内容、下架、网络错误的退出行为一致；连续返回可到最初列表，不重新进入阅读器；深链无历史有合理兜底。

### R03 / P2 / A：小说从目录进入阅读后，返回重置为介绍页

复现：分类 →《校园修仙高手》→ 目录 → 第 1 章 → 阅读器返回。回到 `/novel/book/5` 后，“介绍”选中，“目录 1179”未选中，目录行数为 0。

证据：[51-novel-directory.json](mumu-hands-on-2026-10-20/51-novel-directory.json)、[52-directory-return.json](mumu-hands-on-2026-10-20/52-directory-return.json)、对应 PNG。

位置：`frontend/src/novel/views/NovelBook.vue:45` 的局部 `ref('intro')`。返回路由正确不等于返回原操作位置；目录已卸载，单纯恢复外层 scrollTop 不能恢复目录状态。

验收：从目录第几屏进入阅读，返回后目录 tab、滚动位置、当前章节保持；从介绍进入则返回介绍；刷新页面有清晰默认行为。

### R04 / P2 / A+B：长篇小说目录缺少有效定位入口

同一本书实际有 1179 章。详情目录只提供刷新，全部章节直接 v-for 输出，没有章节搜索、倒序、章节区间跳转或定位当前章入口。找最新章或后半本章节需要长距离滚动。

证据：51-novel-directory；位置 `NovelBook.vue:53–64`。确认了功能缺口和全量 DOM，**没有测得卡顿耗时，不声称已证明性能故障**。

验收：手机和桌面均能快速找到第 1000 章、最新章和当前章；为长目录选择适当渲染方案，测量后再决定虚拟化，避免仅凭行数机械重构。

### R05 / P2 / A+B：源库与已添加页对同一份健康记录给出不同状态

复现：小说源 → 源库，酷我/阅友/番茄均显示“检测已过期”；切到已添加，却显示“完整链路通过”，酷我/阅友为 100/100，没有时间信息。

证据：[53-source-current.json](mumu-hands-on-2026-10-20/53-source-current.json)、[54-installed-status.json](mumu-hands-on-2026-10-20/54-installed-status.json)、对应 PNG。

位置：`frontend/src/api/sourceCatalog.ts:41–45` 根据 checkedAt 判 24 小时过期；`LibrarySourcesPanel.vue:245` 直接展示 quality.status，不走同一判断。

建议：统一健康状态模型，区分适配支持、历史检测、当前失败；同时呈现检测时间及检测范围。不要用一次样本的 100 分暗示所有作品/章节可用。

验收：同源在两页展示一致的过期/失败状态；过期记录保留历史结果但不伪装实时健康；重新检测后同步更新。

### R06 / P2 / A+B：已适配源页面仍混入不兼容项，且作出过强可用承诺

复现：源库选择“已适配源”，说明写“共 3 个已适配源，点击添加即可使用”，下面却显示 4 个候选，包括“69书吧 / 暂不兼容”；其余三项检测已过期。摘要直接呈现 HTTP/HTTPS、779 章、5 段、字体编码等检测细节，手机首屏仅容下约一个完整源卡片。

证据：53-source-current。位置：`LibrarySourceCatalog.vue:39–40,111–121`；`locales/zh-CN.ts:1972`。

说明：混入候选的具体数量来自旧宿主返回的数据；当前前端确实不按该 tab 名称排除 incompatible，说明也仅统计 compatible，不检查检测新鲜度。

验收：普通用户首先看到可采取行动的源与准确状态；不兼容项放到明确的诊断/更多列表；检测细节默认展开方式按用户任务设计，不再把“存在适配器”说成“立即可用”。

### R07 / P2 / B：漫画空目录或来源不可用时，主阅读按钮仍可点击

位置：`frontend/src/comic/views/ComicSeries.vue:37–42` 与底部 `comic-detail-actions`。

没有进度且目录为空时 startPath 返回当前 seriesPath，主按钮仍写“开始阅读”，点击只是回到本页；来源不可用时追漫按钮禁用，但阅读按钮未按可读能力处理。默认第一话也没有排除 unavailable。小说详情已有 noReadableChapter 禁用分支，两个模式行为不一致。

验收：空目录、全部下架、第一话不可用、仅缓存可读等场景分别给可解释的动作；不能出现“开始阅读”实际无动作，也不能粗暴禁止仍可离线读取的内容。

### R08 / P2 / B：漫画上一话/下一话没有处理不可用章节

位置：`ComicReader.vue:112–117` 的 step，及上下话按钮条件。目录弹层会禁用 unavailable 章节，但顺序翻话只取相邻条目。遇到保留的下架章节时仍跳转，随后请求失败，连续阅读中断。

验收：可用 A → 下架 B → 可用 C 的目录中，上下话有明确策略（提示并可跳过，或有解释的恢复入口），与目录禁用状态一致，且不会丢失 A 的进度。

### R09 / P2 / C+B：漫画列表序号冒充真实话号

《DARK MOON: 月之神坛》目录共 7 项，第七项源标题“71. 特别篇”，UI 同时显示“第 7 话”。位置 `ComicSeries.vue` 和 `ComicReader.vue` 都用 chapter.ord + 1 生成 episodeNumber。

证据：上一轮 35–40 及 [实机报告](mumu-hands-on-2026-10-21.md)。应区分“第几个列表项”和“源章节标题/话号”，不要重编号造成误读。**是否少了 64 话尚未核实，不能据此认定目录丢失或绕过付费限制。**

验收：番外、缺号、分卷、免费可见子集均保留真实标题语义；目录覆盖另行核查分页和源站可见规则。

### R10 / P2 / C+B：首页命名与实际能力不一致，小说漫画没有各自清晰的发现流程

小说“书城”主要是继续阅读和书架空状态；漫画“发现”展示本地搜索入库内容。用户容易把个人历史/缓存当作源站书城。入口不应只靠两套颜色和不同名词区分。

位置：`frontend/src/novel/views/NovelHome.vue`、`frontend/src/comic/views/ComicHome.vue:18` 调用本地 listComicLibrary；证据见前报告 02、18、34。当前前端首页尚需逐项复验。

整改应明确小说的找书、目录、文字阅读和漫画的追更、话列表、图片阅读任务；如果暂无发现能力，应准确命名已有内容，不能用假榜单或静态占位伪装功能。

### R11 / P2 / C：漫画无源提示出现太晚

原包无源时给出普通搜索和筛选，提交“one”后才告诉用户需要源。用户已花了无效操作成本。旧“管理漫画源”跳到设置的绕路已修，不代表前置引导已修。

证据：18–23；相关入口 `frontend/src/comic/views/ComicCatalog.vue`。当前设备已有一个源，本轮未为复现删除用户源。用隔离测试数据覆盖无源、全停用和源加载失败，不要混成同一状态。

### R12 / P2 / A：设置仍包含大量与当前阅读任务无关的实现说明

网络策略已移至下方，但页面仍展示后端中间件、弹幕冷却、跨重启保留等技术说明。小说设置里的弹幕策略与用户阅读偏好没有直接关系，移位置没有解决信息架构。

证据：50-current.json；位置 `frontend/src/components/NetworkPolicyPanel.vue`，小说/漫画 Settings。

验收：常规阅读偏好和源管理可直接找到；诊断细节只在相应入口展示，保留必要错误原因，不以删除所有错误信息代替设计。

### R13 / P2 / B：Android JS 桥线程池无上限，异步回调缺少宿主销毁约束

位置：`build/android/app/src/main/java/com/wails/app/WailsJSBridge.java:21,83,163`；`MainActivity.java:1038–1047`。

static newCachedThreadPool 可随并发调用增长线程；任务完成后持有 webView 并 post/evaluateJavascript。MainActivity 销毁 WebView 的路径中没有与该静态执行器相配套的任务所有权/取消/排空约束。这里的 bridge.shutdown() 不能直接认作 WailsJSBridge executor 的关闭，需要沿实际类型核对。

这是代码风险，未复现线程耗尽或崩溃。建议给后台工作明确边界、拒绝/排队策略、销毁后回调拦截；取消等待不能阻塞 Android UI 线程。

验收：压力测试峰值线程受控；Activity 重建期间迟到回调不访问销毁 WebView；退出不会遗留引用或造成请求永久悬挂。
