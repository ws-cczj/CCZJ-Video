# 阅读源质量匹配程序：首版复测

日期：2026-10-21。程序和[使用说明](../docs/reading-source-quality-benchmark.md)已完成；本次以独立临时 SQLite 实测，没有导入来源、修改用户开关或保存到实际应用数据目录。

本版把覆盖面、作品身份、目录与可读范围分开。搜不到一部作品不扣内容质量；标题近似、原著与改编、续作不自动混成一部。判缺章不能只看最大编号，需要同版目录锚点，无法确定时保留未知。

基准含平台推荐/榜单、经典、类型代表和已知可读校准，不是全网热度排名。逐作品依据、官方目录口径与版本陷阱见[第一方调查](reading-quality-benchmark-research-2026-10-21.md)。本轮通用基准的 `corpusHash` 为 `f5baffd43449a9cb9d626dd9249fbf74120d98bd16a3af40dac1824ec6ba44e1`（JSON 内容重新编码后的哈希，不同于原文件字节哈希）。

## 用真实故障校准规则

初次运行对酷我《庆余年》的某些标题跨越比较，造成过强的乱序/跳号判断。已修正：不跨越未识别标题推断编号相邻，卷标题和编号单位变化会断开比较；没有卷信息时的混合回退只待核查，连续整体倒序仍能识别。补回归用例后重新运行了上面的通用来源检查，表中是修正后的分数。

重复正文用例最初还暴露“证据上限把不同原始分压成同分”的问题，已改为证据系数相乘，保留缺陷对分数的影响，回归验证同一套样本中的重复正文源排在正常源之后。

另用前轮曾发现推广行的《三国醉三国》建立了单独的负向对照集。本次泡书吧详情规则缺标题，目录又超时，未进入正文；故此次没有获得新的在线广告检查结论。[对照结果](source-quality/promotion-control-2026-10-21.json)与通用基准哈希不同，没有混在通用排名中。推广词识别用前轮实际发现的“最新网址＋域名”等形态作回归，且验证普通剧情对白、短完结说明不误报。

漫画当前检验实际图片格式和完整像素解码，非只测 HTTP 200。测试还验证伪图片 HTML、仅有图片头的截断文件会失败，Referer 与声明头保留，登录限制单独分类。尚未做 OCR、广告视觉识别或人工逐页对照，不能标“漫画无广告”或“全部页序正确”。

## 排序与后续复用

CLI 可对社区库、外部 JSON 或集合 URL 使用同一份基准运行；不能执行的适配明确列为跳过，不给假分数。可使用 `--works` 做单项回归，或扩充版本化基准进行新源检测。报告包含规则版本、样本集哈希、时间、每项证据。

应用已有质量排序已支持显式保存的深度摘要：有足够证据的基准检查优先于旧首章检查，陈旧记录降为过期。实际设备本次没有应用这些摘要；当前深检入口是命令行，不包含新 UI 按钮或自动后台扫描。没有制作新的主应用 APK/EXE。
