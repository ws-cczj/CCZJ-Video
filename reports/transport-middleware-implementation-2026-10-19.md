2026-10-19。根据 transport-middleware-audit-2026-10-19.md 实施，保留其他会话修改。此次不打包、不做设备操作验收。

## 已落地

1. **请求生命周期与操作观察**：复用 operation.Run，增加模式归属与资源登记；接入阅读资源、阅读状态、视频详情/线路测速、弹幕、评论、源导入。模式切换与退出控制保留独立所有权。
2. **评论取消完整链路**：Wails context → 共享读取等待 → 限速等待 → 验证题计算 → HTTP。共享读取使用 workflight，最后一个读取者离开才取消上游；过期刷新由模式任务组启动，应用关闭时在关库前等待读取完成。取消不记失败、不设置 30 分钟失败退避、不打印 HTTP 失败日志。
3. **数据校验**：前端 response/decode 公共模块接入阅读、详情及缓存、评论、弹幕；保留既有字段、来源身份与空集合兼容。业务字段语义仍由对应解码器负责。
4. **有界解压与导入**：文件和 Base64 源导入共用容量、格式识别和完整 JSON 校验；备份共用解压机制；详情缓存增加 16 MiB 解压上限。已有字节输入和未压缩内容不重复复制。原有导入合并事务和用户数据保留规则不变。
5. **设置保存**：公共队列按顺序写入，合并尚未保存的同键修改，失败保留最新内容；主题提供错误反馈和明确重试，编辑器仅在保存成功后关闭。后端设置持久化与运行时应用按顺序执行。
6. **事件处理**：已知事件在适配层校验；进度在一帧内按身份合并，终态即时交付，解除订阅取消排程。调用方可以追加身份过滤和自定义解码。
7. **诊断**：新增当前模式后端操作成功/失败/取消及耗时；前端使用固定操作集合聚合 IPC 读取/解码；新增事件收到、格式无效、合并及过滤计数。运行记录/导出沿用现有 runtime 或 activity 快照携带新增字段。

## 已确认的行为变化

- 修复前已运行 `go test ./app/service -run '^TestDetailDecompressionRejectsOversizedOutput$'`，用 16 MiB+1 的可压缩输入触发现有解压路径，失败信息为 `oversized cache must fail explicitly: <nil>`。修改后此用例通过并返回 VALIDATION。
- 评论取消用例等待实际替身 HTTP 启动，再取消；确认调用与 HTTP 都停止、共享工作归零且没有新增失败退避。
- 模式请求用例确认任务组停止会等待请求释放，关闭后的新调用不执行处理函数。
- 三次同键编辑中第一次写入在途时，后两次合并为最新值，实际保存 `first` 和 `latest` 两次。失败写入保留，明确重试后清空。
- 同身份两次进度在一次排程内只交付最新值；终态不会留到下一帧，解除订阅后不交付旧进度。
- 返回字段错误被公共流程归为 CORRUPT；取消仍保留运行时 CancelError，观察计数只结算一次。

这些是确定性的行为证据，不是手机/桌面性能跑分。

## 覆盖边界与后续观察

公共模块和主要数据链路已接入，不能把 190 个生成方法都算作已迁移：宿主窗口、日志、模式切换、后台任务控制以及尚未迁移的旧同步接口继续使用已有适配。未知扩展事件需要调用方声明解码器；业务缓存、来源协议、事务、分页续传和具体重试不强行全局化。

正常请求频率没有调整，弹幕相同请求的既有五分钟以上随机冷却继续由 netpolicy 负责。没有为写操作增加统一自动重试或取消后重放。

用户实际操作后的诊断应分别比较：前端调用耗时与取消计数、后端操作耗时与结果、真实出站与复用/拦截、事件合并/格式错误计数。未采样前不报告毫秒、内存或百分比收益；出现事件格式错误时根据对应业务契约排查，不能将数据丢弃数冒充优化收益。
