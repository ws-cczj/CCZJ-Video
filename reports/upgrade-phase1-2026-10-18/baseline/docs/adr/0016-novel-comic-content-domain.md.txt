# ADR 0016: Novel and comic content domain

## Status

Accepted, 2026-10-18. Extends [ADR 0014](0014-application-mode-strategies.md), which
named `NovelRepository` / `ComicRepository` as the adapter seam and left the network
implementation open. Evidence for every parameter chosen here is in
`reports/06_提取层能力清单与实现参数.md`.

## Decision

### Sources share one table, distinguished by `kind`

`sources` gains `kind TEXT NOT NULL DEFAULT 'video'` (migration v11, via
`addColumnIfMissing`). Novel and comic sources are rows in the same table with the
same health sampling (`source_health`), the same auto-disable-after-3-failures guard
(`app/handler/source_guard.go`), and the same `strategy_config` column carrying their
declarative document. No second source registry.

Adding a column is the exact shape of migration v10 (`auto_disabled_at`) that produced
the "old exe reads new database" incident in `docs/pending-decisions.md` item 10. That
path is now covered by `applySchemaAhead`, which switches the connection to
`database.Unsafe()` when `PRAGMA user_version` exceeds `LatestSchemaVersion()`, so an
older build degrades to ignoring the column instead of failing every `SELECT *`.

### Items are per-source; there is no cross-source identity

Video mode normalizes across sources into `global_video` because playback needs to
switch lines mid-episode and keep the position. Reading has no equivalent need: a book
on the shelf comes from one source, and merging two same-titled books would merge two
different translations, editions or scanlation groups. `reports/00:107` states this
directly. So `library_items` and `library_chapters` are keyed by source, with no
`name_norm` column and no dedupe pass.

```sql
CREATE TABLE library_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT NOT NULL,                    -- novel | comic
  source_key TEXT NOT NULL,
  remote_id TEXT NOT NULL,               -- normalized domain-stripped path
  title TEXT NOT NULL DEFAULT '',
  author TEXT NOT NULL DEFAULT '',
  cover TEXT NOT NULL DEFAULT '',
  summary TEXT NOT NULL DEFAULT '',
  genres TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT '',
  latest TEXT NOT NULL DEFAULT '',
  words TEXT NOT NULL DEFAULT '',
  remote_updated_at TEXT NOT NULL DEFAULT '',
  lifecycle_state TEXT NOT NULL DEFAULT 'active',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(kind, source_key, remote_id)
);

CREATE TABLE library_chapters (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id INTEGER NOT NULL,
  remote_id TEXT NOT NULL,
  title TEXT NOT NULL DEFAULT '',
  ord INTEGER NOT NULL DEFAULT 0,
  volume TEXT NOT NULL DEFAULT '',
  is_volume INTEGER NOT NULL DEFAULT 0,
  access TEXT NOT NULL DEFAULT 'unknown',   -- available|login|subscription|unknown
  remote_uploaded_at TEXT NOT NULL DEFAULT '',
  lifecycle_state TEXT NOT NULL DEFAULT 'active',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(item_id, remote_id)
);
```

`remote_id` is the normalized domain-stripped path, which is what Mihon matches on
(`SyncChaptersWithSource.kt:105-109` matches on URL and nothing else). Normalization
goes one step further than Mihon's `setUrlWithoutDomain`: the fragment is dropped and
query keys are sorted, so a source that appends a rotating signature parameter does not
turn every chapter into a new one.

Chapters a source stops returning are **soft-deleted** through `lifecycle_state`,
following the `source_videos` precedent. Mihon hard-deletes them
(`SyncChaptersWithSource.kt:223-227` → `removeChaptersWithIds`), which would discard
downloaded content; `reports/00:109` requires the opposite.

`ord` is computed here, not copied from the remote list index. Mihon's `sourceOrder` is
the remote index and its code comments that sources "MUST return the chapters from most
to less recent" with no detection of the opposite (`SyncChaptersWithSource.kt:195-196`).
Our sources declare their direction explicitly in the source document, and `ord` is
assigned after applying it.

### Content is a discriminated union and never inferred from a string

Legado's `WebBook.getContentAwait` returns the chapter URL as the content when a source
declares no content rule (`WebBook.kt:306-309`), and nothing downstream distinguishes
that from real prose — `CacheBook.kt:381-393` stores it as text. `reports/00:100` names
this as the thing to avoid. Our `Content` carries a mandatory `kind` (`text`, `images`,
`external`) and a reader only accepts the kind it renders.

### Chapter text and comic page lists are caches, not domain data

Neither gets a table. Both go to an on-disk blob store generalised from
`app/proxy/imagestore.go` (sha256 key, mtime-LRU, write-to-temp-then-rename, failure
cooldown), keyed by `source_key + provider_version + item_remote_id + chapter_remote_id`
per `reports/00:104`. Including the provider version means editing a source's extraction
rules invalidates its cached text instead of serving prose parsed by the old rule.

An empty result is never cached. Legado raises `ContentEmptyException` after the chapter
title has already been written to the database and not rolled back
(`BookContent.kt:66-78,149-151`); we keep the same split — metadata may persist, content
may not — but the failure is reported rather than cached as blank.

### Extraction is structured configuration, not a rule string


Legado needs a 14 KB quote- and bracket-aware splitter (`RuleAnalyzer.kt:91-298`)
because it flattens several syntaxes into one string where `&&`, `||`, `@` and `##` can
also legally appear inside a CSS attribute selector, a JSONPath filter or a regex. Our
document is structured JSON: combination and fallback are arrays, a selector is one
opaque string value, and the serializer handles escaping. There is no splitter and no
escape grammar. The one constraint carried over is that a selector string may contain
quotes, brackets and `@`, so nothing may split on those characters.

The JSON side extends the existing bounded dotted-path walker in
`app/collect/response.go` (`lookupPath`, 512-byte / 64-segment caps, typed
`ErrPathSyntax` / `ErrPathNotFound` / `ErrPathType`, `UseNumber()` so a 20-digit remote id
survives as text) with array iteration. **No JSONPath library is added.** Only the HTML
side needs new dependencies: an HTML parser with CSS selector support, and
`golang.org/x/text/encoding` for GBK/GB18030/Big5.

Response decoding follows Legado's verified chain — HTTP `Content-Type` charset, then
`<meta charset>` / `<meta http-equiv>`, then fallback — with one addition Legado lacks:
an explicit `encoding` declared on the source. Legado's URL option `charset` does not
participate in response decoding at all, only in request parameter encoding
(`AnalyzeUrl.kt:242,287-298`), so a GBK site works there purely by detection. Our sources
are added by the user through a form, so offering the override is natural.

JS evaluation and WebView rendering are not implemented. The capabilities this forfeits
are enumerated in `reports/06` §2.2; a source document that declares one of those fields
is **rejected at import with a named reason**, never silently treated as an empty result
(`reports/02:135`).

### Bounds Legado does not have

Legado's content and table-of-contents pagination loops have **no numeric limit** —
grepping `maxPage|MAX_PAGE|maxChapter|contentLimit` under `model/webBook/` returns
nothing; termination relies on URL deduplication and on breaking when the next URL equals
the next chapter's (`BookContent.kt:83-110`). Its dedupe set is an `ArrayList.contains`
over raw, un-normalized URL strings. `reports/00:98` requires both bounds, so:

| Bound | Value |
|---|---|
| Table-of-contents pages followed | 50 |
| Chapter content pages followed | 20 |
| Chapter content size | 4 MiB |
| Pagination dedupe | set of normalized URLs |
| Next-chapter exclusion | absolute + fragment-stripped + path compared, not raw string equality |
| Concurrent page fetch, ordered merge | 4 (Legado's `threadCount` defaults to 16) |

The concurrent-fetch-with-ordered-merge pattern is adopted: Legado fetches in parallel
and awaits in emission order through a `channelFlow` with `.buffer(0)`, so completion may
be out of order but output is not (`FlowExtensions.kt:110-127`).

### Comic pages use Mihon's five states

`Queue → LoadPage → DownloadImage → Ready`, any state to `Error(e)` on a non-cancellation
failure, and **any state back to `Queue` on cancellation** (`Page.kt:51-57`,
`HttpPageLoader.kt:71-78,227-257`). Cancellation is retryable and is not an error.

Image bytes are validated **before** being cached. Mihon writes whatever comes back and
marks the page `Ready`, defaulting an unrecognised MIME to `"jpg"`
(`ChapterCache.kt:157-191`, `ImageUtil.kt:68-71`), so an HTML error page becomes a
cached image and the failure surfaces only at decode time in the viewer. We check
Content-Type and magic bytes first; a page that fails never enters the cache. This is the
same instinct as the video collector's non-JSON precheck (`app/collect/fetcher.go:268-276`).

### Images get their own proxy route

`/__cczj/img` is added beside `/__cczj/hls` in the asset middleware rather than extending
it. `hls.go` rewrites segment URLs inside playlists and suppresses `Range` for `.m3u8`;
neither belongs in an image path. What images need is the full `Referer` — `RefererOrigin`
(`hls.go:110-116`) truncates to `scheme://host/`, and `reports/03:97` requires source
headers to survive to the actual resource request — plus a named header set, which
`hls.go:213-221` cannot express. The new route reuses `safeDialContext`, `ValidateTarget`
and `netstats`.

Whether real comic CDNs need the full path in `Referer` or accept the origin is **not
established**: Mihon's core injects no `Referer` at all (`HttpSource.kt:107-109` sets only
a User-Agent; `core/common/network` has zero `Referer` hits), so all evidence lives in
extensions, which were not in the delivered archive. This is the open item in
`reports/05` task C. The full-Referer route is built regardless, since it is a superset.

### Progress and shelf stay in browser storage this round

ADR 0014 put novel and comic shelf, progress and preferences in versioned
`platform/storage.ts` keys, and ADR 0005 assigns browser persistence to that module. The
keys move to `v2` with `{providerId, remoteId}` composite keys, and the current behaviour
of silently dropping an id the repository cannot resolve becomes "keep the entry, mark the
source unavailable". Whether reading progress should instead live in SQLite next to
`favorites` and `watch_history` is recorded separately in `docs/pending-decisions.md`
rather than decided here.

### One package, not two

Novel and comic live in a single `app/library` package rather than the
`app/novel` + `app/comic` pair this decision originally named. They share the
source table, the item/chapter tables, the document format and the whole
search → detail → contents path; only the last step forks (text versus a page
list with two-step image resolution). Two packages would duplicate that shared
path and then drift.

### Amendments found while implementing

- **Legado's third combinator was dropped.** `%%` interleaves two selections by
  index. It has no coherent placement in a structured format: at list position
  it yields `[title0, link0, title1, link1, …]`, and each list entry must be able
  to supply every field on its own, so the result is a pile of half-entries; at
  value position only the first result is ever read. What the parallel-list
  source shape actually needs is *pairing*, not interleaving, and there is no
  frequency evidence that it is needed at all (`reports/05` task A). Adding it
  back later is a new field, not a breaking change.
- **Concat joins at value level.** At node position it appends lists; at value
  position it joins the child results into one string with an optional
  separator. The second behaviour is the one real sources need — `<span class="num">`
  plus `<span class="name">` has to become one title, not two values of which
  only the first is read.
- **A selector may declare only `attr`.** That means "take the current node",
  which is what a `text` rule wants once `root` has already narrowed the scope.
- **Test-stage names are stable identifiers, not display text.** `TestStage.Name`
  carries `config` / `search` / `detail` / `toc` / `content` / `pages`; the
  frontend translates them. Chinese literals in Go cannot be localized, and
  English literals would be inconsistent with every other Go-side message.

## Consequences

- One source registry, one health/auto-disable mechanism, one declarative document shape
  for all three modes. A novel source and a video source differ by `kind` and by which
  operations their document declares, not by which subsystem owns them.
- No cross-source dedupe means the same book added from two sources is two shelf entries
  with two progress records. That is the intended behaviour, not a bug to fix later.
- Chapter identity survives a domain change but not a path change. A source that rewrites
  its URL paths will orphan reading progress; the fallback is chapter-number inheritance
  plus normalized-title matching, both of which must fail before an entry is treated as new.
- Extracting from HTML adds the project's first parsing dependencies. They are bounded to
  the provider package and must not leak into `app/service` or the UI.
- Rejecting unsupported fields at import means a source written for a richer engine fails
  loudly with a reason instead of returning empty lists. This is deliberate: an empty list
  must only ever mean "one successful query found nothing" (`reports/00:135`).
- Font-codepoint obfuscation (`reports/06` §6) is not decrypted. Sources using it produce
  text that renders as plausible Chinese and reads as nonsense. Detection and an explicit
  "this source uses font obfuscation, which is not supported" diagnostic is in scope;
  decryption is not.
