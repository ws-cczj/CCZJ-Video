# 弹幕并行匹配与交接资料核对

2026-10-19。范围：最多三个内置源并行匹配、默认源优先、按单集与来源保存一天失败冷却，并利用已有交接包元数据消歧。保留共享工作区其他会话改动。本轮未打包 EXE/APK、未操作模拟器或用户数据库、未访问弹幕源站验证当前可用性。

这些资料足以改善现有搜索与目录链路，没有提供可靠的一步通用片名→各平台弹幕 ID 映射。自动匹配不选择搜索首项，不按目录数组位置猜集号，不把搜索热度或作品级弹幕总量当作当前单集有内容的证据。

## 实现行为

1. `DanmakuMatch` 接收本地单集身份、名称、年份、类型、集标识、时长和当前播放位置。前端 API 做运行时解码，视图通过 API 适配层使用生成绑定。
2. 最多探测三个已启用来源。单来源内部依次执行搜索、作品消歧、目录、声明集号校验、索引与当前分段读取；服务级匹配管线最多三个，HTTP 弹幕通道上限也为三个。全局/单主机预算和播放预留不变。
3. 决策顺序为默认源，然后按 B站、腾讯、爱奇艺内置顺序补齐其余来源。回退源先完成也不能抢占未完成的默认源。确定可用赢家后取消并等待不需要的探测，只保存一家绑定与一家时间窗。每个来源探测超时 12 秒。
4. 名称保留季数，处理全半角、标点、空白及有限质量标记。已知年份冲突、已知类型冲突、时长差异超过 60 秒或 10% 的较大者时拒绝；同分同名作品、重复集号、预告/剪辑等不能自动消歧时不绑定。区域剧种如国产剧归一为电视剧；未知类型不凭空推断。
5. 无作品/单集匹配、空池、缺段及远端错误记录逐单集逐源 24 小时冷却。v17 有序迁移建立 `danmaku_match_failures`，跨服务重启继续跳过失败源。元数据指纹变化可重新评估。取消、停用及本地存储异常不写成来源失败。冷却表清理过期条目并限制为 50000 行，达到容量会明确反馈存储异常。
6. 有效索引中当前时间窗没有条目，不能推导整集无弹幕；这种情况仍可使用该源。没有有效池时回退，全部不可用时前端不挂载弹幕画布。后续缺段或读取失败重新评估来源。
7. 匹配结果直接携带首个时间窗，前端不重复读取。年份等迟到元数据改变时取消旧匹配并拒绝迟到响应，切集/退出也释放请求。开关重新启用不会先额外读取旧绑定窗口。既有偏移仅在仍是同一个远端单集时保留。
8. 作品、目录、索引和分段继续复用持久缓存及在途合并。修复元数据后搜索/目录采用 discovery-v2 缓存身份，避免旧的缺字段缓存继续命中。原有共享中间件的随机请求间隔保持生效，一天失败冷却是额外的结果策略；未改变采集、阅读、图片、下载等原有请求节奏。

播放器只保留显示控制与只读“自动匹配记录”，展示当前来源、当前片段条数、各源状态和冷却期限，不提供手动搜索、选源或选集流程。独立源管理仍允许启停、设置默认来源。视频模式诊断新增 `match_runs/fallbacks/cooldown_hits`；失败表也仅归视频业务诊断范围。

播放准备原有顺序与超时保持：配件、弹幕就绪或终态之后准备播放；弹幕可选等待最多 2.5 秒，避免远端接口让视频启动无限等待。超时后的弹幕工作仍归当前会话，结果可稍后显示，退出则取消。

## 本次回归中修复的问题

- 爱奇艺年份和类型读取错误：先用交接样本断言捕获 year、kind 都为空，再修复解析并通过。
- 匹配中迟到的年份更新未触发重新评估：先补回归得到只调用一次的失败结果，再修复取消和身份检查。
- 自动匹配与旧手动 provider watcher 相互取消：仅兼容分支保留该 watcher 的取消职责。
- 共用请求中间件把首次资源登记推迟到微任务，可能遗漏已经发出的立即取消请求。现在先登记活跃绑定，保留同步异常归一与后续 await 的取消保护。原有小说/漫画 transport 取消断言通过。
- 补齐旧测试对 storage、Wails runtime 的部分模拟；保留原有功能断言，更新下载进度测试按实际合并调度投递后验证。
