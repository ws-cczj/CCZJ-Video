# 腾讯视频、爱奇艺弹幕接口与剧名绑定：开发交接

核验日期：2026-10-18。本文补充上一份 B 站弹幕分析，供聚合播放器开发使用。

**两家都已找到可用的弹幕读取链，并完成样例请求和解析。** 腾讯视频使用单集 `vid` 获取 JSON 索引和 JSON 分段；爱奇艺使用数字 `TVid` 获取按 60 秒组织的 Brotli 文件，当前实测内容为 Protobuf。剧名搜索只能找到候选作品，最终必须绑定到具体季、集和版本。

这里研究的是公开客户端协议和开源适配器，**不是平台承诺兼容的官方开放 API**。本文的证据来自固定版本源码及本机公开 HTTP 请求；没有腾讯视频、爱奇艺 APK 分析或登录后抓包证据。实测没有发送登录 Cookie、会员凭证，也没有请求视频媒体。公开弹幕可读不代表视频可播放，也不保证任意作品或完整历史弹幕都能取得。

## 2. 实测结果及证据边界

共进行 15 次 HTTP 请求，其中 13 次 HTTP 200、2 次 HTTP 404。成功样例每个平台只读取两段弹幕，没有拉取整集或全库。

| 平台与样例 | 请求/解析结果 | 时间范围 |
| --- | --- | --- |
| 腾讯《兰香如故》第 1 集，`vid=c4102g9a01t` | 第 1 段 600 条 | 0–29000 毫秒 |
| 同上 | 第 2 段 600 条 | 30000–59000 毫秒 |
| 爱奇艺《狂飙》第 1 集，`TVid=3493131456125200` | 第 1 段 366 条，37325 字节 Brotli → 141616 字节 Protobuf | 1–60 秒 |
| 同上 | 第 2 段 399 条，41808 字节 Brotli → 155822 字节 Protobuf | 61–120 秒 |

四段解析均无解析器警告。腾讯两段合计 1200 条、爱奇艺两段合计 765 条，是本次返回量，不能推断为平台全部弹幕。

爱奇艺另一个数字 `TVid=2176777301438100` 的基础信息请求成功、`displayBarrage=true`，但本次请求其 `.br` 第一段及旧 `.z` 第一段均得到 404。因此不能因为“元数据里开了弹幕”就保证所有文件存在，也不能以单段 404 断定整集没有弹幕。

两个成功样例属于**不同作品**，仅用于验证各自平台，不能互相作为同一影片的备用弹幕源。

## 3. ID：哪些值能交给弹幕接口

| 平台 | 作品/专辑标识 | 最终单集弹幕标识 | 常见误用 |
| --- | --- | --- | --- |
| 腾讯视频 | 搜索结果 `doc.id`，通常作为封面/作品 `cid` | 分集结果 `item_params.vid` | 把腾讯作品 `cid` 或 B 站 `cid` 当作腾讯 `vid` |
| 爱奇艺 | 专辑 `albumId` / 专辑 `qipuId` | 数字 `TVid`，例如 `3493131456125200` | 使用 `v_xkt6z3z798.html` 的短字符串，或 32 位十六进制媒体 `vid` |
| B 站 | `bvid` / `aid`、番剧 `season_id` 等 | 弹幕池 `cid` | 将它和腾讯同名 `cid` 互换 |

爱奇艺 `qipuId` 的含义取决于对象层级：`albumInfo.qipuId` 可能是专辑，而 `albumInfo.videos[i].qipuId` 是该单集。不要仅凭字段名判断。

内部数据库统一以字符串保存所有远端 ID。腾讯实测弹幕 ID 为 17 位数字字符串，爱奇艺实测弹幕 ID 为 19 位数字字符串；JavaScript `Number` 无法精确保存这些 ID。爱奇艺某些 JSON 元数据会把数字 ID 作为 JSON number 返回，应在解析时保留原始整数精度，再转换为字符串。Python 的 `json.loads` 整数没有此精度问题；JavaScript 需要支持大整数的 JSON 解析方式，不能先精度丢失再 `String()`。

## 4. 腾讯视频：剧名 → 作品 CID → 单集 VID

### 4.1 搜索作品

```http
POST https://pbaccess.video.qq.com/trpc.videosearch.mobile_search.MultiTerminalSearch/MbSearch?vplatform=2
Content-Type: application/json
Origin: https://v.qq.com
Referer: https://v.qq.com/
```

实际成功使用的 JSON 请求体如下，关键词可替换。示例中的 `uuid` 是本研究的普通客户端标记，没有复制开源源码中硬编码的 Cookie 或其他标记头。

```json
{
  "version": "25071701",
  "clientType": 1,
  "filterValue": "",
  "uuid": "protocol-study-local",
  "query": "兰香如故",
  "retry": 0,
  "pagenum": 0,
  "isPrefetch": true,
  "pagesize": 10,
  "queryFrom": 0,
  "searchDatakey": "",
  "transInfo": "",
  "isneedQc": true,
  "preQid": "",
  "adClientInfo": "",
  "extraInfo": {
    "multi_terminal_pc": "1",
    "themeType": "1",
    "sugRelatedIds": "{}",
    "appVersion": ""
  }
}
```

| 字段 | 类型/含义 | 接入要点 |
| --- | --- | --- |
| `query` | string，搜索词 | 先搜索作品名，再匹配年份、季和正片 |
| `pagenum` / `pagesize` | integer | 本次从 0 页开始、请求 10 条；不保证返回所有栏目合计恰好 10 条 |
| `version` / `clientType` | string / integer | 客户端协议参数，不是接口版本兼容承诺 |
| `isPrefetch` / `isneedQc` | boolean | 保持 JSON boolean，不要转成字符串 |
| `extraInfo.sugRelatedIds` | string | 值是字符串 `"{}"`，不是 JSON 对象 |
| 其余空字符串字段 | string | 完整模板已经给出；本次未验证删除它们是否仍可用 |

响应根为 JSON，先验证 `ret === 0`，再处理 `data`。实际主结果路径：

```text
data.normalList.itemList[]
  .doc.id                         → 作品 CID
  .videoInfo.title                → 名称，可能带 <em> 高亮
  .videoInfo.year / typeName      → 年份、内容类型
  .videoInfo.playSites[]          → 平台，enName="qq" 才是腾讯站内候选
  .videoInfo.episodeSites[]       → 另一处播放/分集来源
```

开源适配器还兼容 `data.areaBoxList[]` 中 `boxId="MainNeed"` 的 `itemList`。本次实际主结果在 `normalList`，相关推荐在其他 `areaBoxList`。栏目中也实际出现 `videoInfo=null` 的条目，应先判类型再访问。不要将所有相关推荐当成名称匹配结果。

下例是实际响应的字段摘录，省略了其他字段和条目：

```json
{
  "ret": 0,
  "msg": "",
  "data": {
    "normalList": {
      "itemList": [{
        "doc": {"id": "mzc00200803dr6b"},
        "videoInfo": {
          "title": "兰香如故",
          "year": 2026,
          "typeName": "电视剧",
          "playSites": [{"enName": "qq"}]
        }
      }]
    }
  }
}
```

本次搜索“狂飙”时，腾讯搜索也返回该作品，但其 `playSites[].enName` 为 `qiyi`，`doc.id=sdp0010051ttxdf`。这是一条外站结果，不能把这个 ID 送到腾讯弹幕接口；应转到爱奇艺继续匹配。这正是多平台聚合中容易出现“搜得到却没有弹幕”的原因。

实际响应：`evidence/qq-title-search.json`、`evidence/qq-search.json`。

### 4.2 获取选集和每一集 VID

```http
POST https://pbaccess.video.qq.com/trpc.universal_backend_service.page_server_rpc.PageServer/GetPageData?video_appid=3000010&vversion_name=8.2.96&vversion_platform=2
Content-Type: application/json
Origin: https://v.qq.com
Referer: https://v.qq.com/x/cover/mzc00200803dr6b.html
```

```json
{
  "has_cache": 1,
  "page_params": {
    "req_from": "web_vsite",
    "page_id": "vsite_episode_list",
    "page_type": "detail_operation",
    "id_type": "1",
    "page_size": "",
    "cid": "mzc00200803dr6b",
    "vid": "",
    "lid": "",
    "page_num": "",
    "page_context": "cid=mzc00200803dr6b&detail_page_type=1&req_from=web_vsite&req_from_second_type=&req_type=0",
    "detail_page_type": "1"
  }
}
```

注意 `has_cache` 是 integer；`page_params` 中上述值都是 string，包括 `id_type`、`detail_page_type`。`page_context` 是一个嵌在 JSON 中的上下文字符串，不是顶层 URL 查询参数。

先检查 `ret === 0`。响应结构：

```text
data.module_list_datas[]
  .module_datas[]
    .module_params.tabs                         → JSON 编码字符串，需要再 JSON.parse
    .module_params.has_next                     → 可能是 boolean 或 string
    .item_data_lists.item_datas[]
      .item_params.vid                           → 单集 VID
      .item_params.cid                           → 所属作品 CID
      .item_params.is_trailer                    → "1" 表示预告，不应绑定成正片
      .item_params.play_title                    → 如“兰香如故 第01集”
      .item_params.union_title                   → 如“兰香如故_01”
      .item_params.c_title_output / title         → 如 "01" / "1"
      .item_params.video_subtitle                → 副标题
      .item_params.duration                      → 本次为秒数字符串 "2812"
```

本次第一条正片：`cid=mzc00200803dr6b`、`vid=c4102g9a01t`、`play_title=兰香如故 第01集`。由此得到页面：

```text
https://v.qq.com/x/cover/mzc00200803dr6b/c4102g9a01t.html
```

**分页不能只读第一次响应。** 本次 `tabs` 解码后有 1–30、31–47 两个范围，每项带 `page_context`。正式接入时，复用请求体，只替换 `page_params.page_context` 为返回值，依次读取对应页；按 VID 去重，并保留各页失败状态。本次只验证初始选集请求，没有把所有分页都拉完，因此不宣称全 47 集的选集结果已实测完整。

综艺分季还有章节上下文分支，源码从搜索结果的 `episodeSites/playSites[].chapterInfo` 提取章节，再请求选集。不要直接将不同季拉平后用数组下标当集号。

实际响应：`evidence/qq-episodes.json`。完整请求体：`api/request-templates.json` 中 `qq-episodes`。

## 5. 腾讯视频：弹幕索引和分段 JSON

### 5.1 读取索引

```http
GET https://dm.video.qq.com/barrage/base/c4102g9a01t
Accept: */*
```

无请求体。完整实测请求头保存在 `evidence/qq-base.http.json`；本次普通 User-Agent、无 Cookie 即返回 HTTP 200。没有验证每个头是否必需。

实际响应摘录：

```json
{
  "total": "0",
  "count_to_display": "0",
  "first_segment": [],
  "segment_index": {
    "0": {"segment_start": "0", "segment_name": "t/v1/0/30000"},
    "30000": {"segment_start": "30000", "segment_name": "t/v1/30000/60000"}
  },
  "segment_start": "0",
  "segment_span": "30000"
}
```

此处仅列出前两项索引，真实文件中有更多分段。

| 字段 | 类型与解释 | 处理方式 |
| --- | --- | --- |
| `segment_index` | object，key 为分段起点；value 为分段描述 | 校验存在后，按 value 的 `segment_start` 数值排序 |
| `segment_start` | 本次为数字字符串，毫秒 | 不能按字符串字典序排序 |
| `segment_name` | string，相对路径 | 直接接到 `/barrage/segment/{vid}/` 后，不硬编码版本 `t/v1` |
| `segment_span` | 数字字符串，本次为 30000 毫秒 | 仅为观察值；使用返回索引，不假设所有视频恒为 30 秒 |
| `total` / `count_to_display` | 数字字符串 | 本次均为 0，但分段确有弹幕，不能用它们判空 |
| `first_segment` | array | 本次为空；不要把它当作整集弹幕列表 |

### 5.2 读取一段

URL 规则：

```text
https://dm.video.qq.com/barrage/segment/{vid}/{segment_name}
```

实际成功样例：

```http
GET https://dm.video.qq.com/barrage/segment/c4102g9a01t/t/v1/0/30000
```

无请求体。响应 `Content-Type: application/json; charset=utf-8`。实际字段摘录：

```json
{
  "barrage_list": [{
    "id": "76561205919890314",
    "time_offset": "0",
    "up_count": "19",
    "create_time": "1792197508",
    "content_style": "",
    "content": "刘学义剧粉来报道"
  }]
}
```

| 字段 | 含义 | 归一化 |
| --- | --- | --- |
| `barrage_list` | array，分段弹幕 | 缺失或类型改变是结构错误，不是空弹幕 |
| `id` | 弹幕 ID，string | 原样保存，用于去重 |
| `time_offset` | **整集播放毫秒**，本次为 string | `timeMs = int(time_offset)`；不要再加分段起点 |
| `content` | 文本 | 以文本渲染，不作为 HTML 执行 |
| `content_style` | 空字符串或 JSON 编码字符串 | 非空时再解析一次；失败退默认样式并记录警告 |
| `up_count` | 点赞数，数字字符串 | 转为非负整数，可缺省为 0 |
| `create_time` | 创建时间字段 | 不用于播放调度；不要拿它替代 `time_offset` |

开源适配器的视觉映射：`content_style.position=2` → 顶部，`3` → 底部，其余按滚动；`color` 为 RGB 十六进制字符串；`gradient_colors` 为渐变色数组。示例解析器将渐变降级为首个颜色，字号默认 25，不重建气泡、礼物、动画等高级效果。这些是适配策略，不是腾讯完整样式规范。

第二段实际 `time_offset` 为 30000–59000，证实它是整集毫秒。如果再加 30000，会造成第二段整体延后 30 秒。

原始响应：`evidence/qq-base.json`、`qq-segment.json`、`qq-segment-2.json`。

## 6. 爱奇艺：剧名 → 选集 → 数字 TVid

### 6.1 搜索作品

```http
GET https://mesh.if.iqiyi.com/portal/lw/search/homePageV3?key=...&current_page=1&...
Origin: https://www.iqiyi.com
Referer: https://www.iqiyi.com/
```

无请求体，参数在 URL query 中。完整成功请求见 `api/request-templates.json` 的 `iq-search`，不要仅复制上面的省略 URL。

| 参数 | 本次值/类型 | 说明 |
| --- | --- | --- |
| `key` | `狂飙`，string | 使用标准 URL 编码 |
| `current_page` / `pageNum` | `"1"` / `"1"` | 查询字符串，1 起始 |
| `pageSize` | `"10"` | 本次请求值，不代表所有模板合计条数 |
| `mode` / `source` | `"1"` / `"input"` | 客户端搜索参数 |
| `pcv` / `version` | `"13.074.22699"` | 客户端版本参数 |
| `u` | `"protocol-study-local"` | 本研究客户端标记，无登录身份 |
| `scale` | `"200"` | 保持模板值 |
| `userVip` / `vipType` | `"0"` / `"-1"` | 请求使用未登录状态；改它们不会赋予会员权限 |
| `osShortName` | `"win10"` | 客户端信息 |
| `ad` | `{"lm":3,"azd":1000000000951,"azt":733,"position":"feed"}` | 整体作为 JSON 字符串，再做 query 编码 |
| `adExt` | `{"r":"2.1.5-ares6-pure"}` | 同上 |
| `suggest, pu, token, conduit, os, dataType, appMode` | 空字符串 | 完整模板均保留；本次未验证删除行为 |

先检查业务 `code`。本次成功值为字符串 `"0"`。开源适配器把 `"-1"` 当作受限响应处理；不要把它等同于无搜索结果。

```text
data.templates[]
  template=101/102/103 → albumInfo
  template=112         → intentAlbumInfos[]       （源码兼容，本文未逐类实测）
```

本次 `template=101` 的 `albumInfo` 摘录：

```json
{
  "title": "狂飙",
  "siteId": "iqiyi",
  "qipuId": 5328486914190101,
  "playQipuId": 3493131456125200,
  "pageUrl": "https://www.iqiyi.com/v_xkt6z3z798.html",
  "videos": [{
    "title": "狂飙第1集",
    "number": "1",
    "qipuId": 3493131456125200,
    "pageUrl": "https://www.iqiyi.com/v_xkt6z3z798.html",
    "duration": 2733000
  }]
}
```

`albumInfo.playUrl` 和 `videos[].playUrl` 本次为 `qips://tvid=...;vid=...;...` 描述串。可用边界明确的 `(?:^|qips://|[;?&])tvid=(\d+)` 提取数字 ID；不要把里面的媒体 `vid` 传给弹幕接口。该串是元数据，本研究没有调用它播放视频。

**注意单位不同：搜索内 `videos[].duration` 本次是 2733000 毫秒，而下文 `durationSec` 是 2733 秒。** 搜索内嵌 `videos` 可作为已返回单集来源，但不可假定所有作品都内嵌完整选集。

### 6.2 选集详情接口

```http
GET https://www.iqiyi.com/prelw/tvg/v2/lw/base_info?entity_id=...&...&sign=...
Referer: https://www.iqiyi.com/
```

无请求体。本次以已从搜索取得的单集数字 ID `3493131456125200` 作为 `entity_id`，成功返回《狂飙》的选集信息，提取到 39 个不同的正片单集 ID。

完整 query 参数如下，值均先当作字符串构造：

```text
entity_id=3493131456125200
device_id=protocol-study-local
auth_cookie=
user_id=0
vip_type=-1
vip_status=0
conduit_id=
pcv=13.082.22866
app_version=13.082.22866
ext=
app_mode=standard
scale=100
timestamp=<当前 Unix 毫秒时间戳>
src=pca_tvg
os=
ad_ext={"r":"2.2.0-ares6-pure"}
sign=<按下述规则计算>
```

源码使用的请求校验规则，本次按此生成后得到 `status_code=0`：

1. 去掉 `sign` 参数，保留空值。
2. 按参数名升序排列；使用**尚未 URL 编码的原始值**组成 `key=value`，用 `&` 连接。
3. 在末尾追加 `&secret_key=howcuteitis`。
4. 对 UTF-8 字节计算 MD5，转为 32 位大写十六进制，作为 `sign`。
5. 最后对每个 query key/value 做 URL 编码。

这里的常量来自公开客户端适配实现，不是用户账号凭证，也不赋予会员或播放权限。与后面的 `.br` 文件名校验是两套不同规则；不能混用。旧签名 URL 带旧时间戳，应重新生成：

```python
from catalog_requests import iqiyi_detail_url
url = iqiyi_detail_url("3493131456125200")
```

响应先验证 `status_code === 0`，再遍历：

```text
data.template.tabs[].blocks[]
```

本次实际选集块为 `bk_type="album_episodes"`，路径为：

```text
block.data.data[]
  .videos.feature_paged[任意分页 key][]
    .content_type             → 只取 1，过滤预告、花絮等
    .play_url                 → 从 tvid= 提取数字单集 ID
    .qipu_id                  → 本次与上述 TVid 一致，仍应保留字段上下文
    .page_url                 → 页面 URL
    .album_order              → 集序，不使用数组下标
    .short_display_name       → 分集名
    .subtitle                 → 副标题
```

本次出现分页 key `"1-39"`；不要硬编码这个字符串。该数组也包含预告条目，单纯取数组长度或第 N 个元素会错绑。

源码另兼容 `bk_type="video_list"` 且 `tag` 含 `episodes` 的分支：`block.data.data[].videos[].data[]`，仍按 `content_type=1` 过滤。如果旧分季分支的 `group.videos` 是 URL 字符串，则需要读取该季元数据；正式服务应验证其 scheme/host，避免将任意输入 URL 当作抓取目标。本文只实测内联 `album_episodes` 分支。

实际响应：`evidence/iq-episodes.json`；请求证据：`iq-episodes.http.json`。

### 6.3 只有页面地址时转换 TVid

从页面 `https://www.iqiyi.com/v_xkt6z3z798.html` 提取 `pageId=xkt6z3z798`，请求：

```http
GET https://pcw-api.iq.com/api/decode/xkt6z3z798?platformId=3&modeCode=intl&langCode=sg
```

实际完整响应：

```json
{"code":"0","data":3493131456125200}
```

这里是页面标识转换，得到数字 TVid；不是解密视频。若搜索或选集结果已经提供数字 TVid，可直接使用，减少这一步依赖。不要将数字 TVid 再当作 base36 页面 token 转换，否则可能得到另一个错误 ID。

## 7. 爱奇艺：基础信息与 Brotli 弹幕

### 7.1 单集基础信息

```http
GET https://pcw-api.iqiyi.com/video/video/baseinfo/3493131456125200
```

无请求体。实际响应字段摘录：

```json
{
  "code": "A00000",
  "data": {
    "tvId": 3493131456125200,
    "albumId": 5328486914190101,
    "name": "狂飙第1集",
    "playUrl": "http://www.iqiyi.com/v_xkt6z3z798.html",
    "order": 1,
    "displayBarrage": true,
    "durationSec": 2733
  }
}
```

先检查业务成功及 `data` 类型。`durationSec` 单位为秒；`displayBarrage=false` 可标为平台关闭弹幕。时长缺失、业务错误、结构缺失应返回元数据失败，不应伪装成 0 秒空片。

源码使用 `ceil(durationSec / 60)` 规划页数，页号从 1 开始。2733 秒的样例可规划 46 页，但本次只读取其中前两页；没有验证余下每一页存在。

### 7.2 当前 `.br` URL 规则

```text
https://cmts.iqiyi.com/bullet/{倒数第4至第3位}/{最后2位}/{TVid}_60_{page}_{checksum}.br
```

目录来自数字 TVid 的末四位，不足四位时左侧补零。页号 `page` 从 1 开始。文件名校验：

```text
raw = TVid + "_60_" + page + "cbzuw1259a"
checksum = MD5_UTF8(raw).lowercase_hex[-8:]
```

可运行生成器已经包含在 `examples/danmaku_adapter.py`：

```python
from danmaku_adapter import iqiyi_segment_url
url = iqiyi_segment_url("3493131456125200", 1)
```

本次 TVid 末四位为 `5200`，目录为 `/52/00/`。完整实际 URL 保存在 `evidence/iq-kb-segment.http.json`，不需要猜 checksum。

请求是 GET、无请求体。响应是二进制文件，不能 `.json()` 或直接按 UTF-8 XML 处理。本次请求使用 `Accept-Encoding: identity`，响应 `Content-Type: application/octet-stream`，**没有 HTTP `Content-Encoding`，文件本身仍然是 Brotli 压缩**。

不要混淆传输编码和文件压缩：如果 HTTP 库自动解除了 HTTP `Content-Encoding: br`，还需判断剩余内容是否仍是压缩文件；同一层不能解压两次。建议为每个网络库固定处理策略、保存原始字节和响应头，避免凭 `.br` 后缀无条件反复解压。

解压后分流：

```text
HTTP bytes → Brotli 解压一次
  XML 内容（去 BOM/空白后以 < 开头） → XML 解析
  其他内容                            → 已观察的 Protobuf 解析
```

**本次成功的两个 `.br` 文件解压后都是 Protobuf。** XML 分支来自源码，并通过构造样例测试，没有在本次成功网络样例中观察到 XML。

### 7.3 Protobuf 已识别字段

字段编号来自两份固定源码及本次实际二进制响应对应关系。只定义弹幕显示所需子集，未知字段按 wire type 跳过，不能把该子集称为完整官方协议。

| 层级 | 字段号 | wire type / 本次内容 | 含义 |
| --- | --- | --- | --- |
| 顶层 | 1 | 2，UTF-8 `A00000` | 业务状态 |
| 顶层 | 6，repeated | 2，嵌套消息 | 时间块 |
| 时间块 | 1 | 2，数字字符串 | 块时间，单条缺时间时才回落使用 |
| 时间块 | 2，repeated | 2，嵌套消息 | 单条弹幕 |
| 单条 | 1 | 2，数字字符串 | 弹幕 ID，实测 19 位，必须保留字符串 |
| 单条 | 2 | 2，UTF-8 | 文本 |
| 单条 | 6 | 2，数字字符串 | **整集播放秒** `showTime` |
| 单条 | 8 | 2，六位 RGB 十六进制字符串 | 颜色，例如 `ffffff` |
| 单条 | 14 | 2，数字字符串 | 点赞数 |

例如第一条实际弹幕：ID `1707482806092036748`、文本“京海不大，创造神话”、`showTime="1"`、颜色 `ffffff`、点赞数 `2926`。归一化时间为 1000 毫秒。

第二段 `showTime` 为 61–120 秒，说明它已经是整集时间。不要再加 60 秒。第 1 段实际包含 `showTime=60`，因此也不能机械地按 `[0,60)` 丢弃段末记录。跨段缓存按 ID 去重，保留实际时间；拖动到边界时可连同相邻段加载。

`.proto` 子集位于 `api/iqiyi_danmaku_observed.proto`。示例解析器使用严格边界检查，拒绝截断 varint、越界消息和无法识别的结构，避免把解析失败当成空数组。

### 7.4 XML 和旧 `.z` 兼容边界

源码兼容的 XML 单条结构大致如下；这是结构示意，不是本次网络捕获：

```xml
<danmu><data><entry><list><bulletInfo>
  <content>示例 &amp; 文本</content>
  <showTime>61.25</showTime>
  <color>ff0000</color>
  <likeCount>2</likeCount>
</bulletInfo></list></entry></data></danmu>
```

`showTime` 为秒，转换 `timeMs=round(showTime*1000)`；颜色按十六进制。必须在每个 `bulletInfo` 内读取字段，不能把全文的 `content[]`、`showTime[]` 独立抽出来按数组下标硬配，否则缺字段后会错位。使用 XML 解析器处理实体和 CDATA。

历史教程常用 `{TVid}_300_{page}.z`，按 300 秒切分并用 zlib 解压。**本次旧 `.z` 请求返回 404，没有获得可用的旧格式网络样例。** 示例程序保留有输出大小限制的 zlib 解压入口，但不宣称当前旧 URL 普遍有效。新接入优先使用本次验证成功的 60 秒 `.br` 链，不要对每个缺段反复探测旧格式。

## 8. 播放器内部统一格式

两家原始响应不同，播放器最好只接收统一格式。以下为本次爱奇艺第一条的解析结果：

```json
{
  "provider": "iqiyi",
  "sourceEpisodeId": "3493131456125200",
  "id": "1707482806092036748",
  "timeMs": 1000,
  "text": "京海不大，创造神话",
  "mode": 1,
  "color": 16777215,
  "fontSize": 25,
  "likes": 2926,
  "sourceFormat": "protobuf"
}
```

| 内部字段 | 约定 |
| --- | --- |
| `provider` | `bili` / `qq` / `iqiyi`，始终随数据保留 |
| `sourceEpisodeId` | 平台单集弹幕标识字符串 |
| `id` | 远端弹幕 ID；确实没有时为 null，不伪造为数组下标 |
| `timeMs` | 整集时间，非负整数毫秒 |
| `text` | 纯文本 |
| `mode` | 当前支持 1 滚动、4 底部、5 顶部；爱奇艺未识别完整样式，示例默认滚动 |
| `color` | 24 位 RGB 整数；黑色 0 是有效值，不能用 `color || 白色` 覆盖 |
| `fontSize` | 示例降级值 25，不是上游所有弹幕字号的真实还原 |
| `likes` | 非负整数 |
| `sourceFormat` | `json` / `protobuf` / `xml`，便于诊断 |

解析器返回 `{status, items, warnings}`。合法空列表为 `empty`；无法识别结构、Brotli 损坏等抛出解析错误，命令行退出码为 1。HTTP 错误应由网络层先处理，不能把 404 的 HTML 错误页交给 Brotli 解压器。

`create_time`、本次抓取时间均不作为弹幕在视频中的播放时间。示例也没有把当前时间伪装为上游弹幕创建时间。

## 9. 按名称绑定和多平台补充的实现建议

以下是面向学习项目的接入设计，不是平台接口的既有字段。

### 9.1 绑定流程

1. 从本地视频取得作品名、年份、季号、集号、语言、版本及实际时长。清理分辨率等文件标签时保留季集和版本信息。
2. 分别搜索候选作品，核对名称/别名、年份、内容类型和站内来源。搜索推荐结果只能列为候选。
3. 展开候选作品的正片分集，用远端真实集序匹配，不使用数组下标。排除预告、解说、花絮、剪辑和不同季。
4. 新绑定或歧义候选给用户选择，显示平台、作品、集号、版本和时长。保留手动粘贴单集页面 URL 的入口，可以绕开搜索不稳定，但仍需转换正确单集 ID。
5. 绑定成功后按本地单集 ID 持久化。播放时直接读取绑定，不必每次重新搜索。
6. 某平台缺失时，仅切换到已经核对为同一作品、同一集、相同版本的备用绑定；没有匹配就显示需要选择来源。

建议持久化结构：

```json
{
  "localEpisodeId": "local:kuangbiao:2023:e01",
  "selectedProvider": "iqiyi",
  "bindings": [{
    "provider": "iqiyi",
    "seriesId": "5328486914190101",
    "episodeId": "3493131456125200",
    "pageUrl": "https://www.iqiyi.com/v_xkt6z3z798.html",
    "title": "狂飙",
    "year": 2023,
    "episodeNumber": 1,
    "version": "正片",
    "sourceDurationMs": 2733000,
    "offsetMs": 0,
    "confirmed": true
  }]
}
```

本例只有已实测的爱奇艺绑定，没有为腾讯或 B 站编造同片 ID。另两个平台有真实匹配后再追加。

### 9.2 时间校准

延续 B 站交接约定：**`offsetMs > 0` 表示弹幕在本地视频中延后显示**。

```text
localDisplayMs = sourceTimeMs + offsetMs
sourceQueryMs  = localPlaybackMs - offsetMs
```

例：上游 10 秒出现的弹幕，本地对应场景在 15 秒，则 offset 为 +5000。保留原始 `sourceTimeMs`，不要在缓存中永久覆盖后再叠加一次。

如果两个版本中间有删减、插播或片头不同导致偏移随时间变化，一个全局 offset 不足以同步。可以由用户选择正确版本，或另建有明确锚点的分段映射；不要仅靠总时长比例强行拉伸时间轴。

### 9.3 分段加载、缓存和去重

- 缓存 key 至少包括 `provider + episodeId + segment标识 + decoderVersion`。同一个数字串在不同平台不代表同一弹幕池。
- 腾讯使用返回索引定位分段；爱奇艺按 60 秒规划页，页号从 1 开始。时间边界可预取相邻段，保留实际响应中的时间，不硬截段尾。
- 拖动后增加请求 generation，忽略旧位置的过期响应；按播放位置预加载下一段，限制并发和缓存总量。
- 同平台优先按 `provider + episodeId + id` 去重；缺 ID 时可用时间、文本、模式、颜色组成稳定指纹，记录它只是近似键。
- 默认选择一个来源，避免把多个平台整批拼接造成重复和过密。允许用户主动合并时，应逐个绑定校准，并明确近似去重可能误删同文弹幕。
- 尊重响应缓存信息。本次爱奇艺文件返回 `Cache-Control: max-age=180`；不同资源策略可能不同，不应写死成全平台永久缓存。

## 10. 错误分类：排查时保留什么

| 情况 | 建议状态 | 排查/处理 |
| --- | --- | --- |
| HTTP 200，结构正确，弹幕数组为空 | `empty_segment` | 正常空段，不代表整集或所有来源为空 |
| 腾讯 `total=0` 但有索引 | 正常继续读取 | 本次已发生，不能提前返回空池 |
| HTTP 404 | `segment_not_found` | 记录平台、单集、页号；单段缺失不推出全片为空 |
| HTTP 401/403、挑战页 | `access_denied` | 保留状态；不要自动伪装成功或循环重试 |
| HTTP 429 | `rate_limited` | 遵循 Retry-After/退避，降低并发 |
| HTTP 200 但业务码失败 | `upstream_error` | 腾讯看 ret；爱奇艺各接口分别看 code / status_code |
| HTTP 200 但数据路径/类型改变 | `schema_changed` | 保存脱敏响应、触发适配器更新，别返回 [] 掩盖问题 |
| Brotli/zlib 解压失败 | `decode_failed` | 检查是否错误页、传输层已解压、文件损坏、格式改变 |
| Protobuf 越界/非法字段或 XML 损坏 | `parse_failed` | 不返回假空列表；保留解析器版本和有限字节摘要 |
| 名称、季集、版本不能确定 | `needs_selection` | 请求用户选择候选来源，避免错绑 |

源码中部分方法会把网络错误直接转为 `[]`，适合它自身的容错界面，却不利于聚合服务定位问题。本文示例将解析失败保留为错误；正式接入网络层时也应把上述状态分开。

排查日志建议包含：平台、操作名、单集 ID、段号、HTTP 状态、业务码、Content-Type、Content-Encoding、原始大小、解析后条数、解析器版本。不要把用户 Cookie 写入日志。服务端 HTTP 200 不代表浏览器一定能直接请求；本次弹幕文件返回 `Access-Control-Allow-Origin: *`，搜索与选集的跨域预检并未验证。Web 前端若遇到 CORS，使用受控后端适配器，并仅允许已知上游域名和参数。
