# 架构升级接手记录与性能分析（2026-10-19）

后续用户重新授权针对开屏、播放反馈与诊断的实际查看，修复和最新常用预览 APK 交付见 [后续记录](mobile-startup-diagnostics-2026-10-19.md)。下文停止交互及 APK 尚未更新的描述属于此前阶段；原性能数据和未完成项仍保留其环境边界。

当前结论：共享播放会话、端视图选择、请求取消和资源登记已经有运行证据；没有同条件的修改前基线，不能宣布架构调整使内存或首帧提升了多少。Windows 仍有原生内存留存，Android 录制过短，性能收尾尚不能写成全部通过。

用户最新要求由其自行进行真机与体验验证。因此停止追加设备/浏览器交互场景，只分析已采集记录、修复诊断误判并进行本地静态与单元检查。保留并行会话改动；下列文件快照覆盖共享工作区，不表示所有改动由本会话完成。

## 性能证据与判断

### Windows：媒体所有权释放了，进程占用没有完全回落

来源为实际 Wails/WebView2 隔离探针、生产播放器组件和 HLS，业务绑定使用夹具。自然 GC，3 次打开/播放/关闭，每次播放约 2.1 秒，最后空闲 15 秒；基线已经预热，主机内存使用率约 91.5%～92.5%。这是原生资源观察，不是完整 Windows 产品业务验收。

| 读数 | 暖基线 | 最后空闲 | 差值 |
| --- | ---: | ---: | ---: |
| 进程树私有提交 | 528.07 MiB | 605.26 MiB | +77.18 MiB |
| renderer 私有提交 | 79.07 MiB | 131.15 MiB | +52.08 MiB |
| GPU 进程私有提交 | 338.53 MiB | 361.66 MiB | +23.13 MiB |
| CDP JSHeapUsedSize | 13.54 MiB | 14.27 MiB | +0.74 MiB |
| CDP DOM 节点 | 519 | 1648 | +1129 |
| CDP 监听器 | 276 | 348 | +72 |

三次刚关闭时私有提交为 584.67 / 619.47 / 637.73 MiB，空闲后回落到 605.26 MiB。最后活跃播放器、资源观察器、附着 video/canvas、缓存排队和在途任务均为 0。CDP 节点/监听器还没有回到基线；这些计数包含尚未回收的对象，单凭计数不能断言有业务事件监听泄漏。

最后 TS 缓存仍有 **18.45 MiB**，`idleTrimPending=true`。实际策略是最后一个所有者离开后立即取消请求，等待 **30 秒**再把缓存预算收至 **8 MiB / 16 项**；本次只观察 15 秒，因此没有验证收缩后的占用。不能把缓存全部称为泄漏，也不能把其字节从进程提交简单相减：JS、ArrayBuffer、原生分配存在口径和包含关系。

当前主要待归因量在 renderer/GPU；本次没有原生分配转储，不能把全部差值归给驱动、解码器或 Vue。此前 [原生视频最小复现](history/playback.md#origin-webview-native-retention-2026-10-16) 支持继续检查 WebView 图形路径，但不同基线/媒体的历史读数不能拿来计算本轮收益。没有为压低数字关闭硬件加速、强制 GC 或清除用户缓存。

证据：[完整原生快照](upgrade-acceptance-2026-10-19/windows-resource-recording.json)、[按阶段和 PID 角色汇总](upgrade-acceptance-2026-10-19/performance-synthesis.json)。

### Android：会话稳定与合并更新已观察到，长期占用仍未知

MuMu `emulator-5554`，Android 15 / x86_64，WebView 110.0.5481.154.1；隔离包 `com.cczj.video.acceptance`，内嵌前端和实际 Go 绑定。录制 35.56 秒、9 个原生样本，关闭后约 7.81 秒；本地 320×180 H.264/AAC MP4/HLS，包含手势、全屏、后台、切线路/切集和下载操作。

| 指标 | 实际记录 | 判断 |
| --- | --- | --- |
| 首帧 | 715 / 842 / 278 ms | 3 次本地装载；不是远程片源延迟基准 |
| 媒体与观察器 | 最大各 1，关闭后各 0 | 没有观察到随全屏重建的多重所有者 |
| 装载数 | 进入、换线路、换集，共 3 次 | 全屏与设置操作没有额外媒体装载标记 |
| 进度事件 | 44 次输入，10 次 UI 更新，3 次历史写入 | 合并实际生效；22.7% 是更新/事件比例，不是 FPS 提升 |
| Go 活跃堆 | 4.60 → 4.14 MiB | 该短段没有净增长，不能证明长期无泄漏 |
| 应用进程 PSS | 127.30 → 141.99 MiB | +14.69 MiB；不含隔离 WebView/GPU，不能称整 APP 内存 |
| 文件描述符 | 220 → 241，峰值 274 | 有回落，尚未回到起点，不能证明长期稳定 |
| 协程 | 23 → 27 | 栈显示 HTTP 服务/连接等待及录制收尾；未见残留阅读 provider 工作栈 |
| 退出后预算 | active=0，waiting=0 | 本次请求许可已释放；不等于压力下播放保留容量已验收 |

记录的帧计数是 **23 / 181**，原始比值 12.71%；不足面板既定的 200 帧门槛。23 个丢帧在第二次装载前已经累计，HLS 末段新增 30 帧未新增丢帧；不能把整体比值归因于 HLS。当前时间片混合暂停、预览、后台恢复等操作，不能当作稳定观看卡顿率。没有记录到 `stall` 或终止播放错误，也不能反向推断“用户没有卡顿”。

已经修复两项数据可靠性问题：

- 后端录制白名单曾拒绝 `player_media_load`、`playback_page_closed`、`player_issue`、`preview_started/stopped`，导致新架构标记丢失。补齐后实际 Android 录制可关联会话、来源请求及关闭记录；前端现在保留标记写入失败状态，导出明确记录不完整。
- 离线分析器之前仅从最终 JSON 报告读取播放统计，单独 Android JSONL 会丢掉帧数和浏览器资源；现在回退读取最后有效时间线快照，并记录数据来源。缺计数保持未知。面板不足 200 帧现在显示“—”，保留丢帧/总帧数，不再显示误导性的“0.0%”。

已有 Go heap/goroutine 快照已只读提取到报告目录，没有重新启动播放。`alloc_space` 差分约 27.16 MiB，其中 `io.ReadAll` 约 16.63 MiB；其调用约 87.5% 来自本次下载 `getOnce`，12.5% 来自 Android 静态资源读取，不能归成播放常驻堆。录制器自身的 pprof/压缩也产生分配。此次采样的 `inuse_space` 差分为 0，采样不能解释 MemStats 中全部存活小对象，不作为“没有持有对象”的证明。

证据：[录制分析](upgrade-acceptance-2026-10-19/playback-analysis/summary.json)、[原始时间线](upgrade-acceptance-2026-10-19/player-android/playback-recording.jsonl)、[分配差分](upgrade-acceptance-2026-10-19/player-android/go-allocation-delta.log)、[分配调用方](upgrade-acceptance-2026-10-19/player-android/go-readall-callers.log)、[协程统计](upgrade-acceptance-2026-10-19/player-android/goroutine-analysis.json)。

## 日志中的报错不能混为一类

播放器 CDP 记录中 1 次 `/wails/custom.js` 500 与 20 次 favicon 连接失败属于宿主资源请求噪音。已为 Android 可选 custom.js 提供空脚本、为页面声明 data favicon；最新 APK 构建/安装成功，按用户新要求没有再跑页面验收，因此不宣称更新后日志已经清零。

1 次 `manifestLoadError` 被标记 `recoverable=true`，对应 HLS 探测后回退原生 MP4 播放，随后取得首帧；不属于终止播放失败，也保留了原始事件。

另有 **3 次 `CancelledRejectionError`**，其原因都是已取消绑定迟到返回 `context canceled`。Wails beta.30 的 CancellablePromise 会把取消后非 CancelError 的拒绝包装成此异常。后端取消和共享等待者结果检查通过，但这条异常传输仍是待修项，不能宣称所有前端异常已修复。没有通过全局吞掉 unhandledrejection 掩盖它。网络统计旧字段 `fails` 还会计入取消，分析时应区分取消与失败，不能把该累计数直接当片源故障率。

SQLite 故障注入产生的预期 STORAGE 错误单独保留在测试记录，不当作正常运行时故障。分组原始来源见 `performance-synthesis.json/captured_console`。

## 接手期间修复的实际链路问题

这些修复保留既有绑定入口和用户数据；未将共享工作区全部变更归为本轮。

| 问题 | 修复及已有证据 |
| --- | --- |
| Android 默认 `/sdcard/Downloads` 无权限 | 默认使用应用私有 downloads；自定义路径优先；实际暂停、强停恢复与 4 MiB 文件校验通过 |
| 大目录 SQLite `SQLITE_IOERR_GETTEMPPATH` | 在 Java 加载 Go 前及 Go 初始化库前配置可写临时目录；Android 270 小说/135 漫画分页成功 |
| 漫画图片查询上下文被 AssetLoader 丢失 | 受能力令牌保护的原生流式桥加入图片路径，保留 u/ref/k、Referer 与声明头；实际解码成功 |
| 豆瓣匹配兜底读入阅读来源 | 限定为 video 来源，避免将阅读 HTML 当视频 JSON |
| 关闭自动历史续播后，当前集换线也从零开始 | 当前非空作品/集身份相同时传递连续播放位置；实际 MP4→HLS 保持进度，换集归零 |
| 漫画保存页码在空页表上被 clamp 成 0 | 先初始化页表再取有效位置；Android 翻页模式恢复第 3 页通过 |
| Android 播放脚本只认识旧 Vite chunk | 改为发现实际模块引用，支持 Vite 8 文件名；没有把旧脚本未重跑写成通过 |
| 开屏额外图标、条款按钮过长 | Android 12+ 系统启动图标改透明；按钮固定“退出 / 同意并继续”，倒计时独立；移动退出补原生 Activity 关闭。系统启动窗口仍由 Android 管理，不承诺消灭系统启动阶段 |

最新隔离 APK 包含 Go、迁移、绑定和开屏/条款修改，详见 `build-final-ui.log`。之后的诊断丢帧显示修复只完成源码和本地验证，尚未重新打入 APK；用户原预览包也不保证与隔离 APK 同步。
