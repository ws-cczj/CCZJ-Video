## 第一方来源及选样依据

### 番茄：中文主样本

[番茄官网](https://fanqienovel.com/)和[官网书库](https://fanqienovel.com/library/all/page_1)是本次中文小说身份与类别的来源。官网脚本仅作为文本检查，从中查得站点自己使用的分类目录地址；没有执行下载的远程脚本。

实测可用的第一方接口：

- [女频分类目录](https://fanqienovel.com/api/author/book/category_list/v0/?gender=0)、[男频分类目录](https://fanqienovel.com/api/author/book/category_list/v0/?gender=1)、[通用分类目录](https://fanqienovel.com/api/author/book/category_list/v0/?gender=2)。采集器动态读取 `label=主分类` 的实际 ID，不把旧编号永久绑定成某个题材。
- [实际分类分页示例](https://api.fanqiesdk.com/api/novel/channel/homepage/new_category/book_list/v1/?aid=1967&offset=0&limit=100&category_id=511&gender=1)：本次实取 100 条/页，使用项目已经采用的第一方 SDK 域名。其接口没有在本次找到公开稳定性协议，因此只能称为“当前实测可用”，不能承诺接口永久不变。

第一轮先覆盖仍能返回实际作品的玄幻、历史、悬疑、都市、仙侠路线；第二轮根据官网当前目录补女频悬疑、古风世情、科幻末世、衍生、民国言情、青春甜宠、双男主、西方奇幻、都市高武、抗战谍战、动漫衍生和游戏体育等。

`category_v2` 的题材取实际返回名称；重复出现在不同分类中的同一 `book_id` 合并标签。推广别名采用 API 的 `book_flight_alias_name`，不把 `book_short_name` 这种过短缩写当作独立书名。没有根据作者名或内容简介推断国别。

这批作品来自分类分页，不是已经验证的“全网热门榜”。每个作品保留 `https://fanqienovel.com/page/{book_id}` 以及取到元数据的 API URL，方便后续核验目录、权限和连载时效。

### MangaDex：漫画跨地区样本

[MangaDex 官方 API 文档](https://api.mangadex.org/docs/)可由本机 HTTPS 正常读取，官方文档页面也指向其[文档源仓库](https://gitlab.com/mangadex-pub/mangadex-api-docs)。本次实际请求 `GET /manga`，按原作语言分层，各层取四页，每页 100 条；请求展开 `author`、`artist`，并明确限制 `contentRating[]=safe`。这些参数及返回字段以本次实际响应为准，完整 URL 保存在样本引用中。

各层通过 `order[followedCount]=desc` 排序；“关注数排序”只是 MangaDex 站内热度代理，不是销售榜，更不是全网排名。将四种原作语种分别取样，避免日文作品的大量关注数挤掉中文或韩文作品。

匹配时需要同时保留三个概念：

1. `language`：站点明确给出的原作语言。
2. `searchTitles`：站点 `title` 和 `altTitles` 中逐语言的首个真实标题；例如日文原作可能同时有 `zh`、`zh-hk`、`en` 标题。
3. `aliases`：保留站点提供的其余译名和别名，去重但不自动翻译、不自动制造简繁体。

`searchLanguages` 等于 `searchTitles` 的键。中文源可以检测有中文译名的日本、韩国漫画，不能仅因原作语言不是中文便排除；英文源也应使用真实英文标题，而不是把中文展示名拿去查英文站点。繁体和简体译名都以原字段为准，不承诺它们是同一发行版本。

没有把 API 的 `lastChapter` 当作完整目录总数：该字段可能是连载声明、文字编号或未知值。漫画卷、话、特别篇、不同译本及整合版仍需另行从目录核验。

### Gutendex / Gutenberg：独立的经典补充层

[Gutendex 自有 API 文档](https://gutendex.com/)明确说明，它提供 Project Gutenberg 元数据，默认按 Gutenberg 下载量排序，列表每页最多 32 本，并支持按 `topic`、语言等条件过滤。它是开放目录服务，**不是 Gutenberg 第一方 API**。

[Gutenberg 官方离线目录说明](https://www.gutenberg.org/ebooks/offline_catalogs.html)推荐使用机器可读元数据而不是遍历抓站；也明确电子版不一定能对应特定纸本版次。本机直接下载官方 CSV 遇到证书链校验错误，未关闭 TLS 校验，而采用 Gutendex 的元数据入口，同时给每本附上 `https://www.gutenberg.org/ebooks/{id}` 第一方图书链接。

本次科幻目录取得 31 条可保留的虚构文学记录。悬疑、历史、奇幻三个目录请求均超时，保留失败，没有用空数据补足数量。经典补充层不作为当代中文网文覆盖率的分母，也不能仅凭 `Fiction` 标签认定所有作品都是长篇小说。

## 资源边界、去重与重跑

采集器单进程只有一条网络请求链，低于容量 5。两轮实际采集曾同时运行，合计最多两条元数据请求链。87 次网络请求共收到 104,737,447 字节；其中三次 Gutendex 超时。输出的失败不等于小说/漫画采集源的质量失败，只表示基准元数据入口本次未取得结果。

默认边界：每次响应最多 6 MiB、每轮总下载最多 100 MiB、最多 100 次请求、单次超时 25 秒、成功请求后间隔 0.35 秒。分页数量可配置，但参数上限固定；重定向在建立跨域连接前拒绝，所有 URL 使用 HTTPS 和固定域名白名单。

响应按完整 URL 的 SHA-256 缓存，重跑可复用已有成功元数据；缓存引用保留缓存生成日期，不把旧缓存假称为当天重新联网验证。失败保留在 manifest，现有样本合并保留，避免一次临时故障覆盖掉以前已获得的作品。ID 去重复杂度为 O(作品数)，相同标题的不同站点记录或不同发行版本不会被无依据地强行合并。

重新采集：

```powershell
python scripts/collect-reading-benchmark.py
```

强制更新成功缓存：

```powershell
python scripts/collect-reading-benchmark.py --refresh
```

本次额外用独立输出文件重放 `fanqie,mangadex` 两个入口，未产生任何新网络请求，重建 5,201 条中文小说和 1,600 条漫画，验证分页计划与去重可重跑。正式冻结文件没有被这次验证覆盖。31 条经典补充来自另一次科幻目录成功响应；失败的其他补充题材仍保留未知状态。

## 此数据能证明什么

这批样本扩充的是“候选作品、题材、译名和作者”的基准范围，解决只测少数书导致偏差的问题。它们可以用于源发现阶段的身份匹配、分层抽样和覆盖统计。

这批数据本身不能证明源中某部作品全集齐全、正文无广告、图片无广告、版本完全一致。没有目录锚点的记录不应得到“全集匹配通过”，没有正文和图片抽样证据的记录不应得到“无广告通过”。后续调度应对匹配到的作品再验证详情、目录、首中末内容，将权限限制和未知状态单独记录，并以具体作品及章节证据解释评分。
